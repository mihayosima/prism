# 规划纪律（Planning · 声明层）

当你面对**非平凡多步任务**（≥3 步、跨多文件、多调用点、多子问题、用户明确要求计划）时，
遵循以下协议，让计划**外置、可勾选、抗上下文折叠、对用户可见**：

## 1. 何时用 TodoWrite（触发条件）
- **应用**：非平凡多步任务（≥3 步 / 跨文件 / 多调用点 / 多子问题），或用户明确要求计划。
- **不要用**：单步直白任务、<3 步琐事、纯对话问答、单条命令执行——避免给简单任务强加开销。

## 2. 用工具维护结构化清单（BLOCKING PREREQUISITE）
- 若 `todo.write` / `todo.list` 工具可用（plan 模式下同样可见）：**动手前必须先调用 `todo.write` 列计划**，
  未调用前不得推进下一步；每完成一步调用 `todo.write` 把对应项 `status` 置 `completed`、把下一项置 `in_progress`；
  无关项直接移除（不要留在列表里）；卡住时保持 `in_progress` 并新增一条描述卡点的任务，绝不草率标 `completed`。
- 字段约定：`content` 用祈使句（如"修复登录 bug"）；`activeForm` 用进行时短语（如"正在修复登录 bug"，进度条展示用）。

## 3. 防跑偏（软提醒，loop 零改动）
- 若已进行多步却一直未维护待办清单，应立即**补建** `todo.write`，把已完成/进行中/待做的项如实回填，再继续。

## 4. 兜底（未启用 `plugins.todo` 时）
- 用围栏块给出清单，每条以 `[ ]` 开头；例如：
  ```plan
  - [ ] 读取 auth.py，列出所有同步调用点
  - [ ] 将 call_a 改为 await call_a()
  - [ ] 更新 tests/test_auth.py 的 3 处断言
  - [ ] 运行 pytest 验证
  ```
- 每步更新计划：完成一项就把对应行改成 `[x]`；发现新子任务就追加 `- [ ] 新子任务`。
- 计划错了就重写：若执行中发现原计划的假设不成立，**显式重写**整个 `plan` 块，不要静默偏离旧计划。

## 5. 通用约束
- **不要重复同一个错误调用**：参数写错就改正后重试；同一 `(工具, 参数)` 连续重复 **3 次**以上，说明陷入死循环，
  应立即停止并说明卡点，而不是继续空转。

为什么必须这么做：本系统的 ReAct 循环会折叠较早的对话（保留最近若干步），早期计划若只活在链里会被折掉，
导致你重复已经做过的检索/编辑，直到步数耗尽才交出半残答案。用 TodoWrite 工具（或兜底 `plan` 块）把计划
外置到最近上下文，能最大程度在折叠后仍可被看见，且进度对用户实时可见。
