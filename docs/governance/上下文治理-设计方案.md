# 上下文管理插件 — 设计方案（G0–G5，分模块深入）

> 决策输入：总体思路已确认；**落位=目录插件 `plugins/context`**（与 memory/react 同款生命周期，
> layer=system 语义标签，可经插件页启停/卸载）；**工作方式=深入各模块、分模块解决问题**。
> 全部模块完成、测试通过后统一提交。

## 0. 总体架构

```
plugins/context/                 ← 目录插件（M1 模式：DDL 随插件）
  __init__.py    Context 插件：provide(Services.CONTEXT) + 自带迁移 agent_ctx_001_summaries
  governor.py    ContextGovernor：预算模型 + 分块装配 + token 化裁剪
  compactor.py   Compactor：会话增量摘要（走 ctx.llm，guard/budget 照生效）
  protocols.py   GovernorLike 契约（接缝可替换，D2 同款）

消费面（全部 ctx.has 软依赖，插件停用即退回现状，不劣化不裸崩）：
  sys/chat.py      → ctx.governor.build(...)   装配计划/解说窗口
  plugins/react    → ctx.get("context.governor") 动态取（运行时消费，不做 inject 硬依赖）
```

- **宿主登记项**（保留宿主，M3 同款语义）：`Services.CONTEXT`（services_catalog）、
  `Events.CONTEXT_GOVERNED`（events_catalog）、`config_schema "context": "_any"`。
- **公共原语**：`core/tokens.py`（新）——`estimate_tokens` 从 `sys/llm.py` 转正
  （D4 模式：实现迁 core，sys 留兼容别名）+ `clip_text / clip_json` 裁剪原语。
  **sys 层（mcp_client）可直接用 core 原语做源头护栏，不 import 插件，零特权不破。**

预算模型（配置节 `agent.context`）：

```yaml
agent:
  context:
    max_context_tokens: 24000   # 输入窗口总预算
    reserve_output_tokens: 4000 # 输出余量
    memory_ratio: 0.10          # 记忆块配额
    history_ratio: 0.60         # 历史窗口配额
    compact_trigger: 8          # 单轮裁掉 >N 条历史 → 触发增量摘要
    source_clip_tokens: 8192    # MCP 源头护栏上限
```

装配优先级（逐块保障，超配额先降级）：system 骨架（刚性）→ 工具块 → 本轮消息 →
记忆块（预算反推实参）→ 会话前情摘要 → 历史窗口（剩余配额按 token 从新到旧贪心收取）。

## 1. 分模块治理路线（G0 骨架 → G1–G5 逐模块深入）

每模块固定节奏：**问题清单 → 治理动作 → 验收测试**；每阶段完成跑全量 pytest 保持绿。

### G0 — 治理器骨架（其余模块的地基）

| 项 | 内容 |
|---|---|
| 动作 | `core/tokens.py` 转正；`plugins/context` 三件（插件/governor/protocols）；预算模型；历史收窗；装配接缝 |
| 登记 | `Services.CONTEXT`、config 节（`agent.context` → `_any`）。事件 `agent/context/governed` **随 G1 接线一并登记**——SSOT 守卫要求常量被源码引用，未接线的名字不提前入册 |
| 验收 | 预算分配边界（零历史/超长历史/超配额记忆）、CJK 口径、插件停用降级、接缝注入假 governor、K0 纯度守卫 |

### G1 — 会话历史（sys/chat）

- **问题**：`HISTORY_LIMIT=12` 按条数裁剪（条数≠体积）；被裁历史直接丢弃，长会话失忆。
- **动作**：① 历史收窗改按 token（治理器内贪心收取）；② 超窗历史 → Compactor 增量摘要
  （"上次摘要 + 本次被裁消息"滚动合并，存 `agent_session_summaries`，DDL 随插件
  `agent_ctx_001`）；③ 摘要块作为"会话前情"注入 prior 头部；摘要失败诚实降级。
- **验收**：长会话摘要生成/滚动合并不重复计账；LLM 失败本轮无前情但不崩；多 session 隔离。

### G2 — ReAct 多步循环（plugins/react）

- **问题**：`_trim(history_keep=20)` 按条数裁；`tool_result_max_chars=2000` 一刀切；
  循环内观察累积只增不减，多步长任务窗口膨胀。
- **动作**：① 窗口收束改走治理器（运行时 `ctx.get`，缺省退回现有 `_trim`）；
  ② 工具结果按"剩余配额"动态分配（结果大→少留几条，结果小→多留）；
  ③ 步数过半时把早期观察折叠为一行式摘要（Think 保留，Observe 压缩）。
- **验收**：长循环 token 曲线有界；观察折叠后任务仍可收敛（既有 react 测试全绿）。

### G3 — MCP 工具结果（sys/mcp_client + windows_mcp / playwright_mcp）

- **问题**：**源头零裁剪**——`call_tool` 全量返回（text 逐段 join + structured）；
  大载荷（页面快照、长抓取文本）到下游才被 2000 字符硬切，**结构信息丢失**；
  isError 与正常内容混行。
- **动作**：① `core/tokens.py` 提供 `clip_text / clip_json` 原语，`mcp_client.call_tool`
  做源头护栏（`source_clip_tokens` 上限，超限保留头尾 + `[...省略 N tokens...]` 标注，
  structured 优先于 text）；② 治理器下游按预算精裁（护栏保证不爆，治理保证够用）；
  ③ isError 结果提高保留优先级（错误信息优先于成功内容）。
- **验收**：超限快照被结构化裁剪（头尾保留、省略标注、isError 不丢）；正常小结果零损耗。

### G4 — 记忆架构（plugins/memory，消费方治理）

- **问题**：`memory.context(limit=5, max_chars=1200)` 固定实参；注入内容可能与历史窗口重复；
  打分召回与"当前任务相关性"无关。
- **动作**：① **memory 插件零改动**——`context()` 实参由治理器按 `memory_ratio` 预算反推；
  ② 治理器装配时对记忆块 vs 历史窗口做**去重**（同句式内容不重复占预算）；
  ③ 向量召回/MMR 仍后置（本工程不做，留接缝）。
- **验收**：预算反推实参生效；重复内容不双占；memory 停用时治理器独立工作。

### G5 — 系统提示与工具块（sys/chat._plan/_tools_block、plugins/react/prompt.py）

- **问题**：工具描述 60 字符截断是唯一控制；工具数量增长时 system 块无界膨胀；
  PLAN/FINAL 两套 system 各自组装有冗余。
- **动作**：① 工具块纳入预算刚性区并记账；② 工具清单超预算时按**使用频次**
  （budget 账本按工具名可统计）降载——保留 top-N + "另有 N 件工具可用"占位行；
  ③ 工具块按 session 缓存，同会话不重复拼装。
- **验收**：多工具场景 system 块 token 有界；高频工具保留；工具调用正确性不回归。

## 2. 可观测

- 每轮装配发 durable 事件 `agent/context/governed`：各块 token 实占、裁剪条数、
  是否触发摘要、MCP 护栏命中次数——治理全程可审计。
- 控制台（`run/chat.py`）加"上下文"只读视图：最近一轮装配的块级占用条形 + 摘要状态。

## 3. 实施顺序与提交策略

**G0 → G1 → G2 → G3 → G4 → G5**，每阶段完成即跑全量 pytest（现 144 项 + 各阶段新增）保持绿；
全部完成后**统一提交**（延续 D1–D4 纪律：不产生不可构建的中间提交）。

## 5. 风险与边界

- **估算≠精确**：token 口径诚实标注 estimate，治理目标"不爆窗"而非"填满窗"；
- **摘要成本**：增量摘要走 ctx.llm（budget 记账），`compact_trigger=8` 收敛触发，
  长会话均摊成本可控；失败降级无前情；
- **行为变化**：默认启用后裁剪边界从条数变 token，长消息轮次更早被裁但摘要补前情；
  停用插件即回旧行为；
- **零特权**：mcp_client 只 import core 原语；react 运行时动态消费治理器服务
  （插件名排序可能后于 react 装配）；
- **G4 原则**：memory 插件本体零改动，全部治理动作发生在消费方（治理器）——
  延续"消费面治理"思路，避免为适配治理反向侵入已拆包的插件。
