## 三、目标

让记忆块体量受治理器统一窗口预算约束：治理器给多少 token 配额，记忆块就最多占多少字符；配置层调节 `memory_ratio` 即可整体调记忆块配额，无需改代码。消除"记忆块与历史块预算各自为政"。

## 四、方案核心（仅改 `sys/chat.py` 一处）

### 4.1 模块级常量（可配）

```python
# G4：治理器 token 配额 → memory.context max_chars 的反推系数
# 依据：core/tokens.py 的 CJK 启发式为 0.75 token/字，即 1 token ≈ 1.33 中文字符。
# 取 1.5 为宽松经验值（中文主导场景留余量，保证记忆充足）；
# 若要求严格不超 token 配额，改为 1.33（=1/0.75）。
_MEMORY_TOKEN_TO_CHAR = 1.5
_MEMORY_MAX_CHARS_MIN = 600   # 保底下限，退化配置仍有可用记忆
```

### 4.2 改写 `_memory_block`

```python
async def _memory_block(self, ctx, query: str) -> str:
    if not ctx.has(Services.MEMORY):
        return ""
    try:
        # G4：用治理器反推的记忆配额（token）挂钩窗口预算（默认 1800 token）
        max_chars = 1200  # 退化默认，与现状一致
        gov = ctx.get(Services.CONTEXT) if ctx.has(Services.CONTEXT) else None
        if gov is not None:
            max_chars = max(
                _MEMORY_MAX_CHARS_MIN,
                int(gov.memory_budget() * _MEMORY_TOKEN_TO_CHAR),
            )
        return await ctx.memory.context(ctx, query, limit=5, max_chars=max_chars)
    except Exception:  # noqa: BLE001 —— 召回失败不影响对话
        return ""
```

### 4.3 换算与边界说明

- **配额闭环**：`memory_budget()` = `input_budget() × memory_ratio`。调节 `memory_ratio`（governor 配置）即可整体改记忆块配额，代码零改动——这是本方案优于"改 limit 条数"之处（条数是计数维度，反推需粗估；token→字符是同体量维度，反推自然）。
- **`limit` 维持 5 条不变**：条数只决定"召回候选数"，真正控体量的是 `max_chars` 截断。最小改动原则下不动 `limit`；若后续希望条数也随配额弹性，可再加一条 `limit = max(3, int(max_chars / AVG_ITEM_CHARS))`，本期不做。
- **降级不变**：无治理器 / 召回异常 → 退回 `limit=5, max_chars=1200`，与现状逐字节一致，行为不回归。
