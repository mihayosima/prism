# 解耦收敛设计方案（D1–D4）

> 依据：2026-09-25 全系统解耦复查（12 组实证）。总评"结构纪律 A、契约硬化 A-"，
> 本方案把残余的**默契型契约**收敛为**代码化契约**。与《内核系统层优化方案.md》（sys 层 S1–S7，已落地）互补，
> 本方案聚焦**接缝与契约**，不含新的功能特性。
>
> **修订（实施前逐锚点核验后，2026-09-25）**：
> ① D4 改为「实现迁 `core/audit.py`」——原"实现留 sys/audit.py + api re-export"不可行：
>   `sys/audit.py` 顶层 `from agent.api import Services`，api 反向 re-export 即循环 import，
>   且 `api.py` 在 K0 守卫（test_core_never_imports_sys_or_plugins）扫描内，"from agent.sys" 字面量即挂；
> ② D4 标记清单补全为 **5 个**（补 react 的 `MARK_REACT_TURN / MARK_REACT_FINAL`）；
> ③ D2 的 memory 三组件 Protocol 改为**留在 plugins/memory**（消费方仅 memory 自身；
>   core 只放跨模块消费的 `ReactResultLike`，避免内核"知道"记忆细节）。

## 决策尺子（沿用项目既有纪律）

1. **零行为变化优先**：除 D3 中明确标注的一处行为修正（budget 分槽），其余批次纯重构，全量测试（当前 118+ 项）必须全绿；
2. **每批独立提交、独立验收、可单独 revert**；
3. **SSOT 单一真相源**：新常量一律进 `agent.api`（或 `core/` 对应目录），禁止第三处定义；
4. **不做过度设计**：只开缝不造轮子，Protocol 只固化已被两个以上模块消费的契约。

---

## D1 · LLM 服务契约固化（优先级最高——本次 memory 故障的直接教训）

**问题**：`agent/core/contract.py` 已有 `LlmProvider` Protocol（`agent.api` 已 re-export），但只约束方法签名，
未约束 **schema × stream 互调语义**——provider 在 `stream=True` 时收到 `schema` 调用必须仍返回可解析 JSON。
该默契失守直接导致 memory 提取全量失败（`aa39fb4` 已修行为，未立契约）。

**改动点**：
1. `core/contract.py` `LlmProvider` docstring 增补语义契约：
   - `complete(schema=X, tools=Y)` 的结果**必须与 `stream` 配置无关**；
   - `schema is not None` → 返回 dict 可被 `json.loads` 解析（经由 `_parse_json` 的语义）；
   - `tools is not None` → 返回 `tool_calls` 列表（native 或降级）；
   - 失败一律 raise（由 LlmService 统一发 `agent/llm/call-failed`），不得返回 `{"error": ...}`。
2. 新增 `tests/test_llm_contract.py`（`httpx.MockTransport` SSE 模拟，零触网）：
   - `stream=True + schema` → 断言返回可解析 dict 且 content 非空（回归 `aa39fb4`）；
   - `stream=True + tools` → 断言 tool_calls delta 归并正确；
   - EventBus 契约：**同步监听器内联执行**（budget 退款依赖此语义）——加一条行为锁定测试。
3. `LlmService.complete` docstring 同步引用契约（消费方视角）。

**验收**：新测试 3+ 项全绿；全量测试无回归。
**不做**：不改 `DeepSeekLlm` / `FixtureLlm` 实现（已满足契约）；不做运行期 assert（契约由测试锁定，不加运行时开销）。

## D2 · 接缝 Protocol 化（chat↔react、memory 三组件开缝）

**问题**：chat 消费 `ReactResult` 的 6 个字段（`text / ok / reason / tokens_in / tokens_out / as_evidence()`），
全靠鸭子类型——react 改字段名，chat 运行期才断。memory 三组件（Store/Extractor/Search）是 `apply()` 里
`new` 的构造参数，容器级换不了，与 react 四组件（`ctx.get("react.actor") or ...`）不对称。

**改动点**：
1. **ReactResult 契约固化**：在 `core/contract.py` 新增 `ReactResultLike` Protocol（上述 6 成员），
   `agent.api` re-export；`sys/chat.py` 对 `res` 的类型注解引用之（运行期零开销）；
   新增结构守卫测试：用 `typing.get_type_hints`/成员存在性断言 react 的 dataclass 与 Protocol 对齐（防漂移）。
2. **memory 三组件开缝**（照抄 react 模式）：
   `plugins/memory/__init__.py` `apply()` 改为：
   ```python
   driver = MemoryDriver(
       ctx.get("memory.store") or MemoryStore(ctx.db),
       ctx.get("memory.extractor") or MemoryExtractor(),
       ctx.get("memory.search") or MemorySearch(...),
   )
   ```
   键名与 react 组件键同待遇（守卫测试的"扩展键放行"已覆盖）；三组件 Protocol
   （`MemoryStoreLike / MemoryExtractorLike / MemorySearchLike`）**定义在 `plugins/memory/__init__.py`**
   （消费方仅 memory 自身的 apply 与测试注入，core 不放记忆细节，避免内核知悉业务形状）。
3. 新增 `tests/test_memory_seams.py`：注入一个假 extractor 验证接缝生效（仅 1 个最小用例，证明可换性）。

**验收**：全量测试无回归；注入用例通过；chat 侧与 memory 侧对 Protocol 的引用经 grep 可查。
**不做**：不改变 chat/react/memory 任何运行期行为；不把 Protocol 做成运行期 isinstance 强校验；不开 memory 之外的新缝。

## D3 · ctx.state 键常量化 + budget 分槽（唯一含行为修正的批次）

**问题**：`ctx.state` 是跨插件隐形共享面，现有 8 个键全是裸字符串默契；其中 `budget_pending_est` 是单槽，
react 与 memory 并发调 LLM 时互相覆盖（已实测 `est_cost=None` 漏记）。

**改动点**：
1. 新建 `agent/core/state_keys.py`（`agent.api` re-export）：
   ```python
   class StateKeys:
       BUDGET_SPENT = "budget_spent"
       BUDGET_PENDING_EST = "budget_pending_est"
       REACT_LAST = "react_last"
       PERMISSION_MODE = "permission_mode"     # 前向契约：approval 写、react 读（注释注明）
       LOOP_RUNNING = "loop_running"
       MCP_TOOLS = "mcp_tools"                 # 模板键：f"{bridge}.tools" / f"{bridge}.error"
   ```
2. 引用方改常量：`sys/budget.py`、`plugins/react/loop.py` + `__init__.py`、`sys/loop.py`、
   两个 MCP 桥、`run/chat.py`（状态栏与 `pm._state_file` 处同步清理）；
   `grep -rn 'state\["budget_spent"\]'` 等裸键归零，新增守卫测试（AST 扫描，同 services 键守卫风格）。
3. **行为修正（唯一）**：`budget_pending_est` 改按 caller 分槽——`ctx.state` 存
   `dict[caller, est]`；`_pre` 记入 `pending[caller]`，`_post` / `_call_failed` 各自消账。
   修正并发下 `est_cost` 漏记（S1 语义不变，仅记账粒度细化）。
4. 新增 `tests/test_budget_concurrent.py`：模拟两 caller 交错 pre/post，断言各自 est_cost 落值、spent 总账精确。

**验收**：裸键 grep 归零；并发测试通过；全量测试无回归（`est_cost` 相关既有断言同步更新）。
**不做**：不引入 asyncio 锁（GIL 下 dict 单键读写原子，分槽后无竞态窗口）；不改 `budget_spent` 全局累计语义。

## D4 · 公共面转正 + fixture 标记收敛

**问题**：S7 后 `sys.audit` 事实成为公共面（7 模块 import `_now_iso/durable`，含 2 个插件），
sys 层出现横向 import；fixture 魔法标记（`<!--chat:plan-->` 等）在插件与 fixtures 各写一份。

**改动点**：
1. **实现迁 `core/audit.py`**（修订：原"留 sys/audit.py"会造成 api↔sys 循环 import）：
   `now_iso()`（原 `_now_iso` 去私有前缀）与 `durable()` 移入 `core/audit.py`；
   其对 `Services` 的依赖改为 `from agent.core.services_catalog import Services`
   （core 内部互引先例：`events_catalog → errors`）；
   `agent/api.py` re-export `durable`、`now_iso`（转正公共面）；
   `sys/audit.py` 留兼容别名（`_now_iso = now_iso`），旧引用逐步清零；
2. 全部 import 方（guard/chat/tasks/llm/budget/react/memory 等）改为 `from agent.api import ...`；
3. 魔法标记常量化：`agent/api.py` 新增 **5** 个标记常量
   `MARK_CHAT_PLAN / MARK_CHAT_ANSWER / MARK_MEMORY_EXTRACT / MARK_REACT_TURN / MARK_REACT_FINAL`
   （修订：react 在 `prompt.py:14-15` 有 `TURN_MARK/FINAL_MARK`，原清单漏计）；
   引用方 `sys/chat.py`、`plugins/memory/__init__.py`、`plugins/react/prompt.py`、`fixtures/llm.py`
   全部改引用常量；相关 **docstring 不得再含 `<!--` 字面量**（守卫按 AST 字符串常量扫描）；
4. 新增守卫测试（`tests/test_decouple_guards.py`）：
   - AST 扫描 `<!--` 字面量只能出现在 `agent/api.py`（标记 SSOT）；
   - `StateKeys` 值字面量只能出现在 `core/state_keys.py`（D3 联动）；
   - 生产代码禁止 `from agent.sys.audit` import（公共面已转正）。

**验收**：`grep -rn "from agent.sys.audit" agent/ | grep -v tests` 归零；标记字面量 grep 只剩 api.py；
全量测试无回归。
**不做**：不迁移 `durable` 实现文件；不改任何事件 payload 结构；不做向后兼容 shim（项目无外部消费方）。

## 实施顺序与风险

| 批次 | 内容 | 风险 | 回滚 |
|---|---|---|---|
| D1 | LLM 契约 docstring + 3 项锁定测试 | 极低（纯文档+测试） | 独立 revert |
| D2 | Protocol 化 + memory 开缝 | 低（注解 + 开缝，无行为变化） | 独立 revert |
| D3 | 键常量化 + budget 分槽 | 中（唯一行为修正，涉 6 文件） | 独立 revert |
| D4 | 公共面转正 + 标记收敛 | 中（实现迁移 + 循环依赖规避，K0 守卫护航） | 独立 revert |

- 每批完成即跑**全量测试**（`--basetemp` 全新目录，规避 safe-delete 钩子噪声）；
- D3 若并发测试发现实现复杂度超预期，允许降级为"仅常量化、分槽另立批次"，不硬塞；
- 预计共 4 个提交；D1–D2 可合并为一个提交交付（均为纯契约面）。

- 不做 memory 向量召回/MMR（Search 接缝已为其留位）；
- 不改 EventBus 分发模式与事件目录结构；
- ~~不迁移 `_now_iso` 的实现位置~~（修订：实现迁 `core/audit.py`，sys 层留兼容别名——
  原"只转正 import 面"会与 `sys/audit → agent.api` 形成循环依赖）。
