## 0. 插件体系总览

### 0.1 机制

- **一个插件 = 一个业务包**：约定目录 `agent/plugins/<业务名>/__init__.py`（或 `plugin.py`），内含被 `@plugin` 装饰的 `Plugin` 类。
- **元数据**：类属性 `name`（`plugins.<业务名>`）、`version`、`layer`（`system` / `business`，仅语义标签）、`provides`（提供的服务键，来自 `Services`）、`inject`（声明依赖的服务键）、`tables`（自建表名元组）。
- **生命周期**：`apply(ctx)`（装配期，注册服务/建表/订阅事件）→ `start(ctx)` → `run(ctx, **params)`（主任务，可选）→ teardown（经 `ctx.effect(...)` 注册）。
- **注册服务**：装配期通过 `ctx.provide(Services.XXX, 实现)` 把能力挂到容器；消费方一律用 `ctx.has(Services.XXX)` / `ctx.get(Services.XXX)` **软依赖**获取，因此插件停用即降级、绝不裸崩。
- **装配一次性完成（启动期）**：启停为「重启/重建后生效」，**不热插拔**；卸载 = 停用 + 删目录 + `removed` 标记。

### 0.2 依赖与分层纪律

- **单向依赖、软耦合**：插件之间、插件对内核一律经 `ctx.get(...)` 接缝获取，不得 `from agent.plugins.*` 或 `from agent.core.*` 直接 import 互通（包边界即依赖边界，由 `test_agent_purity` / `test_plugin_decoupling` 守卫）。
- **零特权**：模型调用一律走 `ctx.llm`（guard / budget 照生效），工具调用一律走 `ctx.tasks.invoke`（guard 矩阵 / schema 校验 / owner 审计照生效），写库只走 `ctx.db`。插件不新建特权通道、不碰内核内部。
- **layer 与「来源」正交**：`layer=system` 只是语义标签；能否启停/卸载由「来源（目录插件）」决定——放进 `plugins/` 目录即采用「目录插件」这一生命周期形态，与 guard/llm 等内核组件同级但可独立管理。
- **token 口径唯一**：全仓裁剪一律按 token（`agent.core.tokens`），不再按字符（CJK/ASCII 下字符与 token 差约 3 倍，旧字符口径已删除）。

### 0.3 插件管理器与「双命名空间」取舍

目录插件经 `importlib` 以**文件路径**加载，模块登记在 `agent_plugins.<包名>` 命名空间下——与常规导入路径 `agent.plugins.<包名>` 下的同名类**不是同一对象**。因此：

- 对目录插件实例做 `isinstance(x, agent.plugins.xxx.Cls)` 会**失败**；类型识别请用 `type(x).__name__`，或依赖 `@plugin` 元数据（`name` / `provides`）。
- 该语义只影响测试/诊断中的类型识别，不影响装配与运行。

## 1. 插件管理器（PluginManager）

- **位置**：`agent/sys/plugin_manager.py`（285 行，零 import 引擎，与 agent 运行时同一纪律）
- **职责**：目录插件的**发现 / 启停 / 新增 / 卸载**；语义对齐引擎 `PluginManager`（desired / actual / delta）。

### 1.1 功能概述

| 能力 | 方法 | 说明 |
|---|---|---|
| 发现 | `discovered()` | 扫描 `agent/plugins/<包>/__init__.py` 或 `plugin.py`，加载模块并收集 `@plugin` 类，返回轻量元数据（name / layer / provides / inject / tables / runnable / loadable）。单插件损坏只记录不拖垮发现。 |
| 读取启用集 | `enabled()` | 从期望态文件读 `enabled` 列表。 |
| 启停（持久化） | `set_enabled(name, enable)` | 写 `data/agent_plugin_state.json` 的 `enabled` / `removed` 集合。**重启/重建后生效，不热插拔**。 |
| 读取卸载集 | `removed()` | 读 `removed` 列表。 |
| 新增（脚手架） | `scaffold(name, provides)` | 校验标识符 → 建目录 + 写入含 `@plugin` 类的 `__init__.py` 模板 → 自动加入 `enabled`。 |
| 卸载 | `remove(name_or_id)` | `set_enabled(False)` + 写 `removed` 标记 + `shutil.rmtree` 删目录。 |
| 加载（装配前） | `load()` | 加载「启用 id」对应的目录插件 `Plugin` 对象，供装配期 `apply`。 |

### 1.2 工作原理

- **定位入口**：`_find_locator(pkg)` 在包目录中依次找 `__init__.py` / `plugin.py` 作为插件入口标记。
- **命名空间父包**：`_ensure_namespace_pkg()` 登记 `agent_plugins` 命名空间父包（只建一次），使插件包内相对导入（`from .loop import X`）可解析。
- **加载**：`_load_module(locator)` 用 `importlib.util.spec_from_file_location` 以包方式（`submodule_search_locations`）或单文件方式加载，执行模块、收集 `Plugin` 子类（`_collect_plugins`）。
- **可运行判定**：`_candidate_runnable(p)` 检查类是否定义协程 `run`，把 `runnable` 标记报给「插件」页。
  ⚠️ **当前没有执行入口**：`run/chat.py` 只提供 `/api/plugins`（GET）与 enable / scaffold / remove，**没有 `/api/plugins/run`**，故 `run()` 是**预留钩子** —— 前端只展示该标记，无法触发执行。
- **期望态文件损坏（S7）**：`_read_state()` 若 JSON 损坏，备份为 `.corrupt` 并按**空状态**处理（不再静默清空→否则一次文件损坏即禁用全部目录插件且无人知晓）。

### 1.3 配置与启停

- 约定目录：构造参数 `plugin_dir`（默认 `agent/plugins`）。
- 期望态文件：`data/agent_plugin_state.json`（`{"enabled": [...], "removed": [...]}`）。
- 新增模板：`_PLUGIN_TEMPLATE` 生成标准 `@plugin` 骨架（含 `apply` / `start` / `run` / `_teardown` 与 `ctx.provide` / `ctx.effect` 示例）。

### 1.4 必要说明

- **不热插拔**：启停只改期望态，真正装配在下次启动；这是有意取舍（装配一次性完成）。
- **双命名空间**：见 §0.3，类型识别勿用跨命名空间 `isinstance`。
- **单插件损坏隔离**：发现/加载阶段异常被吞并记入 `loadable: False` / 告警，不拖垮整体装配。

## 2. react 插件（ReAct 多步工具循环）

- **位置**：`agent/plugins/react/`（`__init__.py` · `loop.py` 主循环 · `components.py` 四组件接缝 · `prompt.py` 提示词/工具目录）
- **元数据**：`name=plugins.react`，`layer=system`，`provides=[Services.REACT]`，`inject=[LLM, TASKS, EVENTS, DB]`，`tables=()`（轨迹落 `agent_events`、转写落 `agent_messages`，无自有表 ⇒ 卸载零残留）。

### 2.1 功能概述

提供 `ctx.react`：多步工具循环 **Think → Act+Observe → 收敛**。模型不再返回工具调用即视为最终答复；否则执行工具并把结果回灌，进入下一轮。默认启用；停用后 `ctx.has("react")` 为 `False`，`chat` 自动回退单步「规划→执行→解说」路径（chat 契约一行不改）。

### 2.2 工作原理

- **循环形状**（取自 `loong-agent`）：每轮 Think；模型返回工具调用则 Act+Observe 回灌，否则收敛。
- **三把闸**（补上 loong-agent 缺的护栏）：
  1. `max_steps`（配置，默认 8）——步数上限；
  2. `deadline_s`（每轮开头检查，默认 120s）——整任务时延上限；
  3. **token 预算**——不另写，每步都走 `ctx.llm`，`agent/llm/pre-call` 上 guard/budget 已生效；被拒（`CapabilityNotImplemented`）转「触顶收尾」，不崩。
- **失败即观察**：工具异常 / 参数错 / 被拒都转成观察回灌，让模型自纠；同一工具连拒超 `max_rejects`（默认 3）即终止。注意：`denied_by == "user"`（用户本轮主动拒）**不计连拒**（理由已回灌，模型应换方案），步数/时延闸仍兜底；策略类拒绝（guard/approval 名单/超时）重试无益，照常计数。
- **四组件可换接缝**（`components.py`）：`react.reasoner` / `react.actor` / `react.observer` / `react.finalizer`，容器里存在即用注入实现，缺省用内置（`DefaultReasoner` 等）。好处：将来 `approval` 只需替换 `Actor`（插入「问人」）、并行编排同理只换 `Actor`，**不必改循环本身**。
- **零特权**：模型走 `ctx.llm`、工具走 `ctx.tasks.invoke` ⇒ guard 裁决 / schema 校验 / owner 审计 / 预算记账全部继承。
- **S3 循环内上下文**：Think/Act/Observe 是**任务级草稿**（`TaskContext.chain`），**不进** `agent_messages` / 工作记忆 / Redis；循环结束只把终局文本交 chat 落库。窗口构造两层职责不重叠：
  - `_prepare_chain`（本插件）：块内准备，老观察**逐条首尾折叠**（`clip_head_tail`，只折叠不丢）；
  - `_trim_messages`（治理器）：预算裁剪，**整块丢弃 + 末条保底折叠**。
  - 治理器缺失 / 无 `assemble` 接缝 → 退回旧 `_trim` 条数裁剪（`history_keep`，默认 20），行为不变。
- **依赖方向单向**：`chat --软--> react --软(读 permission_mode)--> approval`；approval 对 react **零依赖**。

### 2.3 配置与启停

`config["agent"]["react"]`：`max_steps`(8) / `deadline_s`(120.0) / `history_keep`(20) / `max_rejects`(3) / `finalize_on_exceed`(True) / `react_keep_recent`(6)。

### 2.4 接缝与扩展点

- 替换 `react.reasoner` / `actor` / `observer` / `finalizer` 任一即可改变循环行为（如接入审批、并行工具）。
- `loop.ReactResult.as_evidence()` 产出机器证据（steps / exhausted / tools / tokens），供 chat 转写与前端展示。

### 2.5 必要说明

- **诚实收尾**：任一闸触顶一律 `durable agent/react/exhausted` + 文本如实说明（不静默失败、不假装成功）；`finalize_on_exceed` 时再问一次模型，失败则退回证据兜底文本。
- **无自有表**：卸载零残留。
- **`type` 为私有语义、`pinned` 为通用元数据**：`think/act/observe` 仅本插件识别；`pinned` 交给治理器先占额度，本插件只负责打标。

## 3. memory 插件（长期记忆 · Zep 式）

- **位置**：`agent/plugins/memory/__init__.py`（388 行，含 Store / Extractor / Search / Driver）
- **元数据**：`name=plugins.memory`，`layer=system`，`provides=[Services.MEMORY]`，`inject=[DB, EVENTS, LLM]`，`tables=(agent_memories, agent_entities, agent_memory_edges)`。

### 3.1 功能概述

提供 `ctx.memory`：参考 Zep 的「时序事实 + 打分衰减 + 上下文注入」记忆子系统。动作：`remember`（LLM 提取，走 `ctx.llm` → guard/budget 照生效）、`add`（手动/决策直写）、`recall`（词面×新鲜度×重访 打分排序）、`context`（组装注入块）、`stats` / `prune` / `wipe`。默认启用；停用后 `ctx.has("memory")` 为 `False`，chat 自动跳过记忆。

### 3.2 工作原理

- **模型**：`MemoryItem`（id / kind / content / entity_ids / score_observed / 时间戳 / accessed_count / valid_at / invalid_at / source / extra）；`KINDS = (fact, intention, decision, observation)`。
- **提取契约**：`EXTRACT_SCHEMA` + `EXTRACT_SYSTEM`（带 `MARK_MEMORY_EXTRACT` 标记，离线 Fixture 据此路由）；`MemoryExtractor.extract` 走 `ctx.llm.complete(..., schema=...)`，提取被拒（`CapabilityNotImplemented`）→ 诚实跳过不假记。
- **三组件可换接缝**：`memory.store` / `memory.extractor` / `memory.search`，缺省用内置。
- **打分召回**（`MemorySearch.score`）：`0.5*词面命中 + 0.3*新鲜度(指数衰减, 半衰期14天) + 0.2*重访(半衰期7天) + 0.05*log(访问次数)`，且 `invalid_at` 存在则整体 ×0.5。
- **持久化**（`MemoryStore`）：`upsert` 用 `ON CONFLICT(id)` 合并（`score_observed` 取 MAX、访问次数 +1）；`valid()` 只返回未过期（`invalid_at IS NULL OR > now`）的记忆；`recall` 后 `touch` 更新访问时间戳。
- **事件**：`durable agent/memory/remembered` · `agent/memory/recall`。
- **零特权**：提取每次都经 `ctx.llm`；写库只经 `ctx.db`。

### 3.3 配置与启停

`config["agent"]["memory"]`：`half_life_days`(14.0) / `access_hl_days`(7.0)（影响打分衰减）。

### 3.4 接缝与扩展点

注入 `ctx.provide("memory.store"|"memory.extractor"|"memory.search", ...)` 可替换存储/提取/召回实现（如换向量召回、MMR 去冗余，当前为 MVP 词面）。

### 3.5 必要说明

- **诚实边界**：提取被拒即记为事件并跳过，不假记「已记住」。
- **衰减与清理**：`prune(older_than_days, min_score)` 删除足够旧且低分（空查询打分）的记忆；`wipe(kind)` 清空（可指定种类）。
- **表随内核统一建**：DDL 在 `agent/tables.py` 由 Storage 建，本插件不自带建表逻辑（仅声明 `tables`）。

## 4. short_term 插件（短期记忆 / 滚动摘要）

- **位置**：`agent/plugins/short_term/`（`__init__.py` · `facade.py` 门面 · `compactor.py` 压缩编排 · `store.py` 存储 · `truncate.py` 截短纯逻辑 · `backoff.py` 退避状态机）
- **元数据**：`name=plugins.short_term`，`layer=system`，`provides=[Services.SHORT_TERM]`，`inject=[DB]`，`tables=["agent_011_session_summaries","agent_012_message_fields"]`。

### 4.1 功能概述

提供 `ctx.short_term`：**内容层**，独占对话历史（`agent_messages` 存储 + 检索 + 对自己内容的滚动摘要压缩）。与调度层 `context`（ContextGovernor）解耦：本插件**不再咨询**治理器的 `pick_history`（收窗机制已移除）；压缩候选取全部未摘要历史，时机由自身 `compact_trigger_tokens` 决定，不拥有任何调度决策。

### 4.2 工作原理

- **门面 `ShortTermMemory`**（唯一对外接口）：`append/history/recent/reset/get_history/latest_summary/summary_meta/get_original_messages/truncate_view/maybe_compress/stats`。`agent_messages` 的写入/读取/清除**只在本门面之后**，消费方零 SQL。
- **存储 `SessionSummaryStore`**：`agent_messages` 与 `agent_session_summaries` 两表的**唯一归属者**；原文始终完整（截短/摘要走窗口内视图或独立摘要表，不改写原文）；`token_count` 写入时预估、读时 NULL 则退回 `estimate_tokens`；`reset` 级联清摘要（同一事务，避免「已删历史的前情」仍被注入）。
- **压缩 `HistoryCompactor`**（两层）：
  1. **第一层 本地截短**（`truncate_messages`）：窗口内可逆、不改原文；仅距末尾 ≥ `recent_rounds` 轮的老内容且超阈值才截；疑似文件用 `file_threshold`、否则 `tool_threshold`；保结构/首尾/关键行。
  2. **第二层 LLM 摘要**（`_maybe_llm_summary`）：五类分节（反馈/纠正 · 未决问题 · 目标/意图 · 事实/决策 · 关键实体），增量更新旧摘要；受优先级预算兜底（`compress_summary_to_budget`：反馈/未决受保护绝不牺牲，总超从低优先级 entity→facts→goal 裁起）。
- **覆盖对齐**：摘要 `covers_up_to_seq` 标记覆盖到哪条，避免窗口滑动丢数据；压缩候选 = `seq > covers` 的未摘要历史。
- **失败处理（§8）**：递增退避 `BackoffState`（1m→10m→1h→24h，按原因分类 llm_error/db_error/...，成功一次清零，恢复探测失败只续期不升级）；LLM 失败 → 降级仅本地截短；本地截短失败 → 不截短喂原文；插件/治理器停用 → `HISTORY_LIMIT` 硬裁。

### 4.3 配置与启停

`config["agent"]["short_term"]`：`compact_trigger_tokens`(12000) / `summary_max_tokens`(600) / `summary_budget_*`(五类) / `min_messages_to_summarize`(4) / `tool_result_max_tokens`(6000) / `file_content_max_tokens`(12000) / `truncate_recent_rounds`(3)。

### 4.4 接缝与扩展点

- `ShortTermMemory` 门面即统一出口，消费方（chat）不直连 SQL。
- 压缩阈值/预算均可配；退避状态机 `BackoffState` 可单测、可观测（`stats()`）。

### 4.5 必要说明

- **与 context 职责不重叠**：本插件是「内容怎么凝练」，治理器是「调度怎么裁」，二者解耦；`pick_history` 保留供未来 G1 分块装配复用，当前无跨插件调用。
- **降级**：停用即退回 `HISTORY_LIMIT` 硬裁，不裸崩。
- **幂等建表**：表随内核 `agent.tables` 统一建（agent_011/012），幂等。

## 5. work_memory 插件（工作记忆 / 任务级进度缓存）

- **位置**：`agent/plugins/work_memory/`（`__init__.py` · `backend.py` 两种后端）
- **元数据**：`name=plugins.work_memory`，`layer=system`，`provides=[Services.WORK_MEMORY]`，`inject=[]`，`tables=()`（状态存 Redis 或进程内）。

### 5.1 功能概述

提供 `ctx.work_memory`：**第 3 层**，任务级进度缓存。接口：`begin/update/checkpoint/get/finish/list_active`。只存任务进度态（step / tool_trace / checkpoints / status），**不存对话全文**（对话历史属短期记忆 `agent_messages`，跨会话知识属长期记忆 `plugins.memory`）。

### 5.2 工作原理

- **后端选择（`apply`）**：配置 `enabled`（默认 True）且可连接 Redis → `RedisWorkMemory`；否则（未配置/不可用/导入失败）→ **降级** `InMemoryWorkMemory`（接口一致）。Redis 客户端**延迟导入**（`try: import redis.asyncio`），未启用零开销。
- **Redis 后端**：`wm:{task_id}` hash；`wm:idx:{session_id}` set 供 `list_active`；所有可变字段以字符串存储，list/dict 经 `json.dumps`；checkpoints 列表上限 10，超丢弃最旧（防 hash 膨胀）。
- **进程内后端**：`dict`（`key -> (expire_at, data)`），跨进程/重启后失效（与 Redis 语义一致，只是不跨进程）。
- **寿命**：任务级——`run()` 开始 `begin`、结束 `finish`（DEL）；兜底 TTL 防泄漏。
- **委托吞异常**：`WorkMemory` 包装层对每个方法 `try/except` 仅告警，保证工作记忆异常**绝不拖累主链路**（react 即便不包 try 也安全）。

### 5.3 配置与启停

`config["agent"]["work_memory"]`：`enabled`(True) / `ttl`(3600) / `prefix`("wm:") / `url`("redis://localhost:6379/0")。

### 5.4 接缝与扩展点

- 接缝契约 `WorkMemoryLike`（begin/update/checkpoint/get/finish/list_active）；可注入替换后端。
- 消费方（react）经 `ctx.get(Services.WORK_MEMORY)` 获取，`None` 则跳过（不破解耦）。

### 5.5 必要说明

- **边界钉死**：只存任务进度态，不存对话全文（避免与短期/长期记忆职责重叠）。
- **降级不崩**：Redis 不可用自动降级内存版，功能不破、不破解耦。
- **进度态 SSOT 仍在 work_memory**：react 的 `TaskContext.task_id` 只是引用，不自持进度字段。

## 7. context 插件（上下文治理 · token 预算装配）

- **位置**：`agent/plugins/context/`（`__init__.py` · `governor.py` 治理器 · `protocols.py` 接缝契约）
- **元数据**：`name=plugins.context`，`layer=system`，`provides=[Services.CONTEXT]`，`inject=[]`，`tables=()`。

### 7.1 功能概述

提供 `ctx.context`（默认实现 `ContextGovernor`）：**全仓唯一持有 token 语义**的组件。职责分阶落地：

- **G0**：预算模型 + token 化历史收窗（`pick_history`）；
- **G1**：分块装配 `assemble(blocks)`（注册制 + 统一互斥 + 刚性超限双通道标注 + 剩余回吐 water-filling）；
- **S3**：循环内（react）预算口径（`react_budget` / `clip_*` / `react_keep_recent` / `react_min_chain_tokens`）+ 块内准备 `clip_head_tail` + messages 块通用 `pinned` 条目支持。

### 7.2 工作原理

- **预算模型**：输入总预算 `input_budget = max_context_tokens - reserve_output_tokens`，按比例分给记忆块（`memory_ratio` 0.10）/ 历史窗口（`history_ratio` 0.60）/ 其余归 system/工具/本轮消息；裁剪一律按 token（`core.tokens.estimate_tokens`），不再按条数。
- **分块装配 `assemble(blocks)`**：
  1. **注册制**：只对 `present` 且非空的块分配预算；权重在「存在的块」间重归一；
  2. **刚性先扣**：`rigid` 块按 `priority` 升序（越重要越先满足）分配，次要块降级并**双通道标注**（`AssemblyReport.rigid_overflow` + `system_text` 内显式 `⚠️` 段），**绝不静默截断**；
  3. **剩余回吐**：可裁块 water-filling——未用满余量回吐公共池再分配（`redistributed` 记账）；
  4. **块内裁剪**：text 块 `_trim_text`、messages 块 `_trim_messages`（整块丢弃 + 末条保底折叠；**绝不逐条折叠**，逐条折叠归块内准备）；
  5. **messages 互斥**：按 `coverage`（**左开右闭 `(lo, hi]`**）排序，重叠时高阶块胜出，绝不双份注入；
  6. **pinned（通用元数据）**：messages 块内 `pinned` 条目**按原顺序先占额度**，额度不足者降级为普通条目并记入 `BlockReport.pinned_downgraded`（诚实、可追溯）；
  7. **`reserve_tokens`（S3）**：为调用方后续块预留额度（如 react 的 chain 保底），先扣除再分配。
- **S3 循环内**：`react_budget = input_budget - prior_tokens`（**可为负**，prior 超预算时由 chat 调度层先压缩再重建）；`clip_head_tail` 只折叠不丢（保头 `clip_head_tokens` + 保尾 `clip_tail_tokens`，错误常在尾部）。
- **职责边界钉死**：治理器**只回答「内容怎么裁、占多少 token」**，**不感知任何业务语义**（不认识「任务进度」，也不认识循环步骤类型；条目 `type` 属消费方私有，治理器只认通用 `pinned`）。

### 7.3 配置与启停

`config["agent"]["context"]`：`max_context_tokens`(24000) / `reserve_output_tokens`(4000) / `memory_ratio`(0.10) / `history_ratio`(0.60) / `source_clip_tokens`(8192) / `clip_max_tokens`(1000) / `clip_head_tokens`(500) / `clip_tail_tokens`(500) / `react_keep_recent`(6) / `react_min_chain_tokens`(2048)。

### 7.4 接缝与扩展点

注入 `ctx.provide("context.governor", ...)` 可用自定义治理器替换默认 `ContextGovernor.from_config(cfg)`。消费方契约见 `protocols.py`（`BlockSpec` / `BlockReport` / `AssemblyReport` / `Assembly` / `GovernorLike`）。

### 7.5 必要说明

- **消费面软依赖**：`ctx.has(Services.CONTEXT)`；插件停用即退回各消费方现状，不劣化不裸崩。
- **G0 零依赖**：预算纯计算，无表、无 LLM。
- **零特权**：预算/裁剪一律走 `core.tokens` 公共原语，不碰内核内部。

## 8. approval 插件（人机审批 + 权限模式）

- **位置**：`agent/plugins/approval/`（`__init__.py` · `policy.py` 三态判定 · `providers.py` 通道接缝 · `pending.py` 待答表 · `options.py` 候选项归一）
- **元数据**：`name=plugins.approval`，`version=0.4.0`，`layer=system`，`provides=[Services.APPROVAL]`，`inject=[EVENTS, DB]`，`tables=()`（审计走现成 `agent_events`，卸载零残留）。

### 8.1 功能概述

提供 `ctx.approval`：**人在环中审批 + 权限模式（会话档位持有者）**。职责三分（互不混同）：

- **mode**（会话档位 `default/plan/auto/bypass`）：本插件持有，写 `ctx.state["permission_mode"]`；
- **policy**（三态 `allow/deny/ask` + fnmatch）：`policy.py` 纯函数；
- **provider**（怎么问人）：`providers.py` 可换接缝（非交互 `auto-deny`/`auto-allow`、交互式 `web` 经 `pending.py` + SSE 弹窗 + 入站应答接口、`cli` 终端问答）。

此外提供两个常驻工具：`approval.ask_user`（澄清问询，read 级、plan 模式可见，发交互卡片）与 `approval.submit_plan`（仅 plan 模式可见的终态工具）。

### 8.2 工作原理

- **挂点与优先级**：默认 `append` 挂 `agent/tasks/pre-execute`，排 guard（`prepend`）之后 ⇒ guard 硬否决短路、approval 不被调用（AC-7 天然成立）；guard 放行 ⇒ `next()` ⇒ approval 按自身名单+模式判定。`ask` 的来源只本插件名单与模式；guard 的 `permissions.risk.*="ask"` 是无 approval 时的 fail-safe 兜底，两者不应同时使用。
- **三态判定 `decide(rules, tool, mode, risk)`**（顺序）：
  1. `deny` 名单命中 → `deny`（一票否决）；
  2. `plan` + 非只读 → `deny`（plan 硬兜底：软约束看不见，硬约束必须拒绝，防幻觉写工具越权）；
  3. `auto` + 非只读（`write/danger`）或 `ask` 名单命中 → `ask`；
  4. `allow` 名单命中 → `allow`；
  5. 未命中 → `default`（**默认 `deny`**：fail-safe；出厂 `allow=["*"]` 保持「默认全放行、行为与现状一致」）。
- **fail-safe 铁律**：`ask` 无人应答 / 超时 / provider 异常 / 插件停用 ⇒ **一律默认拒绝**。
- **会话级批量确认（第 3 期）**：应答带 `always` → 记会话级名单（`_session_allow` / `_session_deny`），此后同类请求不再问。
- **plan 终态**：进 plan 动态注册 `submit_plan`（离开即注销）；模型提交计划→问人批准；同意 ⇒ 切 `auto`（§6.3），拒绝 ⇒ 留 plan 回灌意见。
- **澄清问询 `ask_user`**：`options` 经 `normalize_options` 归一为选择规格（`label/value/desc/group`），卡片据此渲染单选/多选、带说明、分区；`multi=True` 用户勾选多项回灌 `choices`；非交互通道立即告知模型自行假设，超时/未应答返回 `answered=False` 并附假设提示。
- **待答表 `PendingTable`**（交互式基座）：`call_id → Future + 超时 + 去重`。三保证：① 超时返回 `{"approved":False,"by":"timeout"}`；② 同 `(tool, args)` key 去重，并发多 ask 合并为一次人答；③ `aclose()`（teardown/停用）唤醒全部在途等待者为拒绝，不留悬挂协程。

### 8.3 配置与启停

`config["agent"]["approval"]`（与 `profiles.BASE_AGENT_CONFIG` 的 approval 节一致）：

```json
{ "provider": "auto-deny", "allow": ["*"], "deny": [], "ask": [],
  "timeout_s": 30, "default": "deny" }
```

默认 `allow=["*"]` ⇒ 全放行（与无本插件时行为一致），便于灰度；`provider` 可选 `auto-deny`(fail-safe 默认) / `auto-allow`(开发灰度,审计照记) / `web` / `cli`。

### 8.4 接缝与扩展点

- **provider 接缝**：`ApprovalProvider` 协议，`build_provider(name, table)` 按名构造；新增通道只需实现 `ask(ctx, req) -> {"approved", "by"}`，且**无权放行 guard 已否决的任务**（它排在 guard 之后根本看不到那些调用）。
- **policy 纯函数**：`hit` / `decide` 零依赖（仅 `fnmatch`），可单测、可替换判定策略。
- **options 归一**：`normalize_options` 把 JSON 数组/对象数组/逗号文本统一成选择规格（label 去重保序、单卡片上限 24、单项上限 200 字符）。

### 8.5 必要说明

- **不改 guard 一行**：挂点 append 在 guard 之后，硬规则先裁、问人后行。
- **默认配置 = 现状**：`allow=["*"]` 时行为与无 approval 完全一致，灰度安全。
- **审计全程**：`asked/answered/timeout/mode_changed` 等事件落 `agent_events`（即便 `auto-allow` 也照记，可事后追责）。

## 9. playwright_mcp 插件（浏览器自动化桥）

### 9.5 必要说明

- **默认未启用**：避免无谓起子进程；启用即出现在工具目录。
- **headless 默认**：后台服务无显示器；需有头时设 `headless=false`（需 DISPLAY）。

## 11. events 插件（事件总线）

- **位置**：`agent/sys/events_plugin.py`（21 行）
- **元数据**：`name=agent.events`，`layer=system`，`provides=[Services.EVENTS]`，`inject=[]`。**内核常驻插件**，不经 `PluginManager` 启停。

### 11.1 功能概述

提供 `ctx.events`：全仓唯一的 **EventBus（双模式 emit + waterfall + strict-payload）**。所有插件经它订阅生命周期与 capability 事件（`LLM_PRE_CALL` / `TASKS_PRE_EXECUTE` / `CHAT_IN` / `CHAT_RESET` / `CONTEXT_GOVERNED` 等），是内核事件/钩子通道，也是 guard/budget 做 capability 裁决的载体。

### 11.2 工作原理

- **装配**：`apply` 构造 `EventBus()` → `ctx.provide(Services.EVENTS, bus)`；`ctx.effect(bus.aclose)` 在 teardown 时取消并等待在途 fire-and-forget 监听器任务（K4a，防悬挂协程）。
- **双模式**：`emit`（fire-and-forget 异步，不阻塞调用方）/ `waterfall`（有序链式，供 guard/budget 做 capability 裁决，handler 可 `return 不带 next()` 短路）。
- **strict-payload**：事件 payload 须为 `dict`；订阅用 `ctx.on(event, handler, prepend=...)`，`prepend=True` 令裁决插件（guard/budget）先执行。

### 11.3 配置与启停

无配置；常驻内核插件，随运行时装配，无法经 state 文件启停/卸载。

### 11.4 接缝与扩展点

事件名见 `agent.api.Events`；消费方 `ctx.on(...)` 订阅、`waterfall` 用 `next()` 放行或返回 `{"denied": True, ...}` 短路。

### 11.5 必要说明

- **零依赖、不落库、无 LLM**：纯运行时通道。
- **teardown 安全关闭**：`aclose` 唤醒在途监听者，避免进程退出悬挂。
- **与目录插件解耦**：同为 `Services.EVENTS` 消费，但它本身不经 `agent/plugins/` 生命周期。

## 12. llm 插件（模型接缝）

- **位置**：`agent/sys/llm.py`（428 行）
- **元数据**：`name=agent.llm`，`layer=system`，`provides=[Services.LLM]`，`inject=[Services.EVENTS]`。**内核常驻插件**。

### 12.1 功能概述

提供 `ctx.llm.complete(...)`：**统一模型接缝**。按配置选 Provider（fixture 离线 / deepseek 真实 / 其它占位诚实拒绝），消费方只调 `complete`，不关心具体厂商。负责 wire 转换（内部消息/工具名 ↔ OpenAI 兼容）、token 记账、流式打字机、思考链外发。

### 12.2 工作原理

- **`LlmService.complete` 包夹 capability 事件**：`pre-call` waterfall（guard→budget 预借）→ `provider.complete` → `post-call` emit（真实 `usage` 入账；S6 优先真实 token，无则回退 `estimate_tokens`）；失败发 `LLM_CALL_FAILED`（budget 同步退款）后原样抛出。
- **Provider 选择（`apply`）**：`fixture`/`offline` → `FixtureLlm`；`deepseek`/`ds` → 解析 key（`config > env DEEPSEEK_API_KEY > local_secrets.json`，缺 key → `PlaceholderLlm` 诚实拒绝）；其它 → `PlaceholderLlm`。
- **`DeepSeekLlm`**：`httpx.AsyncClient` 懒初始化复用连接池（S6 `close()` 释放）；**非流式**（默认行为）与**流式**（`stream` + `stream_options.include_usage`，B5.2 打字机；D4 `reasoning_content` 思考链照流不混入 `text`；D3 `tool_calls` 按 `index` 归并）；优先采集响应 `usage` 真实 token 数经返回值 `usage` 键上交。
- **Wire 转换**：`_wire_messages`（内部 `tool_results`/`tool_calls` ↔ OpenAI `role=tool`/`function`）；`_wire_tools`（工具目录 → functions 数组，内部命名空间名净化 `^[a-zA-Z0-9_-]+$`，映射表回程还原，重名加 `_2`/`_3` 消歧）；`_wire_call`（模型净化名还原内部原名）；`_parse_json` 剥离 markdown 围栏解析。

### 12.3 配置与启停

`config["agent"]["llm"]`：`provider`(fixture) / `model` / `api_key` / `stream`(true) / 真实实现预留（未配 key → `PlaceholderLlm` 不虚标）。常驻内核插件。

### 12.4 接缝与扩展点

换厂商 = 新增 `LlmProvider` 实现（协议 `interface_version=(1,0)`）+ 在 `apply` 注册；`ctx.llm.complete` 契约稳定（`schema` / `tools` / `caller`）。

### 12.5 必要说明

- **诚实边界**：未接入厂商 → `CapabilityNotImplemented` 不虚标；失败如实上浮。
- **token 口径唯一**：`usage` 真实优先，否则 `estimate_tokens`；与全局 token 口径一致。
- **零特权**：guard/budget 在 `pre-call` 已生效，模型调用不绕过裁决。

## 13. budget 插件（成本护栏）

- **位置**：`agent/sys/budget.py`（80 行）
- **元数据**：`name=agent.budget`，`layer=system`，`provides=[Services.BUDGET]`，`inject=[Services.EVENTS, Services.DB, Services.LLM]`。**内核常驻插件**。

### 13.1 功能概述

提供 `ctx.budget`：**成本护栏**（挂在模型接缝，非管线内嵌）。`pre-call` 已花 + 本次估算 > 上限 → 否决（return 不带 `next()`）；`post-call` 真实 token 入账落 `agent_budget_log`。`max_tokens_per_run` 是**容器生命周期累计额度**；`reset_on_new_session`（默认 True）→ 网页「新会话」经 `CHAT_RESET` 重置累计。

### 13.2 工作原理

- **`_pre`（LLM_PRE_CALL waterfall，后裁决）**：`est` 覆盖 `messages + tools + schema`（S1 不再漏算请求侧开销）；`spent + est > max` → `denied`；否则预借记账（`pending est` **按 caller 分槽** D3：react 与 memory 并发调 LLM 时互不覆盖，est 不漏记）。
- **`_post`（LLM_POST_CALL emit，S1 对账）**：用实际入账替换预借（`spent = spent - est + actual`），账面精确等于 Σ 实际；落 `agent_budget_log(model, tokens_in, tokens_out, est_cost, at)`。
- **`_call_failed`（LLM_CALL_FAILED，同步监听器内联执行）**：全额退还本次预借。
- **`CHAT_RESET`（若 `reset_on_new_session`）**：`spent` 清零。

### 13.3 配置与启停

`config["agent"]["budget"]`：`max_tokens_per_run`(10000) / `model`（取 `llm.model`）/ `reset_on_new_session`(True)。常驻内核插件。

### 13.4 接缝与扩展点

与 guard 同为 capability 裁决插件——**guard `prepend` 先裁决（权限先），budget 后裁决（成本后）**。消费面经 `LLM_PRE_CALL` 链路，无需直接调用。

### 13.5 必要说明

- **仅管 LLM 成本**（工具/cron 不在此账）。
- **按 caller 分槽**避免并发漏记；**失败退款**保证账面精确。
- 日志表 `agent_budget_log` 随内核统一建。

## 14. guard 插件（权限网关）

- **位置**：`agent/sys/guard.py`（96 行）
- **元数据**：`name=agent.guard`，`layer=system`，`provides=[Services.GUARD]`，`inject=[Services.EVENTS, Services.DB]`。**内核常驻插件**。

### 14.1 功能概述

提供 `ctx.guard`：**权限网关**（capability 事件裁决 + durable 审计）。矩阵 `config["agent"]["permissions"]` **默认 open**（不先限制能力）。挂在 `LLM_PRE_CALL` + `TASKS_PRE_EXECUTE`（`prepend`，与 budget 同 seam 但先裁决：权限先、成本后）。允许 → `next()`；拒绝 → 不带 `next()` 短路 `{"denied": True, reason}`。每次裁决落 durable `agent/permission/decision`（审计=事件查询，不另建表）。

### 14.2 工作原理

- **`_decide(kind, target, caller, risk)`**：
  - `llm` → `open` 则 `allow` 否则 `deny`；
  - `task` → `deny` 名单命中 → `deny`；`risk` 策略（`deny`/`ask`/`allow` 优先）→ `default open` 放行 → 否则走 `task_allow` 名单（`"*"` 或命中 → `allow` 否则 `deny`）。
- **`_pre_llm` / `_pre_task`**：先 durable 审计，再裁决。
- **`ask` 风险级**（`risk="ask"`）：MVP 按拒绝处理——返回 `denied`，提示「approval 插件未接入前按拒绝处理」。

### 14.3 配置与启停

`config["agent"]["permissions"]`：`default`(open) / `llm`(open) / `task_deny`[] / `task_allow`[] / `risk{...}`。常驻内核插件；`policy(ctx)` 返回当前矩阵副本（诊断用）。

### 14.4 接缝与扩展点

纯函数 `_decide`（零依赖、可单测、可替换判定策略）；与 approval 插件分工——guard 硬否决/allowed，approval 负责 `ask` 问人（guard 排在 approval 之前先裁，AC-7 天然成立）。

### 14.5 必要说明

- **默认 open 零回归**：出厂不限制能力。
- **fail-safe**：`ask` 风险级无 approval 时按拒绝。
- **审计全程**落 `agent_events`；不改业务插件一行。

## 15. loop 插件（裁决驱动主循环）

- **位置**：`agent/sys/loop.py`（100 行）
- **元数据**：`name=agent.loop`，`layer=system`，`provides=[Services.LOOP]`，`inject=[Services.TASKS, Services.EVENTS]`。**内核常驻插件**。

### 15.1 功能概述

提供 `ctx.loop`：**裁决驱动主循环（loop-as-plugin）**。`AgentDriver` 协议使消费方只依赖接口——**换驱动 = 换插件**。`ProduceDriver`：跑一次 task（`tasks.resolve → run(ctx,**params)`），重叠 skip + deadline 上限 + 单次异常捕获（不 kill 调度）。

### 15.2 工作原理

- **`ProduceDriver.run`**：`state[LOOP_RUNNING]` 防重叠（overlap skip）；`tasks.resolve` 任务入口；`deadline_s`（`config.agent.loop.deadline_s` 默认 60）`asyncio.wait_for` 上限；`TimeoutError`/`Exception` 返回 `RunResult(ok=False)` 不抛（单次任务失败不 kill 循环）。

### 15.3 配置与启停

`config["agent"]["loop"]["deadline_s"]`(60)。常驻内核插件。

### 15.4 接缝与扩展点

`AgentDriver` 协议（`run` / `cancel` / `when_idle`）；换驱动 = 实现协议 + 在 `apply` 提供 `Services.LOOP`。`chat` 是第二 driver（会话外设），与 loop 互不依赖。

### 15.5 必要说明

- 单次任务失败被吞为 `RunResult` 不 kill 调度；重叠 skip 防重入；cancel 即时生效。
- **不落库、无 LLM**：纯调度原语。

## 16. storage 插件（数据访问 + 迁移）

- **位置**：`agent/sys/storage.py`（148 行）
- **元数据**：`name=agent.storage`，`layer=system`，`provides=[Services.DB, "migrations"]`，`inject=[]`（`db_path` 取 `ctx.config`）。**内核常驻插件**。

### 16.1 功能概述

提供 `ctx.db`（独立库，默认 `data/agent.db`）+ 迁移注册器（`namespace=agent`）。只提供 `execute`/`query`/`transaction`/迁移执行，**不承载业务语义**（业务词只许出现在 `agent.tables` DDL）。装配即建全量表。

### 16.2 工作原理

- **`SqliteDb`（stdlib `sqlite3` 实装）**：零后台线程（本地微秒级，事件循环内直跑；`asyncio.Lock` 串行化防并发写，避免 aiosqlite 跨事件循环悬挂）；`WAL` + `busy_timeout=5000`（S7 多进程稳）；显式事务（`isolation_level=None`，`BEGIN`/`COMMIT` 本类掌控）；事务块内 `execute` 不自行提交（`_in_tx`）；dict 行（`row_factory`）。
- **`MigrationRegistry.apply`**：建 `agent_migrations` 表；**幂等**（已应用跳过）；**防脏武**（已应用但代码已删 → `AgentError` 拒绝启动）；每组迁移全语句 + 名字登记包进单事务（中途失败整组回滚，不留半套表、不留名字，下次启动可完整重放）。
- **`apply`**：`db.start()` → `provide DB + migrations` → `effect close` → `migrations.apply(MIGRATIONS, "sqlite", namespace="agent")`。

### 16.3 配置与启停

`config["db_path"]`（默认 `data/agent.db`）。常驻内核插件。

### 16.4 接缝与扩展点

换后端 = 换本插件 provider（现 sqlite 实装，dialect 映射留位）；迁移 DDL 集中在 `agent.tables`（`MIGRATIONS`），业务插件只声明 `tables` 不写 DDL。

### 16.5 必要说明

- **业务严禁直连 sqlite**：只走 `ctx.db`。
- **防脏武**保护迁移（删旧迁移会拒绝启动）；WAL 多进程安全；teardown 关库。

## 17. tasks 插件（任务注册表）

- **位置**：`agent/sys/tasks.py`（237 行）
- **元数据**：`name=agent.tasks`，`layer=system`，`provides=[Services.TASKS]`，`inject=[Services.EVENTS]`。**内核常驻插件**。

### 17.1 功能概述

提供 `ctx.tasks`：**任务注册表**（`run(ctx,**params)` 统一入口 + `owner` + `risk` 元数据）。`register` **注册即逆**（teardown 对称移除）；`catalog` 输出工具目录（带 `risk`）；内置 `agent.ping`。是所有工具调用的**唯一入口**（含业务插件、MCP 桥），guard/budget/owner 审计在此统一生效。

### 17.2 工作原理

- **`TaskRegistry.register`**：名称唯一（D-3，重复抛 `AgentError`）；`risk ∈ {read, write, danger}`（默认 `write`，保守）；`owner` 缺省 `current_plugin()`；注册时 `ctx.effect(dispose)` **注册即逆**。

- **`_guard_result`**：软依赖 context（无则不限），整函数 self-try，护栏失效不得掀翻工具调用（仅 `warning`）。
- **`resolve`**：降级为 `lambda **kw` 可调用（面向 loop/桥）；`catalog`：工具目录带 `risk`/`owner`/`params`；`owned_by`：按 owner 查。
- 内置 `agent.ping`（`owner=None`）。

### 17.3 配置与启停

无独立配置（`risk` 默认 `write`；guard 矩阵在 guard 插件）。常驻内核插件。

### 17.4 接缝与扩展点

`register` 即统一工具入口；MCP 桥（playwright/windows）经 `ctx.tasks.register` 把外部工具挂入；`risk` 元数据供 approval/权限模式消费（当前只落字段）；`pre-execute` waterfall 供 guard/approval 挂载。

### 17.5 必要说明

- **名称唯一**（冲突即报错）；`risk` 默认保守 `write`。
- **源头护栏**按 context 软依赖（无治理器不裁，与全线降级一致）；失败也发 `post` 事件（审计不缺失败样本）。
- **注册即逆**防悬挂。

## 18. chat 插件（对话驱动 · 第二 driver）

- **位置**：`agent/sys/chat.py`（557 行）
- **元数据**：`name=agent.chat`，`version=0.1.0`，`layer=business`（sys/ 中**唯一的业务层插件**，但仍为内核常驻），`provides=[Services.CHAT]`，`inject=[Services.LLM, Services.TASKS, Services.EVENTS, Services.DB]`。**记忆四层（MEMORY/SHORT_TERM/SYSTEM_MEMORY 等）为软依赖，不写 `inject`**——否则目录插件未启用时容器装配直接 `MissingDependencyError`；消费处一律 `ctx.get(...) or 默认`。

### 18.1 功能概述

提供 `ctx.chat`：**第二 driver（交互问答外设）**。机器权威，LLM 只做「规划 + 复述」：`send` → ①规划（LLM→JSON intent）→ ②执行（走 `tasks`/只读面，guard 照生效）→ ③解说（LLM 按机器证据复述成友好 markdown）。**多步**：若装配 `react`（`ctx.has("react")`）→ 委托 ReAct 循环（合约不变）；未装配回退单步路径。durable：`CHAT_IN` / `CHAT_DONE`（审计脊柱）。

### 18.2 工作原理

- **`send`**：空消息短路 → durable `CHAT_IN` → append user → `_build_prior`（短期记忆内容层 + 治理器调度层收窗，统一互斥左开右闭 `(lo, hi]`，react 经 `reserve_tokens` 预留 chain 保底）→ 有 react → `_ensure_react_headroom`（prior 超预算一次性压缩重建，不重试）→ `_send_via_react`；否则 ①`_plan`（LLM JSON intent，失败当闲聊）→ ②`_execute`（`tasks.invoke`，guard 照生效）→ ③`_narrate`（LLM 解说，被拒用证据兜底）→ 写 assistant → 喂 `memory`（若启用，失败不破坏主链）→ durable `CHAT_DONE` → 触发 `_safe_compress`（异步压缩）。
- **规划/解说**：刚性块（`plan_head`/`env`/`answer_head` priority 0/90）保证与降级拼接逐字节一致；工具目录动态（`catalog()`）注入提示词；`_env_facts` 把真实用户名/主目录/桌面喂规划器并禁用 `%VAR%` 占位符（从源头杜绝不展开路径）。
- **`_assemble`**：经治理器 `assemble` 软依赖（无治理器/无接缝 → `_fallback_assemble` 降级拼接，对拍等价）；`reserve_tokens` 为后续块（react chain）预留；装配后发 `CONTEXT_GOVERNED` 遥测。
- **诚实降级**：LLM 任一步被拒（预算/guard/解析）→ 解说用证据兜底，不给假成功。

### 18.3 配置与启停

`config["agent"]["chat"]` 无强制配置；短窗 `HISTORY_LIMIT=12`（≈6 轮，治理器/短期记忆缺失时硬裁）。常驻内核插件（但 `layer=business`）。

### 18.4 接缝与扩展点

`ctx.has(REACT)` 委托多步；记忆四层经 `ctx.get(...)` 软依赖（MEMORY/SHORT_TERM/SYSTEM_MEMORY）；与 react/context/approval 单向软耦合（契约一行不改即可降级）。

### 18.5 必要说明

- **机器权威**：LLM 不越权自由裁量，只规划+复述。
- **多步委托合约不变**：chat 只经 `ctx.has("react")` 感知其存在，不 import 其实现。
- **诚实降级**（不假成功）；短期记忆内容层 owner（chat 零 SQL）；与 react 共享审计脊柱。

## 19. 通用纪律与约定（跨插件）

1. **软依赖消费**：消费方一律 `ctx.has(...)` / `ctx.get(...)`；插件停用即降级，绝不裸崩。
2. **零特权**：模型 → `ctx.llm`，工具 → `ctx.tasks.invoke`，写库 → `ctx.db`；不碰内核内部、不新建特权通道。
3. **诚实边界**：装配失败/不可用诚实报（不假挂）、提取/调用被拒诚实跳过（不假记）、预算超限显式标注（不静默截断）。
4. **layer 与来源正交**：`layer` 仅语义标签；能否启停/卸载由「目录插件」来源决定。
5. **token 口径唯一**：全仓按 `core.tokens`，字符口径已废弃。
6. **装配一次性（启动期）**：启停重启/重建后生效，不热插拔；卸载 = 停用 + 删目录 + `removed` 标记。
7. **双命名空间**：目录插件实例在 `agent_plugins.<pkg>`，类型识别勿跨命名空间用 `isinstance`。
