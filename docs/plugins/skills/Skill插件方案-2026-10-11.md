## 1. 背景与动机

现有 agent 的能力扩展只有两类：

- **tool（原子函数）**：`ctx.tasks.register` 注册，模型可直接调用。告诉模型「能调什么函数」。
- **MCP（外部服务桥）**：把外部 CLI/服务封装成工具。本质是「远程函数」。

二者都停留在「**能力点**」层面——模型知道有哪些函数可用，但**不知道遇到某类任务「该怎么一步步做」**。这正是「光有 tool、MCP 不能很好完成工作」的根因：缺少**可复用的高阶流程 / 方法论**封装层。

**Skill（技能）** 补全这一层：每个技能是一份「遇到 X 类任务时，按 Y 步骤做」的说明文档 +（可选地）一段可被编排器直接执行的代码。它与 tool/MCP **正交互补**：skill 描述「怎么做」，tool 提供「能做的具体动作」，skill 内部可调用既有 tool 完成步骤。

> 业界对照（已联网核实）：Claude Code 与 OpenAI Codex 均遵循 **Agent Skills 开放标准**——技能 `SKILL.md`（frontmatter `name`/`description` + 正文）**只挂免费索引进系统提示、正文按需注入**，**绝不进常驻工具注册表**。这正是本方案的形态依据。

## 2. 设计目标

1. **形态 = 两者兼具**：每个 skill 同时拥有 `content`（说明文档，给模型看）+ 可选 `run`（代码入口，给编排器调）。文件型技能只有 `content`（低代码写 playbook）；插件型技能可再带 `run`。
2. **暴露 = 单工具 + 免费索引 + 按需注入**：系统提示里挂一个紧凑索引块（技能名 + 一句话摘要 + 权限档），**零工具注册、零发现往返**；模型需要时调**单个** `skill` 工具（`action=load` 注入正文 / `action=invoke` 调代码入口）。彻底避开「每个技能占一条 tool schema」的 token 黑洞。
3. **两种来源**：① 插件贡献（Python，可含 `run`）；② 文件型 `SKILL.md`（低代码，仅 `content`）。两者汇入同一目录，对模型视角无差别。
4. **零破坏既有路径**：技能**不进 `ctx.tasks` 工具注册表**（避免注册表污染与跨 run 状态）；未启用技能插件时，react 所有新增分支整段跳过，行为逐字节等价现状。

## 3. 架构（解耦方向已修正）

```
                [来源 A] 插件 apply  ctx.provide(Services.SKILLS, catalog)
                                                      │
                [来源 B] 文件发现   data/skills/*.md 解析
                                                      │
                                                      ▼
                                          SkillsCatalog 实例
                                          ├─ meta_tools()  -> list[dict]   （单 skill 工具定义，常驻）
                                          ├─ handle_meta(task, call, ctx) -> ToolResult
                                          │      action="load"  ⇒ content 写入 task.skill_docs
                                          │      action="invoke" ⇒ 调 Skill.run(ctx, **params)
                                          └─ index_block(max_chars) -> str   （带预算上限的索引）

   ┌─────────────────── ReactLoop（运行时，零 import skill）───────────────────┐
   │                                                                           │
   │  cat := ctx.get(Services.SKILLS, None)     ◄── 反向读取，无则全部跳过      │
   │                                                                           │
   │  (1) 索引注入    build_system(..., system_memory += cat.index_block())    │  ← loop.py:606 / prompt.py:120
   │  (2) 工具合并    visible_tools += cat.meta_tools()   （常驻，独立于 lazy_tools 开关）│
   │  (3) 调用路由    发往 "skill" 的 tool_call ⇒ cat.handle_meta(task, call, ctx)│  ← 独立于 _partition_meta
   │  (4) 正文注入    reason(..., system_note="\n".join(task.skill_docs))      │  ← loop.py:769 / components.py:117
   │                                                                           │
   └───────────────────────────────────────────────────────────────────────────┘

   ctx.provide / ctx.get 经父链解析（context.py:147-156）；运行期 ctx 是装配根的子作用域，
   故运行期 ctx.get(Services.SKILLS) 必中装配期 provide 的 catalog。
```

**对照 v1 的关键修正**：v1 画的是「skills → react 注册（register_meta_tool）」方向，错误。正确方向是 **react 运行时反向读取 skills 提供的契约**；`Context` 无 `register_meta_tool` 方法（全量确认），该方向本就走不通。

## 4. 数据模型（`agent/core/skill.py`）

```python
@dataclass
class Skill:
    name: str                 # 唯一键，如 "skill.docker_build"
    description: str          # 触发摘要（索引块展示，≤120字首行，复用 _slim_description）
    content: str              # markdown 说明（注入上下文；纯文本 ⇒ 400 安全）
    owner: str = ""           # 来源域（插件 id 或 "file:data/skills"）
    risk: str = "read"        # read/write；影响权限裁剪
    tags: list[str] = field(default_factory=list)
    version: str = "0.1.0"
    run: Callable | None = None   # 可选执行入口 run(ctx, **params) -> dict
    enabled: bool = True
```

## 5. 注册表契约（`agent/sys/skills.py` —— `SkillsCatalog`）

> 注意：下面是 **react 反向读取的契约面**，react 只依赖以下方法签名，永不 `import` `SkillsCatalog` 具体类型。

- `register(skill)` / `unregister(name)`
- `catalog() -> list[dict]`：卡片（name / description / tags / risk / owner / has_run）
- `search(keyword) -> list[card]`：按 name+description+tags 模糊匹配（供 `skill` 工具的 search action 复用，可选）
- `load(name) -> Skill | None`：返回含 `content` 的完整技能
- `invoke(name, ctx, **params) -> dict`：调用 `run`，包成 `{"ok": bool, "output"/"error": ...}`
- **`meta_tools() -> list[dict]`**：返回单 `skill` 工具 schema（常驻可见，**不依赖** `lazy_tools` 开关）
- **`handle_meta(task, call, ctx) -> ToolResult`**：处理发往 `skill` 工具的调用
  - `action="load"`（risk=read）：`load(name)` 取 `content`，追加进 `task.skill_docs`，返回「已加载」确认
  - `action="invoke"`（risk 取自技能）：转 `invoke(name, ctx, **params)`，结果包成 `ToolResult`
- **`index_block(max_chars: int = 8000) -> str`**：生成紧凑索引（name + 一行摘要 + 权限档），带预算上限（仿 Codex 2%/8000 字规则）；技能过多时压缩 `description`、超阈值省略并告警
- 文件技能 + 插件技能合并；同名冲突按「插件侧优先」或显式 `ServiceConflictError`（待定，见开放问题）

## 6. 文件型发现（`agent/sys/skills_loader.py`）

- 扫描 `data/skills/*.md`（及可选 `agent/plugins/<p>/skills/*.md`）
- 解析 frontmatter（`name` / `description` / `tags` / `risk` / `owner`）+ 正文（`content`）
- **低代码**：文件技能 `run=None`（纯说明型）；代码型一律走插件
- 解析失败 → 告警 + 跳过单个（不拖垮启动），与 `PluginManager` 同纪律

## 7. 装配插件（`agent/plugins/skills/__init__.py`）

- `apply`：加载文件技能 → 实例化 `SkillsCatalog` → `ctx.provide(Services.SKILLS, catalog)`
- 可选 `status()` 自述技能数量；随容器 teardown 对称回收
- **本插件不 import react、不调用任何 react 注册方法**——纯净单向依赖（PluginManager → 两插件）

## 8. 内核衔接（含两处隐藏点）

## 9. react 暴露（`agent/plugins/react/loop.py`）—— 整节重写（v2 修正）

> v1 把 skill 寄生在 `LAZY_META_TOOLS` + `_partition_meta` 是错误的：默认 `lazy_tools=False`（`loop.py:733-734`、`842`），该通道**根本不激活**，tool_search/tool_load/wm_read 默认对模型不可见 ⇒ skill 默认失效。**必须走独立常驻通道，与 `lazy_tools` 开关正交。**

改动清单（全部零耦合，无 SKILLS 时整段跳过）：

1. **工具合并（常驻）**：在 `_tools_for_step`（约 `loop.py:733` 起）计算 `tools_step` 后，若 `cat := ctx.get(Services.SKILLS, None)` 存在，则把 `cat.meta_tools()` 并入可见工具集。**该合并不依赖 `lazy_tools` 开关**，故 skill 工具默认可见。
2. **调用路由（常驻）**：新增一处**独立于 `_partition_meta`** 的 meta 调用分发——当某 `tool_call.name == "skill"` 时，路由到 `cat.handle_meta(task, call, ctx)` 并返回 `ToolResult`（观察）。不进 `ctx.tasks` 注册表，无跨 run 状态污染。
   - 注：`_tools_for_step` / `_partition_meta` 当前签名**无 `ctx` 参数**，需各加一个 `ctx` 形参（小改，调用点同步传参）。
3. **索引注入（免费）**：`loop.py:606` `build_system(prompt_catalog, ..., system_memory=...)` 处，若 `cat` 存在，把 `cat.index_block()` 追加进 `system_memory`（`prompt.py:120` 确认该参数是前置静态底座，承载常驻索引最干净）。随每轮下发，但仅 ~30 tok × 技能数，且免费可见、零发现往返。
4. **正文注入（按需）**：`loop.py:769` 主循环 `out = await self._reasoner.reason(ctx, window, tools_step)` 调用处补 `system_note="\n".join(task.skill_docs)`（不破坏签名，A 方案重试增强已用过同通道）。模型下一轮即「看到怎么做」。
5. **字段新增**：`TaskContext`（`loop.py:108` dataclass，与 `loaded: set` 同款位置）增 `skill_docs: list[str] = field(default_factory=list)`。循环内草稿，不进 `agent_messages`、不写 Redis，随 run 结束即弃（与 `loaded` 同纪律）。
6. **上限**：`skill_docs` 受 `skill_docs_max_chars` 封顶（超则截断+标注，镜像 `lazy_tools_max`）；正文纯文本，compact 收缩时不会触发 DeepSeek 400。

## 11. 治理 / 审计 / 设置

- **clip**：`skill_docs` 经 token clip / `guard_source`，避免窗口膨胀；`content` 纯文本 ⇒ compact 安全
- **权限裁剪（plan 模式）**：skill 带 `risk`；plan 下 `action="load"` 仅放行 `risk=="read"` 的技能；`action="invoke"`（write）在 plan 下被拒（与 tool 同款 `guard`/`approval` 闸门，见开放问题 2）
- **审计**：durable 事件 `SKILL_LOADED` / `SKILL_INVOKED`（可选，低优先）
- **开关**：插件技能随插件 enabled；文件技能用 `data/skills_state.json`（`disabled` 列表）或复用 `agent_plugin_state.json` 兄弟键
- **索引预算防护**：`index_block` 超 8000 字 / 上下文 2% 阈值时压缩 `description`、省略并告警（仿 Codex），防止索引本身撑爆系统提示

## 13. 风险与缓解

| 风险                 | 缓解                                                                |
| ------------------ | ----------------------------------------------------------------- |
| 默认失效（v1 致命）        | skill 走**独立常驻通道**，不绑 `lazy_tools` 开关                              |
| 索引膨胀               | `index_block` 带 8000 字 / 2% 预算上限，超阈压缩+省略+告警                       |
| `skill_docs` 膨胀    | `skill_docs_max_chars` 上限 + 只注入已 load 的技能；纯文本，compact 安全          |
| 与 `tool_load` 语义混淆 | skill 注入「说明」，tool_load 加载「函数 schema」，职责清晰分离                       |
| 权限裁剪（plan 模式）      | skill 带 `risk`；plan 下仅放行 `risk=="read"` 的 load；invoke（write）被拒    |
| 代码型 `run` 安全       | `action="invoke"` 走与 tool 同款护栏（guard/approval 视 `risk`，待定见开放问题 2） |
| `ALL` 守卫失败         | `Services.SKILLS` 同步进 `ALL` frozenset（隐藏点，v1 漏）                   |
| `ctx` 缺参           | `_tools_for_step`/`_partition_meta` 加 `ctx`（隐藏点，v1 漏）             |
