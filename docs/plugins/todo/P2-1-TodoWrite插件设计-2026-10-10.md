## 1. 目标与范围

把 P0-2 的「纯文本规划纪律」升级为**真实机制**：结构化待办 + 实时进度，且 **`loop.py` 零改动**（与 P1-1 把无进展检测焊死在 loop 形成对比，正面验证"规划能力走插件而非 loop"）。

- **本插件只做选项 1（计划完成度跟踪）**。
- **P1-1 无进展检测不迁入**：其归宿是独立护栏插件 / `sys/guard.py`（给待办清单插件赋予"停 loop"开关属于职责错配）。
- **明确不做**：`EnterPlan` 工具 / planner 角色 / 计划跨 run 落库（留后续）；不动 `loop.py` 一行。

## 2. 为什么必须走"工具调用"这条路（架构约束，结合实代码）

本仓 react 循环里，**模型改变 agent 侧状态的唯一通道是工具调用**：
- `system_memory`（`system_memory/__init__.py:33-39`）只是 `ctx.provide(Services.SYSTEM_MEMORY, text)` → 注入系统提示词，**模型只读、写不出状态**；
- 事件订阅（`ctx.on`，如 `approval/__init__.py:106`、`sandbox/__init__.py:361`）是**框架自动触发**，模型控制不了；
- `provide` 服务（`work_memory`/`memory`/`context`）是**代码消费**，模型看不见。

所以"让模型往一个 TodoStore 里写计划、标完成"**只能通过调一个注册好的工具**。其余三条通道对模型都是只读或自动——这是 `approval`/`subagent`/MCP 插件全部走 `ctx.tasks.register` 的根本原因（见 `approval/__init__.py:113,284`、`subagent/__init__.py:54`、`playwright_mcp/157`）。

**真正的岔路口**：
- 路线 A（纯文本，无工具）= 已落地的 **P0-2** `02-planning.md`——模型在回复里写 `[ ]/[x]` 块，react 当普通对话历史存着；无结构化存储、无进度事件、无前端进度条。
- 路线 B（真结构化，工具）= 本插件——`todo.write`/`todo.list` 注册成工具，`TodoStore` 持有状态，mutation 后 emit `TODO_PROGRESS`。

用户已选"带进度跟踪的 TodoWrite 插件"，即路线 B → 工具调用是路线 B 的必然代价，不是多余设计。

## 3. 成功案例借鉴：Claude Code 的 TodoWrite

下列做法来自对 Claude Code TodoWrite 机制及工程实践案例的核实（来源：`deepwiki.com/marckrenn/cc-mvp-prompts/4.1-todowrite-system`、`learn-claude-code s03-todo-write`、`claudepluginhub cagents todo_write_helper`、Mario Giancini《The Checklist Manifesto for AI Commands》），**直接决定本设计的若干关键决策**：

### 3.1 整表替换（幂等）—— 坐实决策点①
Claude Code 的 TodoWrite **每次调用传入完整列表、整体替换旧状态**（"Each invocation of the tool updates the entire task list, replacing the previous state"）。这**直接支持**本设计 `todo.write` 采用"整表替换"而非增量接口：简单、幂等、天然支持重排序与删除。⇒ 决策点①（整表替换 vs 增量）以成功案例背书，定为**整表替换**。

### 3.2 严格状态机（坐实"质量"而非"装饰"）
Claude Code 强制以下规则，本设计在 `store.write()` 内落实：
- **恰好一个 `in_progress`**：任意时刻只能有 0/1/多中的"恰好 1 个";多则自动归一（保留最近一个、其余回退 pending），不在工具层拒绝调用以免阻断。
- **开始前标 `in_progress`**、**完成后立即标 `completed`**（不要批量标记）。
- **彻底移除无关项**（不要留在列表里）。
- 仅当任务**完全完成**才标 completed；卡住时保持 `in_progress` 并新增一条描述卡点的任务，绝不一知半解地标 completed。

### 3.3 字段约定（已对齐）
每条 todo = `content`（祈使句，如"修复登录 bug"）+ `activeForm`（进行时，如"正在修复登录 bug"，进度条展示用）+ `status`（`pending|in_progress|completed|blocked`）。与 `02-planning.md` 现有字段一致。

### 3.4 触发条件（写进提示，避免噪声）
应主动用 TodoWrite 的场景：**≥3 步**、非平凡、用户明确要求、多任务并列、新收到多需求。
**不应**用的场景：单步直白任务、<3 步琐事、纯对话问答、单条命令执行——避免给简单任务强加开销（对齐 Mario Giancini 的"Skip it for"清单）。

### 3.5 BLOCKING PREREQUISITE（写进提示）
多步任务**必须先建清单再动手**——"未调用 TodoWrite 前不得推进下一步"。借鉴 cagents 的强制先置约束，用提示强化（非 loop 拦截）。

### 3.6 防跑偏 reminder 注入（本设计的"防中途失序"机制）
Claude Code 的成功关键之一是：**≥N 轮未调用 todo → 向提示注入 `<reminder>` 把模型拉回正轨**（`learn-claude-code s03`："rounds_since_todo ≥ 3 → 注入 reminder"）。
- **本仓实现（loop 零改动）**：不引入 in-loop 计数器，而是把"若已进行多步却未维护 todo，应立即补建"写进 `02-planning.md`（经 `system_memory` 每轮注入系统提示词），作为**软提醒**。这保住"loop 零改动、规划走插件"的架构立场。
- **可选增强（不在本轮）**：未来若需硬约束，可加一个**独立微小钩子插件**订阅 `REACT_STEP_END`、按会话计数未调 todo 的步数、超阈值 emit 一个 `TODO_REMINDER` 事件由 `system_memory` 消费——仍不碰 `loop.py` 主逻辑。in-loop 硬计数需改 `loop.py`，**本轮不做**。

## 4. 数据模型（`store.py`，纯逻辑、可单测）

### 4.1 会话隔离（关键：照搬 approval 的分桶思路）
`sys/progress.py:14-15` 明确警告：**子 ctx 的 `state` 不继承父级**，且审批/H2 教训表明 `ctx.state` 是**容器级**——直接往 `ctx.state` 写 todo 会跨会话串号。`approval` 的正确做法是按 `current_session_key()`（ContextVar，按 asyncio task 隔离）分桶（`approval/__init__.py:99-104,237`）。**TodoStore 同样按会话分桶**，绝不碰容器级 `ctx.state`。

```python
# agent/plugins/todo/store.py
from __future__ import annotations
import time, uuid
from dataclasses import dataclass, field

@dataclass
class Todo:
    id: str
    content: str
    status: str = "pending"          # pending | in_progress | completed | blocked
    active_form: str = ""
    created_at: str = ""
    updated_at: str = ""

class TodoStore:
    # 按会话分桶：键 = current_session_key(ctx) or "default"（ContextVar，非 ctx.state）
    _buckets: dict[str, list[Todo]] = field(default_factory=dict)

    def write(self, session_key: str, todos: list[dict]) -> dict:
        """整表替换 + 严格状态机归一，返回 summary。"""
        items, in_prog = [], 0
        for t in todos:
            st = str(t.get("status", "pending"))
            st = st if st in ("pending", "in_progress", "completed", "blocked") else "pending"
            if st == "in_progress":
                in_prog += 1
            items.append(Todo(
                id=str(t.get("id") or uuid.uuid4().hex),
                content=str(t.get("content", "")),
                status=st,
                active_form=str(t.get("active_form", "")),
                created_at=str(t.get("created_at", "")) or _now(),
                updated_at=_now()))
        # 严格状态机：恰好一个 in_progress（多则保留最后一个、其余回退 pending）
        if in_prog > 1:
            seen = 0
            for t in reversed(items):
                if t.status == "in_progress":
                    seen += 1
                    if seen > 1:
                        t.status = "pending"
        self._buckets[session_key] = items
        return self.summary(session_key)

    def list(self, session_key: str) -> list[dict]:
        return [vars(t) for t in self._buckets.get(session_key, [])]

    def summary(self, session_key: str) -> dict:
        items = self._buckets.get(session_key, [])
        total = len(items)
        done = sum(1 for t in items if t.status == "completed")
        return {
            "total": total,
            "pending": sum(1 for t in items if t.status == "pending"),
            "in_progress": sum(1 for t in items if t.status == "in_progress"),
            "completed": done,
            "blocked": sum(1 for t in items if t.status == "blocked"),
            "percent": round(done / total * 100) if total else 0,
        }
```

> 注：`_now()` 用 `agent.api.now_iso()`（与 approval 同款）保证时区一致。

## 5. 工具契约（`risk="read"`，关键决策 + 代码坐标）

| 工具 | 参数 | 行为 | risk |
|---|---|---|---|
| `todo.write` | `todos: list[{content, status?, activeForm?, id?}]` | **整表替换**（Claude Code 风格，幂等） | **read** |
| `todo.list` | — | 回读当前清单 + 完成度摘要 | **read** |

**为何 `risk="read"`**（核实坐标）：
- `loop.py:245-246` 的 plan 过滤 `catalog = [t for t in catalog if t.get("risk")=="read"]` 只放行只读工具；若标 `write` 会被藏，废掉"在 plan 模式做规划"的能力。
- 安全不依赖这层软过滤：`approval/policy.py:36` 对 `mode=="plan" and risk!="read"` 硬拒；未标注工具默认 `write`（`sys/tasks.py:114`）→ 照样拒。软过滤对安全是多余的，但对"规划可见性"恰好必需。
- **反向印证独立发现**：plan 模式软可见性过滤过粗——隐藏 write 工具对规划无安全价值、反而削弱计划质量。TodoWrite 是首个因该过滤而**必须**标 `read` 的"本地状态写"工具；后续此类工具应引入 `risk="local"` 语义（仅改 agent 自身内存态、无外部副作用），而非一律 `write`。**这是待评审的改进项，不在本轮实现。**

## 6. 插件主体（`__init__.py`，照搬 subagent/approval 范式）

```python
# agent/plugins/todo/__init__.py
from __future__ import annotations
from agent.api import Events, Services, current_session_key, plugin, now_iso
from .store import TodoStore

@plugin
class TodoWrite:
    name = "plugins.todo"
    version = "0.1.0"
    layer = "business"
    provides = [Services.TODO]
    inject = [Services.TASKS, Services.EVENTS]
    tables = ()                                   # 不落库（会话内存态），卸载零残留
    description = "结构化待办/规划：列计划、跟踪完成度、暴露前端进度条"

    async def apply(self, ctx) -> None:
        self._ctx = ctx
        self._store = TodoStore()
        ctx.effect(self._dispose)
        ctx.tasks.register(
            ctx, "todo.write",
            schema={"todos": {"type": "array", "required": True,
                             "description": "完整待办列表（整表替换）。每项："
                                            "content(祈使句,必填) / status("
                                            "pending|in_progress|completed|blocked) / "
                                            "activeForm(进行时短语,进度条展示) / id(可选,留空自动生成)"}},
            handler=self._write, owner="plugins.todo",
            description=("维护结构化待办清单（整体替换）。非平凡多步任务开始前先调用列计划，"
                         "每完成一步更新对应 status 为 completed 并把下一项置 in_progress；"
                         "用户端可见实时进度。plan 模式下亦可调用。"),
            risk="read")
        ctx.tasks.register(
            ctx, "todo.list",
            schema={},
            handler=self._list, owner="plugins.todo",
            description="回读当前待办清单与完成度摘要", risk="read")
        ctx.provide(Services.TODO, self)

    async def _write(self, *, todos: list | None = None) -> dict:
        sk = current_session_key(self._ctx) or "default"
        summary = self._store.write(sk, todos or [])
        try:
            await self._ctx.events.emit(Events.TODO_PROGRESS, summary)   # live 遥测，不落库
        except Exception:                                                # 遥测失败不阻断主链路
            pass
        return {"ok": True, **summary}

    async def _list(self) -> dict:
        sk = current_session_key(self._ctx) or "default"
        return {"todos": self._store.list(sk), **self._store.summary(sk)}

    async def status(self, ctx) -> dict:                                # 供插件页可观测（仿 approval）
        sk = current_session_key(ctx) or "default"
        return {"session": sk, **self._store.summary(sk)}

    async def _dispose(self) -> bool:
        self._store = None
        return True
```

> 注册范式严格对齐 `subagent/__init__.py:54-101`（`risk="read"`、显式 `owner`、`inject=[Services.TASKS, Services.EVENTS]`、`ctx.provide`）+ `approval/__init__.py:113-138`（schema 描述详尽、handler 返回 dict）。`ctx.tasks.register` 返回值可存为 dispose 句柄（approval `:284-293` 动态注销先例），但本插件工具常驻，无需动态注销。
