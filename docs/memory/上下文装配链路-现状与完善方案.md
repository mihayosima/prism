# 上下文装配链路：现状与完善方案

> 文档目的：把「一次对话请求 → 拼装成喂给 LLM 的 messages」的**完整链路**讲清楚（现状），并给出上下文治理器的**分阶段完善方案**（G1–G5）供评审。
> 范围：上下文调度层（`plugins.context`）+ 各记忆层（system / long-term / work / short-term）+ 对话驱动（`sys.chat`）。
> 立场：所有断言均来自当前代码实证（含 `file:line`），非设计臆测。
> 当前状态（已确认）：长期记忆 `plugins.memory` 经插件页停用，处于 `desired:false / actual:false / 未装配`，故下文"长期记忆块"现状为**不注入**。
> 结构变更（2026-09-26）：**收窗机制（`pick_history` 从消费方）已移除**，压缩时机改由 `compact_trigger_tokens`（默认 12000，经设置视图可调）单独决定；前端新增「⚙️ 设置」视图承载上下文管理可调项；"记忆"tab 改为分层展示（B 方案）。

## 1. 现状

### 1.1 组件与职责边界

| 组件 | 层 / 类型 | 是否启用 | 职责 | 关键文件 |
|---|---|---|---|---|
| `plugins.system_memory` | ① 系统记忆 | ✅ | 静态声明底座（身份/规则），**前置注入**到 plan/narrate 的 system | `plugins/system_memory/` |
| `plugins.context` (`ContextGovernor`) | 调度（system 层目录插件） | ✅ | **只做预算查询**：token 分块预算（`history_budget`/`memory_budget`/`source_clip_budget`）；历史收窗方法 `pick_history` 保留但未调用（收窗机制已从消费方移除）；**不持有任何记忆内容** | `plugins/context/governor.py` |
| `plugins.short_term` | ④ 短期记忆（内容层） | ✅ | 会话转写（`agent_messages`）+ 滚动摘要（`agent_session_summaries`）+ 本地截短 | `plugins/short_term/` |
| `plugins.work_memory` | ③ 工作记忆 | ✅（本机无 Redis→内存降级） | 任务/会话态（run 级），非对话历史 | `plugins/work_memory/` |
| `plugins.memory`（长期记忆） | ② 长期记忆 | ⛔ **已停用** | 实体/关系/打分召回；停用后 `ctx.memory` 缺失，`_memory_block` 返回 `""` | `plugins/memory/` |
| `sys.chat`（`ChatDriver`） | 业务驱动 | ✅ | 把上述内容**装配**成 LLM messages；协调 plan→execute→narrate | `sys/chat.py` |

**单向依赖纪律**（沿用用户纠正的红线：上下文管理管**调度 / 预算**，短期记忆管**内容与压缩时机**）：
- `sys.chat._build_prior` 经 `ctx.get(Services.SHORT_TERM)` 取得 `summary_meta`（含 `covers_up_to_seq`），由短期记忆**自行决定**装配边界；消费面一律 `ctx.has(...)` 软依赖（停用即退回 `HISTORY_LIMIT` 硬裁，不裸崩）。
- `short_term.compactor` 压缩时机**完全由自身 `_threshold()`（读取 `compact_trigger_tokens`）单独决定**；不再经 `ctx.get(Services.CONTEXT).pick_history` 咨询调度层（收窗机制已移除）。
- 长期记忆 `plugins.memory` 停用后，`_build_prior` 仍能经 `SHORT_TERM` 正常装配；`pick_history` 方法仅保留供 G1 分块装配复用。
- 短期记忆表归属（`agent_messages` / `agent_session_summaries`）已收口到 `store.py`，chat 零 SQL。

### 1.2 一次对话的完整装配链路

入口：`ChatDriver.send()`（`sys/chat.py:94`）→ 单步分支 `plan/execute/narrate`，或多步分支 `_send_via_react`。

```
send(message, session_id)
├─[1] 写 durable 事件 CHAT_IN                           (chat.py:99)
├─[2] _append(user)  → short_term.append               (chat.py:101,196)
├─[3] prior = _build_prior(session_id, message)        (chat.py:103)  ← 核心装配
├─[4] if ctx.has(REACT):  _send_via_react(prior)       (chat.py:106)
│       └─ react.run(prior=prior)  # 复用同一 prior；循环内窗口治理=G2 缺口
│   else:
│     ├─ plan      = _plan(message, prior)             (chat.py:109)
│     ├─ evidence  = _execute(plan)                    (chat.py:110)
│     └─ text,...  = _narrate(plan, evidence, prior)  (chat.py:111)
├─[5] _append(assistant)  → short_term.append          (chat.py:121,169)
├─[6] if ctx.has(MEMORY):  ctx.memory.remember(...)    (chat.py:127,170)  ← 当前恒 false
├─[7] 写 durable 事件 CHAT_DONE                        (chat.py:134,178)
└─[8] asyncio.create_task(_safe_compress)  后台触发滚动摘要 (chat.py:139,184)
```

#### 链路核心：`_build_prior`（chat.py:217–248）

```
short    = ctx.get(Services.SHORT_TERM)        # 内容层（软依赖，缺失→HISTORY_LIMIT 降级）
raw      = short.get_history(session_id)        # 全量历史 seq ASC，含原文 (store.py)
raw_excl = raw[:-1]                            # 排除本轮 user（调用方单独追加）
meta     = short.summary_meta(session_id)      # 取 covers_up_to_seq（摘要已覆盖到哪条）
covers   = int(meta["covers_up_to_seq"]) if meta else 0
post     = [m for m in raw_excl if m["seq"] > covers]   # 仅喂「未摘要」部分（互斥边界）
post_view= short.truncate_view(post)           # 单条超大消息可逆截短（安全网，非收窗）
summary  = short.latest_summary(session_id)    # 滚动摘要（可能为 None）
prior    = ([summary 头部] if summary else []) + post_view
```

- **收窗机制已移除**（2026-09-26 改造）：`sys.chat` 不再调用 `governor.pick_history`，历史窗口不再做"按 token 预算从新到旧贪心收窗"。取而代之：压缩时机完全由 `short_term.compactor._threshold()`（读取 `compact_trigger_tokens`，默认 **12000**）控制——未摘要历史达到阈值即晋升滚动摘要，`covers_up_to_seq` 随之前移，使"已摘要部分"自动退出 prior（互斥边界在 `summary_meta` 处取得，而非收窗）。
- `truncate_view`（`compactor.py:178`）：仅对 `post` 中**单条超大**消息（工具/文件结果）做窗口内可逆截短（保留最近轮次、工具结果≤6000 tok、文件≤12000 tok）；原文留在 `agent_messages`，窗口内视图凝练。**这是单条安全网，不是历史收窗。**
- **降级**：`ctx` 无 `SHORT_TERM` 时退回旧 `HISTORY_LIMIT` 条数硬裁（chat.py:246–248），不裸崩。

#### 装配出的最终 messages 结构

**plan 段**（chat.py:289–290）：
```
[ system = MARK_CHAT_PLAN
          + 系统记忆(system_memory)            ← 前置注入 (chat.py:277-280)
          + PLAN_SYSTEM
          + 长期记忆块(_memory_block)          ← 当前停用→空 (chat.py:282)
          + 工具目录(_tools_block)             (chat.py:285)
          + 环境事实(_env_facts)               (chat.py:288)
] + prior + [ user = message ]
```

**narrate 段**（chat.py:363–364）：
```
[ system = MARK_CHAT_ANSWER
          + 系统记忆(system_memory)            (chat.py:355-358)
          + ANSWER_SYSTEM
          + 证据 JSON(plan+evidence)
          + 长期记忆块(_memory_block)          ← 当前停用→空 (chat.py:360)
] + prior + [ user = message ]
```

> 两段（plan / narrate）**各自独立重拼** prior，且 system 组成不同（规划器 vs 解说员），因此同一轮对话 LLM 被调两次、各带一份上下文。

### 1.3 降级与解耦纪律

- **软依赖守卫**：`sys/chat.py` 对四记忆层一律 `ctx.has(...)` 判断 + `ctx.get(...) or 默认`，绝不写进 `inject`（否则未启用即 `MissingDependencyError`）。
- **内容层缺失降级**：`_build_prior` 无 `SHORT_TERM` 时退回旧 `HISTORY_LIMIT` 条数硬裁（chat.py:246–248），不再依赖治理器收窗；`ContextGovernor` 缺失亦不影响装配（仅预算查询不可用，装配路径已不咨询它）。
- **压缩失败不拖累主链路**：`_safe_compress` 外层 try/except；`maybe_compress` 仅"执行异常"计失败+递增退避（compactor.py:70–77）。
- **reset 级联清摘要**：`delete_session` 同事务删历史 + 摘要，避免"已删历史的前情"残留注入（store.py:128–141）。

## 2. 完善方案（分阶段落地 G1–G5）

### 2.1 设计原则（沿用既定纪律）

1. **调度/内容分离**：`context` 只做**预算决策**（收窗机制已于 2026-09-26 移除，压缩时机归短期记忆 `_threshold` 决定），记忆内容（含摘要）仍归各记忆层 owner。
2. **软依赖 + 降级**：任一新能力缺失须退回现状，不裸崩。
3. **零特权**：预算/裁剪只走 `core.tokens` 公共原语；表归属收口到 owner 插件。
4. **可逆优先**：窗口内凝练不改原文（`agent_messages` 始终完整），摘要为独立表。

### 2.2 分阶段路线图

#### G0（已完成）
预算模型（token 分块预算 `history_budget`/`memory_budget`/`source_clip_budget`）+ **压缩阈值 `compact_trigger_tokens` 开放可调（经设置视图即时生效）** + 接缝可注入。✅ 已上线。
> 注：原 G0 的"token 历史收窗（`pick_history`）"已在 2026-09-26 改造中**从消费方移除**——压缩时机改由 `_threshold()` 单独决定，`pick_history` 方法保留供 G1 复用。

#### G1 — 分块装配统一编排（✅ **已实现，2026-09-26**）
- **目标**：把"四块如何拼、各占多少"收敛到治理器统一编排，给 prior 一个**总 token 硬上限**，避免长会话下无限增长。
- **已实现**：`governor.assemble(blocks)`（注册制 / 左开右闭互斥 / water-filling 回吐 / 刚性超限双通道）；`sys/chat` 的 `_plan`/`_narrate`/`_build_prior` 均经 `_assemble` 装配、`_fallback_assemble` 降级（逐字节对拍）；`agent/context/governed` 事件接线。详见 [`../governance/G1-分块装配-设计方案.md`](../governance/G1-分块装配-设计方案.md) §3。
- **已完成的前置（2026-09-26）**：摘要/历史互斥边界已就位——`_build_prior` 以 `covers_up_to_seq` 直接排除已摘要历史（不再"摘要+原文"重复，原 S2 闭环）；`pick_history` 收窗已从消费方移除。
- **待做改动面**（深化设计见 [`docs/governance/G1-分块装配-设计方案.md`](../governance/G1-分块装配-设计方案.md)）：
  - **块注册制**：块由消费方构造并自声明存在性（`present`）——memory 停用 / 短会话 / 无工具 → 该块 `absent`；治理器只对存在的块分配预算，**权重在存在块间重归一**（静态比例不适用）。
  - **统一互斥规则**：S1 层形式化"任意两 `messages` 块 `coverage` 区间两两不相交"，边界语义**一律左开右闭 `(lo,hi]`**（summary `(0,covers]` / history `(covers,N]`，由 `covers_up_to_seq` 单一来源派生；`covers` 由 chat 作入参传入，避免 governor 反向查询）；S2 层由治理器装配时校验边界相接（重叠则 priority 小者胜出）并加守卫单测——**S2 是 S1 互斥规则在 messages 维度的应用，非独立问题**。
  - `ContextGovernor` 新增 `assemble(blocks)` 返回 `Assembly{system_text, prior, report}`（`report` 为 `AssemblyReport` **dataclass**，非裸 dict）；`chat._plan/_narrate/_build_prior` 改为构造块列表交由治理器统一装配（无治理器 → `_fallback_assemble` 旧拼接降级，**对拍不劣化**）。
  - **预算收口**：刚性块超限按 priority 诚实降级并**双通道标注**（`AssemblyReport.rigid_overflow` + `system_text` 内显式标注段）；剩余预算**回吐**给被截断的可裁块（water-filling，`redistributed` 记录）。
  - （可选）若需保留"最近 N 条硬窗口"语义，可让 `pick_history(messages, budget, *, keep_first, exclude_upto=None)` 重新接线（`exclude_upto` 即 `covers_up_to_seq`），但**非必需**——当前靠摘要晋升自然收敛。
- **验收**：长会话（>50 轮）下 prior token 数被钳在 `history_budget` 量级、无重复 seq、总 messages 长度有上限。

#### G2 / S3 — react 多步窗口治理（✅ **已实现，2026-09-26**）
- **目标**：多步循环内 Think/Act/Observe 也受上下文预算约束（S3）。
- **已实现**：`plugins/react` 不再复用 `pick_history`（**该思路已驳回**：会话级工具，循环内无 seq/covers）
  也不新写裁剪器，而是**复用 G1 的 `assemble`**——块列表 `react_system`（rigid）/`react_prior`（rigid）/
  `react_prompt`（rigid）/`react_chain`（可裁）。折叠/丢弃**职责不重叠**：react 只逐条折叠老观察
  （`_prepare_chain`，不丢条目），治理器只整块丢弃 + 末条保底（`_trim_messages`，不逐条折叠）。
  chat 侧新增**超预算闸**（`_ensure_react_headroom`，一次性压缩）与 **chain 保底**
  （`_build_prior` 经 `reserve_tokens` 预留）。
- **验收**：✅ 12 步大观察工具链每步 `total_used <= input_budget`（`test_react_context.py`）。
- 详见 [`../governance/S3-循环内上下文-设计方案.md`](../governance/S3-循环内上下文-设计方案.md)。

#### G3 — MCP/工具源头护栏接线
- **目标**：巨量工具/MCP 输出在进模型前被裁到 `source_clip_budget()`（S4）。
- **改动面**：`chat._execute` 拿到 `evidence.result` 后，对超长结果经治理器 `source_clip_budget()` 截断（或交由 `short_term.truncate_view` 统一处理）。
- **验收**：单工具返回 50k tok 时，进模型的仅 ≤8192 tok，且关键行保留。

#### G4 — 记忆注入配额反推
- **目标**：`_memory_block` 用 `governor.memory_budget()` 反推 `limit`/`max_tokens`（S5）。
- **改动面**：`chat._memory_block` 改为 `ctx.memory.context(query, max_tokens=governor.memory_budget())`；长期记忆停用时不调用。
- **验收**：记忆块 token 不超过 `memory_budget()`，与历史块预算可加总校验。

#### G5 — 工具块动态降载
- **目标**：工具目录描述按剩余预算动态裁剪（S6）。
- **改动面**：`_tools_block` 接收治理器剩余预算，超阈值时压缩描述 / 折叠低频工具。
- **验收**：工具数从 5→50 时，工具块 token 增长受控。

### 2.3 优先级与节奏建议

| 优先级 | 阶段 | 理由 |
|---|---|---|
| P0 | **G1** | 当前唯一"会出错"的短板（长会话重复注入），且是其余阶段的基础编排 |
| P1 | **G3 → G4** | 安全（源头净化）+ 配额闭环，风险收益比高 |
| P2 | **G2** | 仅多步场景受影响，依赖 react 插件启用 |
| P3 | **G5** | 体验优化，非阻塞 |

建议顺序：**G1 → G3 → G4 → G2 → G5**，每阶段独立 PR + 守卫测试（沿用 `test_plugin_decoupling.py` 的"分层方向/inject 耦合/表归属"三向守卫）。

### 2.4 风险与守卫

- **回归风险**：G1 若重新接线 `pick_history`，须同步更新治理器单测（`test_context_governor.py` 已含其保留方法用例）；当前 `short_term.compactor` 已不调用它，无需联动。建议先在 facade 层做兼容包装。
- **配置覆盖风险**：`/api/settings` 写入 `data/agent_plugin_config.json` 覆盖层；新增可调键须同步登记 `_SETTING_SCHEMA`（类型+上下限钳制）与前端 `keys` 列表（chat.py:557），否则前端不可见 / 后端拒绝。
- **解耦纪律**：所有新调用必须经 `ctx.get(Services.CONTEXT)` 软依赖；不得让 `sys/chat.py` 或 `react` 反向 import 治理器实现。
- **守卫复用**：表归属守卫（`agent_messages`/`agent_session_summaries` 仅 owner 读写）已在解耦复核中固化，G1 摘要衔接不得破坏该归属。
