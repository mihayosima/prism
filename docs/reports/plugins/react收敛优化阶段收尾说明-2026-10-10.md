## 3. 已闭环（6 项，附证据）

### ① P0-2 规划纪律提示词（零生产代码）

### ② P1-1 无进展检测 + 启发式2 误伤修复

- 落点：`plugins/react/loop.py` —— `ReactConfig` 增 `no_progress_window=5` / `no_progress_repeat=3`（999=关）；新增 `_step_fp()` 步级指纹与 `_detect_no_progress()`；`plugins/react/__init__.py` 的 `apply` 补转发两个新键（★ 首版漏转发导致旋钮失效）。
- **误伤根因**：启发式2 把按「工具调用」累积的 `observed` 当「步」切片 ⇒ 单步内多个 `tool_search`（返回高度相似候选文本）即凑满阈值，实测 steps=1 就误报。
- **修法**：另建 `step_fps` 步级指纹（工具名+内容哈希，空步 `None`），按**连续** N 步判定；不动 `observed` 本体（`_closing_summary` 按调用级找最后失败，语义正确）。
- 证据：真机分段对比 —— 修复前 17:30–17:40 **3/10 run 误伤**；修复后 19:55–20:10 **0/1**。破坏实验：把调用点改回不传 `step_fps`，新增误伤用例立即 FAILED。

### ③ P2-1 TodoWrite 插件（`plugins/todo`，loop.py 零改动）

- 新增 `agent/plugins/todo/store.py`（会话分桶、整表替换、严格状态机自动归一、percent）与 `__init__.py`（注册 `todo.write` / `todo.list`，**均 `risk="read"`**，mutation 后 emit `Events.TODO_PROGRESS`）。
- 契约扩展：`core/services_catalog.py` 加 `Services.TODO`、`core/events_catalog.py` 加 `Events.TODO_PROGRESS`、`sys/progress.py` 映射 `"todo"` 帧驱动前端进度条。
- 设计要点：会话隔离照搬 approval 的 `current_session_key()` 分桶，**绝不碰 `ctx.state`**；标 `risk="read"` 是为了在 plan 权限模式下可见（安全由 `approval/policy.py:36` 硬拒兜底）。
- 证据：`test_todo` 4 用例 + 契约/相邻回归 91 全绿；本机 `data/agent_plugin_state.json` 的 enabled 已含 `plugins.todo`。

### ④ P0-3 委派判据写进工具描述

- 根因：`react/prompt.py` 的 `REACT_SYSTEM` 零委派字样，模型无从判断何时委派（对应 2.7% 触发率）。
- 落点选择：写进 `agent.delegate` 的 `description`（而非系统提示词或 system_memory）—— 只有工具真注册/可见时才出现，零装配风险。
- ★ 坑：`loop.py:219 _slim_description` **无条件**截首行 120 字符 ⇒ 三条判据必须压进首行；压缩后原始 277 字符、可见 79 字符，实测 `①②③` 完整。

### ⑤ P0-4 max_steps / deadline_s 进设置页（含保存失败修复）

- `agent/run/chat.py` `_SETTING_META` 登记 `max_steps(int 1~200)` / `deadline_s(float 5~3600)`，`scope="container"`；`web/src/views/settings.logic.ts` 新增「执行闸门」卡片并登记数值键。
- ★ 默认值口径：`profiles.BASE_AGENT_CONFIG` 的 react 节没有这两个键，真实默认在 `plugins/react/__init__.py:65`，登记时直接写 8 并注释锁定。
- **保存失败修复**：`core/config_schema.py` 的 permissions 节漏登 `allow`/`deny`（G7 引入）⇒ 非 `_any` 节严格校验导致整次保存 fail-fast。已补键，并加跨文件守卫 `test_every_setting_key_is_registered_in_schema`（遍历 `_SETTING_META` 核对 schema）+ 负例回归。
- ★ 坑：改前端后必须 `cd web && npx vite build`，服务托管的是 `web/dist` 产物（曾只验 `/api/settings` 就以为完事，用户看不到旋钮）。

### ⑥ 工具调用事件 durable 落库 + 入参脱敏

- 落点：`agent/sys/tasks.py::invoke` 的 `finally` —— **保留 `emit`**（护栏/审批 waterfall 与前端进度条依赖它）并追加 `durable`，pre-execute 也落库 ⇒ pre 与 post 的差额＝被拒数。
- 脱敏 `_redact_kwargs()`：敏感键（text/content/token/key/password…）留 `<redacted:str>`；长 str 截 200；复杂结构只记形状。
- 证据：真机 `tasks/post-execute` **0 → 4**、`pre-execute` 0 → 4；`request_id` 把 13 类事件串成一次请求；抽查 `{"mode":"read","path":"...","risk":"write"}` 保留可用。
- 副作用收获：实证了 F9 —— MCP 工具注册未传 risk，45/47 个工具落默认 `write`。
