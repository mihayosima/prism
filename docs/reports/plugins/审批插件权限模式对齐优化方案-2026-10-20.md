## 1. B1 —— 模式集命名与语义对齐 CC

### 1.1 现状与目标

**现状**（`policy.py:24,32-42`）：`default / plan / auto / bypass`，其中
- `default` = 只问 `ask` 名单内（默认空 ⇒ 不问）；
- `auto` = 写类/danger 都问。

**目标**：让**模式键名与其行为一致**，且与 CC 语义可对齐（消除 D-1 的"名字与行为对调"）。

### 1.2 模式集重命名（映射表）

| 旧键 | 行为（现状） | 新键（对齐 CC） | 新行为 |
| --- | --- | --- | --- |
| `auto` | 写类/danger 都问 | **`manual`** | 写类/danger 都问（= CC `default`/Manual） |
| `default` | 只问名单内 | **`permissive`**（或退役，见 DP-2） | 只问 `ask` 名单内（保留为显式宽松档） |
| — | — | **`acceptEdits`**（新增） | 只读 + **文件编辑放行**；danger 仍问（= CC `acceptEdits`） |
| `plan` | 只读 + 写类硬拒 | `plan`（不变） | 不变 |
| `bypass` | 不打扰 | `bypass`（不变） | 不变 |

> 新键名直接对齐 CC 的 `default`/`acceptEdits`/`plan`/`bypassPermissions`（本项目沿用短名 `manual`/`acceptEdits`/`plan`/`bypass`），**语义一一对应**。

**改点**：`agent/plugins/approval/policy.py:24`（`MODES`）、`:32-42`（`decide`）。

**具体改动**（`decide` 目标形态）：
```python
MODES = ("manual", "acceptEdits", "plan", "permissive", "bypass")

def decide(rules, tool, *, mode="manual", risk=""):
    if hit(rules.get("deny"), tool):                 return "deny"
    if mode == "plan" and risk != "read":            return "deny"   # plan 硬兜底（不变）
    if mode == "bypass":                             return "allow"  # 不打扰（guard 仍先裁）
    if mode == "manual" and risk in ("write", "danger"):  return "ask"
    if mode == "acceptEdits" and risk == "danger":        return "ask"   # 编辑放行、shell 仍问
    if hit(rules.get("ask"), tool):                  return "ask"
    if hit(rules.get("allow"), tool):                return "allow"
    return str(rules.get("default", "deny"))
```

### 1.3 新增 `acceptEdits` 的**前置依赖**（重要）

`acceptEdits` 依赖 `risk` 分级准确：**写类文件编辑 = `write`、shell/危险 = `danger`**。当前 **`plugins.windows_mcp` / `plugins.playwright_mcp` 注册工具时未传 `risk` ⇒ 默认 `write`**（`skills_mcp/__init__.py:204-206` 的注释已点出此 bug，但另两桥未修）。若 `acceptEdits` 按 `risk` 放行 `write`，**会把 `mcp.windows.PowerShell`（实为 danger）当编辑放行**。

**故 B1 含前置修复**：
- 改点：`agent/plugins/windows_mcp/__init__.py`、`agent/plugins/playwright_mcp/__init__.py`（注册处补 `risk=`）；
- 危险工具名映射：`PowerShell/process/registry/…` → `danger`，`Click/Type/Screenshot/FileSystem 读` → 视语义定 `write`/`read`；
- 验证：`catalog()` 中 `mcp.windows.*` 的 risk 不再是清一色 `write`。

### 1.4 plan 批准后的去向（D-7）

**改点**：`agent/plugins/approval/__init__.py:335`（`_submit_plan` 内 `set_mode(ctx, "auto", ...)`）。
**改动**：`set_mode(ctx, "manual", by="plan-approval")` —— 批准计划后回到"写类仍问"的常规档（对齐 CC"退出 plan 回 Manual"），而非名字误导的 `auto`。
**验证**：`test_submit_plan_approve_switch*` 断言目标档位由 `auto` 改 `manual`。

### 1.5 起始档与内核默认值

**改点**：`agent/core/permissions.py:26`（`current_permission_mode(ctx, default="default")`）。
**改动**：默认值 `"default"` → `"manual"`（配合 B2，见 §2）。
**验证**：未设档位时 `mode()` 返回 `manual`。

### 1.6 影响面（改名触及处）

| 文件 | 改动 |
| --- | --- |
| `agent/plugins/approval/policy.py:24,32-42` | 模式键与判定 |
| `agent/plugins/approval/__init__.py`（`set_mode` 校验 `:255`、`_sync_submit_plan` `:278`、`_submit_plan` `:335`） | 模式键引用 |
| `agent/core/permissions.py:26` | 内核默认档 |
| `web/src/views/PermsView.vue`（`data-mode`、`bypass` 二次确认） | 档位标签与确认 |
| `agent/tests/test_approval.py`、`test_permission_mode_scope.py`、`test_guard_scope.py` | 用例中的模式键 |
| `docs/plugins/approval/审批插件-设计方案.md` | 档位定义表（§3）同步（文档跟随） |

> **模式不持久化**（设计稿 §7：`ctx.state` 不落盘、重启回起始档）⇒ **无数据迁移负担**，改名只动代码/前端/测试。

**风险/代价**：中。主要是前端标签与既有测试的模式键需同步；无持久化 ⇒ 无历史数据兼容问题。

## 2. B2 —— 默认姿态：起始档改为"写类都问"（D-2）

| | |
| --- | --- |
| **目标** | 会话起始档 = `manual`（写类/danger 都问），对齐 CC Manual 的"先问"姿态 |
| **改点** | `agent/core/permissions.py:26`（默认值）；`agent/profiles.py:70`（`permissions.default`）；`agent/plugins/approval/__init__.py:41-48`（`allow=["*"]`） |
| **现状** | 起始档 `default`（只问名单内、默认空）+ `allow=["*"]` ⇒ **开箱什么都不问** |

**具体改动**：
1. 起始档改 `manual`（§1.5）；
2. `approval.allow` 由 `["*"]` 收紧为**只读白名单**或空（读类由 `risk=="read"` 走 `manual` 的"不问"分支自动放行，无需 `["*"]`）；
3. `guard.permissions.default` 是否同步收紧 —— **与《安全与质量优化方案-2026-10-20》O-3 是同一决策点**，两处择一执行，勿重复。

**验证**：新会话起始档 `manual`；`mcp.windows.PowerShell`（danger）起始即问；只读工具不问。
**风险/代价**：中 —— **改变本地默认体验**（见 DP-4）。若用户更看重"本地零打扰"，则本批只做 §1（改名不改默认），B2 延后。

## 3. B3 —— "总是允许"持久化 + 粒度到参数摘要（D-5）

| | |
| --- | --- |
| **目标** | "不再问"能跨会话记住，且粒度到"工具 + 参数摘要"（对齐 CC 的"仓库+命令"） |
| **改点** | `agent/plugins/approval/__init__.py:99`（`_session_allow/deny` 内存桶）、`:197-199`（`_remember`）、`:165-176`（命中判定） |
| **现状** | 只记**工具名**、仅**会话内内存**（重启即清） |

**具体改动**：
1. 记忆键从 `task` 扩为 `task + "|" + args_digest`（复用 `sys/tasks.py` 的 `_redact_kwargs` 摘要，避免把凭据落盘）；
2. 落盘位置：`data/approval_rules.json`（与 `agent_plugin_state.json` 同域），结构 `{session|repo 作用域: [rule, ...]}`；
3. 作用域二选一：**会话级**（默认，最保守）或**容器级**（对齐 CC 的"仓库级"持久化）；
4. 提供清除入口（插件页 status + 一个 `POST /api/approval/forget`）。

**验证**：放行一次 `Bash` 特定命令 → 重启 → 同类不再问；异参仍问。
**风险/代价**：低-中。落盘需脱敏；`bypass`/模式不落盘（既有铁律不变）。

## 7. 与其它方案的关系 / 不纳入

- **与《安全与质量优化方案-2026-10-20》**：B2 与其中 **O-3**（guard 默认策略）是**同一决策点**——两文档任选一处执行，避免重复改默认值。本文档只负责**模式语义**一侧。
