## 二、已落地能力清单（供后续直接引用）

### 2.1 对外契约：`agent.delegate`

参数（全部可选，缺省即串行同步委派）：

| 参数 | 类型 | 默认 | 语义 |
|---|---|---|---|
| `task` | str | `""` | 单个子任务（与 `tasks` 二选一，皆空 ⇒ 结构化报错） |
| `tasks` | array | `[]` | 批量子任务 ⇒ 并行 fan-out（`MAX_SUBAGENT_BATCH=16`） |
| `role` | str | `"default"` | 角色名（内置 `default`/`explorer`/`worker` + `<data_dir>/agent_roles/*.json`） |
| `tools` | array | `[]` | 在角色白名单基础上**再收窄**（交集，只能更窄） |
| `wait` | bool | `true` | `false` ⇒ 立即返回 `{status:"pending", handle}` |
| `handle` | str | `""` | 取回句柄；`"*"`/`"all"` ⇒ 一次 join 本轮全部在飞句柄 |
| `wait_timeout_s` | float | `0` | 等待上限，`0` = 用子时限；**超时不取消在跑的子**（`shield`） |

返回：`{status, answer, evidence, request_id}`；并行形态另带 `{count, succeeded, failed, results, request_ids}`；
异步形态另带 `{handle, pending}`。超限不抛异常，返回 `status="rejected"` + `evidence.reason`。

### 2.2 护栏常量（`agent/plugins/subagent/runner.py`）

```
SUBAGENT_MAX_STEPS      = 6      # 子循环步数上限（父为 8）
SUBAGENT_DEADLINE_S     = 60.0   # 子循环整体时延上限
MAX_SUBAGENT_THREADS    = 4      # 每父 run 在飞子上限
MAX_SUBAGENT_BATCH      = 16     # 单次调用委派数上限
MAX_DELEGATIONS_PER_RUN = 24     # 同父 run 委派总数上限
MAX_RESEND_PER_TASK     = 3      # 同一任务文本（sha1 指纹）重派上限
MAX_PENDING_PER_RUN     = 8      # 未回收异步句柄上限
MAX_TRACKED_RUNS        = 256    # 记账字典按插入序淘汰（父 run 无"结束"事件）
MAX_SUBAGENT_DEPTH      = 1      # 子永远是叶子，禁止再委派
```

## 五、恢复工作手册

### 5.1 让 `agent.delegate` 真正生效（★ 最易踩的坑）

**目录插件是 opt-in**：`PluginManager.load()` 只加载 `data/agent_plugin_state.json` 的 `enabled` 列表。
该文件 gitignored、每台机器独立 ⇒ **换机器必须手动把 `plugins.subagent` 加进 enabled 列表**，
否则代码在真服务里不生效（单元测试用 `extra_plugins=` 注入会掩盖这个缺口）。

复验方式（真服务，非 TestClient）：

```bash
python -m agent.run.chat --port 8727
curl -s --noproxy '*' http://127.0.0.1:8727/api/tools   # 看 agent.delegate 是否在列
```

### 5.2 跑测试（本机纪律）

```bash
CODEBUDDY_SAFE_DELETE_SANDBOX=0 \
  "<用户主目录>/.workbuddy/binaries/python/envs/default/Scripts/python.exe" \
  -m pytest agent/tests/test_subagent_async.py -q --basetemp=<用户主目录>/AppData/Local/Temp/pbt_x
```

- `--basetemp` 必须写 Windows 路径 `C:/...`，且置于工作区外；**不要预删 basetemp**（删除守卫会让 pytest 清理阶段失败）。
- 每批 4 文件、各自独立 basetemp；不要一次跑全量（会 MemoryError）。

### 5.3 离线端到端

`agent/fixtures/llm.py`（`provider="fixture"` 为默认）零触网，可跑真 ReactLoop 端到端。
**断言必须穿过真实读取点并断言任务文本真回显**，弱断言（如只查 `"fixture" in answer`）会造成恒绿假象。

## 六、遗留风险（暂缓期间保持认知）

1. **未推送**：5 笔提交仅在本地 `main`，机器故障会丢。
2. **插件 opt-in**：新环境需手动启用（§5.1），否则功能静默缺席。
3. **后台子生命周期依赖 teardown**：异步子登记在 `_BG_TASKS`，靠 `ctx.effect(_dispose)` 在 teardown 时
   `cancel_all()`。任何绕过正常 teardown 的关停路径都会留下孤儿任务。
4. **异步取回语义是 await 而非注入**：设计稿原拟"完成时注入下一轮 tool_result"，需 react 侧新增
   「外部消息注入」接缝（阶段 0 五参数里没有），本阶段未改共享 Actor。若未来要真注入，接缝加在
   `ReactLoop`，调用点零改动。
5. **记账内存兜底靠淘汰**：父 run 无"结束"事件可挂清理，靠 `MAX_TRACKED_RUNS=256` 插入序淘汰。
