## 1. P0 —— 安全堵漏

### P0-1　修复 `/api/plugins/remove` 路径穿越（最高优先）

| | |
| --- | --- |
| **目标** | 任何 `id` 都不得删除「插件目录以外」的任何路径 |
| **改点** | `agent/sys/plugin_manager.py:149-173`（`remove` / `package`）、`agent/run/chat.py:1403-1407` |
| **现状** | `package()` 对未发现的 id **原样返回**；`self._dir / pkg` 遇绝对路径被 pathlib 丢弃左段，`rmtree` 直删（实测可删 `C:\Windows`；`id="../.."` 使 `pkg` 变空串 → 删整个 `agent/plugins`） |

**具体改动**：新增 `_safe_target()`，`remove` 改用它。

```python
def _safe_target(self, name_or_id: str) -> Path:
    """id/包名 → 已校验的、必然位于插件目录内的目标路径。非法即 raise。"""
    pkg = self.package(name_or_id)
    if not pkg or not pkg.isidentifier():          # 拒绝空/含分隔符/含 . 或 / 或 \
        raise ValueError(f"非法插件标识：{name_or_id!r}")
    root = self._dir.resolve()
    target = (self._dir / pkg).resolve()
    if target.parent != root:                       # 拒绝对齐到别处
        raise ValueError(f"目标越界：{target}")
    return target

def remove(self, name_or_id: str) -> dict:
    try:
        target = self._safe_target(name_or_id)
    except ValueError as exc:
        return {"removed": False, "package": "", "error": str(exc)}
    self.set_enabled(name_or_id, enable=False)
    ...                                             # 状态照旧
    removed_ok = target.is_dir()
    if removed_ok:
        shutil.rmtree(target, ignore_errors=True)
    return {"removed": removed_ok, "package": target.name}
```

**验证**：新增单测，`id ∈ {"C:\\Windows", "/etc", "../..", "../../", "a/b", "..", ".", ""}` 一律拒绝且**不触盘**；合法 id（`react`）仍能删。
**风险/代价**：极低。`scaffold()`（`:130-147`）已用 `isidentifier()`，本修复与之口径一致。

| | |

**具体改动**（与既有 fail-fast 同址、同风格）：
```python
_LOOPBACK = {"127.0.0.1", "localhost", "::1"}
if args.host not in _LOOPBACK and not str(args.token or ""):
```

### P1-2　guard / 审批默认策略：`open` → `ask`（对 write/danger）

| | |
| --- | --- |
| **目标** | 把「默认开放」降级为「写类操作默认询问」 |
| **改点** | `agent/profiles.py:70`、`agent/sys/guard.py:34-41` |

**具体改动（建议做法）**：不动 `default`（避免全量回归），只改 **risk 矩阵**默认：

**验证**：默认下 `mcp.skills.skill_bash`（danger）被拒、`skill_file_create`（write）转 ask、读类放行；更新 guard 真值表用例。
**风险/代价**：中 —— **改变本地使用体验**（详见 O-3）。是否改、改哪些级别由你定。

## 6. 未纳入本方案 / 已知局限

- **`skills_mcp` 启用后的"完全权限"本质**：本方案只改**默认值**；一旦显式开启，`skill_bash` 仍是宿主全权限（这是该工具的定位）。真正的边界靠 **guard + 审批 + 沙箱 tier** 三层，非本文档可单独解决。
- **多用户隔离**：单全局 token 模型下无用户级鉴权（O-4）。本方案不引入 per-user token。
- **审计报告 §7 的「未亲验项」**（budget 竞态、SQL/SSRF 全局性、前端 XSS）**需先复核**再决定是否入方案 —— 见 附-2。
