## 1. 结论速览

| 维度 | 评价 | 一句话 |
| --- | --- | --- |
| **架构 / 解耦** | ★★★★★ | `agent/core` 零反向依赖、插件间零横向 import，由 AST 静态守卫强制。**实测坐实**。 |
| **安全** | ★★☆ | 无「裸装即被攻陷」的 Critical；真正的 Critical 是 `/api/plugins/remove` 路径穿越（**不需任何插件启用**）。其余多为「opt-in 后默认值不安全」。 |
| **功能完整度** | ★★★ | 通用 harness 骨架成型；相对 Claude Code / OpenHands / Aider 缺并行工具、token 级流式、默认沙箱、编辑回滚、MCP 远程传输。 |

**最高优先级一条**：`POST /api/plugins/remove` 的 `id` 未做任何清洗即拼进 `Path(插件目录) / id`，在 Windows 下 pathlib 会**丢弃左段**，`shutil.rmtree` 直删任意绝对路径目录（已实测）。此路由**不依赖任何插件启用**，无鉴权默认形态下匿名可达。

## 3. 漏洞清单

### 🔴 C-1　`/api/plugins/remove` 任意目录删除（Critical）【实测】

| 项 | 内容 |
| --- | --- |
| 位置 | `agent/run/chat.py:1403-1407` → `agent/sys/plugin_manager.py:149-173` |
| 触发 | `POST /api/plugins/remove`，`body = {"id": "<任意字符串>"}` |
| 需要鉴权？ | **否**（无 token 默认形态匿名可达；有 token 时任意持 token 者可达） |
| 依赖插件启用？ | **否** |

**代码链：**

```python
# chat.py:1404-1405
async def _plugin_remove(body: dict):
    info = pm.remove(str(body.get("id") or ""))
```
```python
# plugin_manager.py:149-173
def remove(self, name_or_id: str) -> dict:
    pkg = self.package(name_or_id)
    ...
    target = self._dir / pkg            # self._dir = agent/plugins
    if target.is_dir():
        shutil.rmtree(target, ignore_errors=True)   # :161
def package(self, name_or_id: str) -> str:
    ...                                  # 命中 discovered 才返回其 package
    return name_or_id.rsplit(".", 1)[-1] if "." in name_or_id else name_or_id  # :173
```

`package()` 对**未发现**的 id **不做任何清洗**。对照：同文件 `scaffold()`（`:130-147`）正确校验了 `name.isidentifier()`——**唯独 `remove` 漏了**。

**实测（Windows，本机复现 pathlib 行为）：**

| `id` | 实际 `base / pkg` | `resolve()` | 后果 |
| --- | --- | --- | --- |
| `C:\Windows` | `C:\Windows` | `C:\Windows` | pathlib 丢弃 `agent/plugins` → `rmtree` 直删 `C:\Windows` |
| `../..` | `agent\plugins`（`rsplit` 后 `pkg` 为空串） | `...\agent\agent\plugins` | 删掉整个插件目录 |

**修复（改动极小）：** `package()` 或 `remove()` 入口增校验——拒绝绝对路径、`..`、非 `isidentifier`；并强制 `target.resolve().is_relative_to(self._dir.resolve())`。

## 4. 解耦性复核

**结论不变：这是项目最强项，且非「文档宣称」而是「守卫强制」。**

### 4.1 实测证据（grep）

```
agent/core/   →  0 处 import agent.plugins / agent.sys
agent/sys/    →  0 处 import agent.plugins
agent/plugins/→  0 处 import agent.core / agent.sys （直连）
```

分层由 `agent/tests/test_plugin_decoupling.py:108-146` 用 AST 强制：禁 `core→sys/plugins` 反向、禁 `plugins→plugins` 横向、禁绕过 `api` 直连 `core`、禁 `sys→core`（仅留一个兼容 shim）。

### 4.2 结构要点

- **单一出口**：`agent/api.py:1-5` 定义边界；`core/` 只经此对外。
- **装配引擎与插件无关**：`core/container.py`（Kahn 拓扑 + 对称 teardown）只认 `Services.*` 键与 `Events.*` 名。
- **能力接缝**：`provide`(D-3 唯一)/`get`(软)/`has`/`on`/`effect`(可逆)/`tasks.invoke`（唯一工具执行通道，guard/budget/schema 全在此汇聚）。
- **契约即 Protocol**：`LlmProvider`（`core/contract.py:11`）、`ReactResultLike`（`:37`）；`chat` 委托 react **不 import react 类型**。

### 4.3 名字级紧耦合（**刻意且有注释**，非隐藏债）

| 紧耦合点 | 位置 | 说明 |
| --- | --- | --- |
| `_SCHEMA` 硬编码插件配置节名 | `core/config_schema.py:82-124` | 插件节必须登记，否则用户配置装配期 `ConfigError` |
| `Services` 目录含插件键名 | `core/services_catalog.py:28-55` | 新键不加进 `ALL` 则 `test_services_contract` 失败 |
| `EVENT_MODE`/`SEAM_SUBSCRIBERS` | `core/events_catalog.py` | 新事件须同时登记枚举与模式 |
| `ctx.state` 共享键 | `core/state_keys.py` | budget 写、react 读——「看不见的共享可变介质」 |

### 4.4 软肋（代码自陈，非发现）

1. **`inject` 只用于排序，无运行期校验**（`container.py:7-9` 自陈）——「读什么就声明什么」是纪律，靠静态测试兜。
2. **`plugin_manager` 双命名空间**（`:10-16`）：目录插件加载为 `agent_plugins.<pkg>` ⇒ `isinstance(x, agent.plugins.xxx.Cls)` **永远 False**，类型判断退化为 `type(x).__name__`。
3. **`chat.py` → 各插件靠「签名降级梯」**（`sys/chat.py:544-557` 逐层 `TypeError` 重试）——解耦足，但**脆弱**：插件改签名靠运行期试错而非静态约束。
4. 反例（代码自承已修）：`sandbox/__init__.py:341` 曾有 `NameError` 被吞 ⇒ 隔离**静默失效**。

- 插件生命周期（desired/actual/delta + 页面启停卸）比多数 OSS harness 更系统；
- **运行时取消**在任意 `await` 点生效（含 120s MCP 等待），实现诚实；
- 分级沙箱**诚实上报**（`enforcement`/`backend`/`enforced_by`，fail-closed）；
- 上下文治理器（token 预算、原子单元裁剪、压缩 shadow 模式、不变量校验）成熟；
- **断点续传**（work_memory + 前缀对齐，`CONTEXT_PREFIX_UNSTABLE` 诚实上报）——**亮点，很少见**。

## 6. 建议优先级

**P0（先堵洞，改动小）**
1. `plugin_manager.remove()`/`package()` 增校验：拒绝绝对路径、`..`、非 `isidentifier`，并强制 `resolve().is_relative_to(self._dir)`。
2. `_identity()` 的 session 与 token 绑定（或对 `X-Session-Id` 加签），否则 token 模式下跨会话读写仍成立。
3. `/ready` 去掉 `str(exc)`（改回固定文案 + `request_id`）。
4. `/api/plugins/remove` 等**写路由**纳入鉴权（`OPTIONS` 与 `/metrics` 需单独的鉴权决策）。

**P1（默认值转向安全）**
5. `skills_mcp` 的 `allow_exec` 默认改 `False`（与 adapter 的 fail-closed 一致，`adapter.py:133-135` 已写「默认 fail-closed」，把桥反过来对齐）。
6. 默认 `permissions.default` 从 `open` 改为 `ask`（有审批插件）/`deny`（无），把「默认开放」降级为显式选择。
7. 工具输出进 prompt 前加**来源标记 + 注入过滤**（C9）——这是把 H-1/H-2 降级的关键。
8. 基础限流 + 上传/并发上限。

**P2（功能补齐，按需）**
9. 并行工具（需重构，见 §8.2）；10. token 级流式；11. git 提交 + 编辑回滚；12. MCP HTTP/SSE 传输。
