## 1. 目标与一句话结论

把「上下文窗口参数/层 cap」与「预算额度+累计」从**容器级（G1）**提升为**会话级（G2）**，使
每个会话可以有不同的窗口大小、不同的 token 上限、各自独立的用量累计与重置。

**结论：推荐路线 B（容器级会话分桶 + 会话感知门面），不引入每请求 child 容器。**
理由见 §4；核心原因是 `Context.state` **无父链回退**（child 的 state 是全新空字典），
一旦把请求跑在 child 上，容器级状态全部丢失/归零（2.2 期间 `Approval.mode()` 已踩过此坑）。

### 2.3 三处必须正视的既有缺陷（本方案顺带修掉）

1. **⚠️ 重置串账（P0）**：`CHAT_RESET` 是全局事件，任意会话点「清空会话」都会把
   **整个容器的 `BUDGET_SPENT` 清零** ⇒ 多会话下 A 清历史 = B 的预算凭空回满。
   这是 2.2 落地后**新暴露**的行为（此前只有一个会话，语义无差别）。
2. **累计共享**：`BUDGET_SPENT` 单值累加 ⇒ 会话 A 疯狂用 token 会把 B 提前顶到上限。
3. **账单无会话维度**：`agent_budget_log` 只能按 `run_id` 归组，无法回答「这个会话花了多少」。

### 2.4 相关但独立的两处（本方案一并给出接线，不在同批改语义）

- `plugins.short_term.compactor` 持有 `self._cfg`（`compactor.py:45-70`），
  `compact_trigger_tokens` 与 `summary_budget_*` **在构造期固化** ⇒ 需按会话查表（S4 接线）。
- `plugins/memory/__init__.py:374` **现读** `ctx.config` 的 `agent.memory` 节 ⇒ 需「会话配置视图」（S1）。

### 2.5 容器机制事实（决定路线可用性）

- `Context.child()` 存在（`core/context.py:229`），但**生产代码零使用**。
- `get()` 走父链；`provide()` 只做同作用域冲突检测 ⇒ 子作用域可遮蔽父。
- `State` **无父链回退**，child state 是全新空字典（2.2 已验证）。
- 请求链路：`sys/chat.send(ctx=c.root, ...)` —— 全程 **root**，没有请求级 child。
- 2.2 已有先例：`ctx.state[StateKeys.SESSION_KEY] = ident.session_key`（`sys/chat.py` send 开头），
  作为「无参数通道的尽力而为提示」，approval 的归属判定就靠它。

## 3. 语义边界：什么升 G2，什么留在 G1/G0

### 3.1 升到会话级（G2）

| 项 | 说明 |
|---|---|
| 窗口与配比 | `max_context_tokens`、`reserve_output_tokens`、`memory_ratio`、`history_ratio` |
| 层 cap | `resident_cap_tokens`、`on_demand_cap_tokens`、`prompt_cap_tokens` |
| 裁剪/循环口径 | `source_clip_tokens`、`clip_*`、`react_keep_recent`、`react_min_chain_tokens` |
| 水位与治理动词 | `working_window_tokens`、`window_{high,low}_ratio`、`compact_mode`、`clear_at_least_tokens` |
| 预算**额度** | `max_tokens_per_run`、`finalize_reserve_tokens`、`warning_ratio` |
| 预算**状态** | `BUDGET_SPENT`、`BUDGET_PENDING_EST`、`BUDGET_WARNING` |
| 压缩阈值 | `compact_trigger_tokens`（short_term，本就按 session 存储内容） |

### 3.2 明确**不迁**（迁了反而更差）

| 项 | 理由 |
|---|---|
| `LLM_COST_RATIO`（EWMA 校准） | 口径是模型属性，与会话无关；会话化会让每个会话样本数不足（<5 即退裸估算），**精度变差** |
| `cost_calibration` 总开关 | 校准机制属 G1 容器策略 |
| db 路径 / provider / model / token / hardened | G0 进程级，改要重启 |
| MCP 子进程、Redis 客户端、EventBus | 资源句柄，会话化 = 资源放大 |
| 插件启停（`_apply_rebuild`） | G1 装配单元 |

## 4. 机制选型（三条路线，推荐 B）

### 路线 A：每请求 child 容器

- 做法：`run/chat` 的 `_worker` 里 `async with ctx.scope()`，在 child 上 `provide(Services.CONTEXT, 会话governor)` + `provide("config", 会话配置)`，请求结束 teardown。
- 优点：**并发天然正确**（每个请求独享作用域），语义最干净。
- 缺点：① `State` 无父链 ⇒ 预算累计若写 child.state 会随请求结束蒸发，仍须回写 root 分桶；
  ② 审批模式等容器级状态会**归零**（已知事故形态）；③ 每个请求一次 child 创建/teardown 开销与 effect 执行；
  ④ 现有 8 处消费点虽零改动，但 `send(ctx)` 必须改传 child，链路改动面变大。
- 结论：**不 adopt 为主路线**；保留为「并发正确性」的后手增强（S4-b，可选）。

### 路线 B（推荐）：容器级会话分桶 + 会话感知门面

- 做法：
  1. **门面化**：`Services.CONTEXT` 提供 `GovernorRouter`（实现 `GovernorLike`，方法转发到「当前会话的实例」），
     `Services.BUDGET` 侧把额度/累计改成 `dict[session_key, ...]` 分桶；
  2. **会话键来源**：优先显式参数（2.2 的 `identity=` 线程化已铺好），无通道处用 `StateKeys.SESSION_KEY` 兜底；
  3. **存储**：配置覆盖落 `{version, container, sessions}`（S0），状态分桶落 root.state（跨请求持久）。
- 优点：**消费方零改动**；不动容器装配、不需 rebuild；与 2.2 的显式线程化一脉相承；每步可独立回滚。
- 缺点：**并发下 SESSION_KEY 单值可能被后写覆盖**（与 `REACT_RUN_ID` 同性质，budget 注释已自陈该风险）。
- 对策：① 显式 `identity=` 覆盖主链路（chat/react 全有）；② memory 等旁路调用带 caller 语义，
  短中期接受「尽力而归组」并写进文档；③ 若日后要求强一致，再叠加路线 A（child 提供强隔离）。

### 路线 C：会话级持久容器池

- 每会话一个 child 容器长期持有。缺点：MCP 子进程 ×N、内存 ×N、需 LRU 与 teardown 治理，
  且多会话 ≠ 多容器（2.2 已裁定）。**否**。

## 5. 实施步骤（S0–S7，每步独立可回滚）

### S0 配置存储 v1→v2（先做，否则会话覆盖无处安放）

- 现状：`data/agent_plugin_config.json` 形态 `{plugins.X: {...}}`，由 `_merge_cfg` 覆盖 `BASE_AGENT_CONFIG`。
- 新形态：`{version: 2, container: {plugins.X: {...}}, sessions: {sk: {plugins.X: {...}}}}`
- 迁移七条纪律（沿用既订）：
  1. 读时兼容 v1 平铺形态，**不写回**；
  2. 首次写 v2 前备份 `*.v1.bak`；
  3. 版本守卫（未知 version → 拒绝加载并回退默认）；
  4. 禁止「双写平铺副本」；
  5. scope 只收窄不猜测（会话覆盖缺失键 = 继承容器）；
  6. `sessions` 上限（建议 200）+ LRU 淘汰；
  7. 淘汰只删覆盖，**不动会话数据**（转写/记忆/快照不受影响）。

### S1 会话配置视图（单一真源）

- 新增解析：`default(G0) → container(G1) → session(G2)` 三级继承（G3 run 级本次不做）。
- 输出**不可变快照**给本轮使用（run 级冻结语义的前置），禁止运行期改。
- 同时给 `plugins.memory(__init__.py:374 现读 cfg)` 与 `short_term.compactor` 提供「按会话取值」的入口，
  避免这两处绕过门面直接读容器配置。

### S2 context 门面化（本批核心，低风险）

- `plugins/context/apply`：`provide(Services.CONTEXT, GovernorRouter(factory=ContextGovernor.from_config, cfg_view=...))`
- `GovernorRouter`：
  - 实现 `GovernorLike` 全部方法（`assemble / plan / execute / pick_history / input_budget / memory_budget /
    history_budget / source_clip_budget / clip_head_tail / declare / ...`）→ 转发到当前会话实例；
  - 实例按 `session_key` LRU 缓存（上限同 S0）；**参数快照型，重建成本 ≈ 一次 dataclass 构造**；
  - 无会话覆盖时**必须逐字节等价于现状**（默认走容器 cfg，实例与现在同一个 `from_config` 结果）。
- ★ 契约守卫：新增测试断言「Router 的方法集 == ContextGovernor 的方法集」（防协议漂移，见 §6 T3）。

### S3 budget 会话化（含修 P0 缺陷）

- 额度：`_limits[sk] = (max, reserve, ratio)`，缺省继承容器（S1 视图）。
- 状态：`BUDGET_SPENT / BUDGET_WARNING / BUDGET_PENDING_EST` 改 `dict[sk, ...]`；
  `pending` 现有「按 caller 分槽」保留，再加一层会话：`dict[sk, dict[caller, ...]]`。
- **P0 修复**：`CHAT_RESET` 处理器改为「只清 payload 里的会话」（事件已带 `session_id`，`sys/chat.py:491`），
  无 session 字段的历史调用方 → 退回清全局并记 warning（兼容不劣化）。
- 账单：`agent_budget_log` 幂等加 `session` 列（与 run_id 迁移同手法），使「本会话花了多少」可回答。
- 不迁：`LLM_COST_RATIO` 保持全局（§3.2）。

### S4 触发点接线

- 主链路：`sys/chat.send(identity=)`（2.2 已有）→ 透传给预算与门面；`react/loop.run(identity=)` 同理。
- 旁路（memory 的 LLM 调用、后台任务）：以 `StateKeys.SESSION_KEY` 兜底，并在代码注释里写明
  「并发多会话时以后写者为准」的已知边界（与 F2 run_id 同口径）。
- **S4-b（可选，择期）**：若要求强一致，再引入请求级 child 仅用于提供会话作用域，状态仍写 root 分桶。

### S5 设置页 scope（**先做表合并**）

- 现状四表靠注释维持同源：`_SETTING_SCHEMA`(117) / `_PLUGIN_OF_KEY`(158) / `_SETTING_DEFAULTS`(191) / `_CTX_DEFAULTS`(190)。
- **S5-0**：先合并为 `_SETTING_META`（三表现有表改派生视图），否则再加 scope 字段必漂移。
- **S5-1**：`POST /api/settings` 增加 `scope` 参数（`container` | `session`，缺省 container），
  会话级写入**不再触发 `_apply_rebuild()`**（下个请求自然生效，这也是「永不 rebuild」的收益）。
- **S5-2**：`GET /api/settings` 回显 `{container: {...}, session: {...}, effective: {...}}`。

### S6 前端

- `SettingsView.vue` / `settings.logic.ts`：scope 切换（容器 / 本会话）+ 会话级值标徽标 + 「重置为继承」。
- 状态栏：`/api/status` 的 budget 改为**本会话**（`spent` 取本会话累计、`max` 取本会话额度）。
- 「清空会话」按钮文案与行为对齐：只清本会话（转写 + 本会话预算）。

### S7 观测（默认关）

- `/metrics` 增加 `agent_budget_spent_by_session`（默认关闭，防标签基数爆炸；由 `agent.metrics.session_labels` 打开）。

## 7. 风险与对策

| 编号 | 风险 | 对策 |
|---|---|---|
| R1 | `SESSION_KEY` 单值在并发下被覆盖（门面选错会话） | 主链路显式 `identity=`；S4-b 提供 child 强隔离后手；文档写明边界 |
| R2 | 会话分桶内存增长 | sessions 上限 200 + LRU；状态分桶随覆盖淘汰一起回收 |
| R3 | `GovernorRouter` 协议漂移（governor 加方法而门面未跟） | T3 契约测试 + `GovernorLike` 单一真源 |
| R4 | 设置四表 + scope 五表漂移 | S5-0 先合并为 `_SETTING_META` |
| R5 | 语义变化波及快照/续接 | 本批不改快照键；`react_min_chain_tokens` 等变化只影响裁剪结果，不影响键契约 |
| R6 | 既有测试因「spent 变 dict」红灯 | 提供 `_spent_total()` 兼容视图给 `/metrics` 与状态栏；测试一并更新（先跑基线留证） |
| R7 | 会话级窗口过小导致循环内退化 | 沿用既有降级纪律：失败即降级 `keep`，不半途破坏结构（governor 已实现） |

## 8. 验收标准

1. 两个会话可设置**不同**的窗口大小与 token 上限，互不影响；
2. 清空会话 A **不再**清零会话 B 的预算（T6）；
3. 未配置任何会话覆盖时，行为与改造前**逐值等价**（T2）；
4. `pytest agent/tests` 与 `npm run check` 全绿（仅剩已知基线失败）；
5. 账单可按会话归因（T7）；
6. 设置页能区分「容器级 / 本会话级」并即时生效，不触发容器 rebuild。

## 9. 裁定结果（v1.1，按推荐定稿）

| # | 议题 | 裁定 |
|---|---|---|
| 1 | 范围 | **纳入 `compact_trigger_tokens`**（语义本就是会话级，随 short_term 走会话视图）；`summary_budget_*` 留 G1 |
| 2 | `finalize_reserve_tokens` / `warning_ratio` | **随 `max_tokens_per_run` 一并会话化**（否则「上限会话级、预留容器级」会出现自相矛盾的判定线） |
| 3 | S5-0 四表合并 | **同批做**（合并为 `_SETTING_META`，三张旧表改派生视图） |
| 4 | S4-b 请求级 child 强隔离 | **本批不做**，留作 R1 后手；本批按「显式 `identity=` + 尽力归组」上线 |
| 5 | sessions 上限 | **200**（LRU 淘汰，与配置作用域治理方案同值） |
| 6 | S7 per-session 指标 | **默认关闭**（`agent.metrics.session_labels` 打开） |

### 9.1 接缝与解耦纪律（v1.1 补充，实施硬约束）

插件**不得 import 适配层**（`agent.run.*`）。会话配置的传递一律经 **ctx 接缝**：

- 适配层在装配后注入 `ctx.provide("session.cfg_view", view)`，形态为
  `view(section: str, session_key: str | None) -> dict`（**纯读、返回不可变快照**）；
- 插件侧（context / budget / short_term）`ctx.get("session.cfg_view")` **软取**：
  不存在 ⇒ 退化为「容器配置单实例」，行为与改造前**逐值等价**（默认关闭会话作用域也照样工作）；
- 当前会话键：`ctx.state[StateKeys.SESSION_KEY]`（2.2 既有「尽力而为」通道），
  主链路另有显式 `identity=` 时不依赖它。

### 11.2 与计划的偏差（三处，均为实施期发现）

1. **门面转发用 `__getattr__` 而非逐方法显式定义**。
   - 收益：治理器新增方法时门面**自动跟随**，协议漂移风险归零（仍有 T3 守卫）。
   - 代价：`type(gov)` 由 `ContextGovernor` 变为 `GovernorRouter`；`isinstance`/`type(gov).x = ...`
     这类**按类型打桩**的写法失效。故两处测试按「门面是**有意**的接口变化」适配：
     `test_context_governor` 的类名断言改为门面名；`test_react_context` 的 patch 目标改为
     `type(gov.current())`（插件按文件路径加载为 `agent_plugins.*`，与 `import` 路径不是同一个类，
     故只能从实例取类）。
   - 备注：注入接缝**不套门面**（注入方自担语义），故 `test_governor_seam_injection` 不受影响。
2. **`ConfigStore` 惰性访问**（`_store()` 按 `_OVERRIDE_FILE` 路径变化重建）。
   原因：既有 3 处测试用 `monkeypatch.setattr(srv, "_OVERRIDE_FILE", tmp_path/...)` 重定向覆盖文件；
   若在 import 期把路径固化进单例，这些重定向会静默失效。接缝因此传 lambda 而非绑定方法。
3. **`BUDGET_WARNING` 形状兼容靠「是否含 `limit` 字段」判定**（旧单值记录与新分桶都是 dict，
   不能只按类型区分）。`budget._warn_map` 会把旧记录迁移到容器桶 `""`。
