## 0. 摘要（一屏读懂）

**一句话**：在 **两处**加域过滤——`_tools_for_step`（native tools 投影）与 `build_system`（系统提示目录）；**`tools` 变量保持全量**，供 `tool_search` / `tool_load` 检索。隐藏的域「对模型不可见、对检索可见」。

**改动量**：**后端 3 个文件（约 50 行）+ 前端 2 个文件（约 8 行）+ 1 个契约测试**；**2 个新配置键**（`tool_domains_enabled` / `tool_domains`，均入设置页）；**0 个新事件、0 个新状态键**。

**收益（实测全口径，隐藏 playwright 域）**：

| 计费位 | 现状 | 裁剪后 | 省 |
|---|---:|---:|---:|
| native tools | 3,190 | 1,677 | **1,513** |
| 系统提示目录块 | 1,488 | 763 | **725** |
| 新增「域清单」行 | 0 | ≈20 | −20 |
| **合计** | — | — | **≈2,218 tok/轮（占单轮 42.9%）** |

> 注意：《治理方案》§4.6 报的 **1,513 只是 native 一档**，见 §3.5 的更正。

**硬门禁**：§2 的 3 项实测未通过，**不得进入编码**。

**硬前提**：`lazy_tools=False` 时域裁剪**自动禁用**（非懒加载下无检索通道，裁剪 = 死锁），见 §3.2。

## 2. 前置门禁 G0（**未过不实施**）—— ✅ 已执行，结论与实测数据见下

三项均在《治理方案》§6.3 / §9-6 已列，此处给出**可执行化**的判定标准。

| # | 项 | 方法 | 通过判据 | 实测结论 |
|---|---|---|---|---|
| **G0-1** | 服务端前缀缓存切分粒度 | 项目已有 `agent_budget_log.cache_hit`；对比「改域前一轮 / 改域后一轮」的 `prompt_cache_hit_tokens` | 若 miss 骤增 ≈ 整个 `messages` 长度 ⇒ 缓存按**请求体整体**切分 ⇒ **域只允许在会话开始变更一次**；若仅小幅 ⇒ 改 tools 代价可忽略 | ✅ **通过（最有利结论）**：命中 4,736 → 2,048（miss 1,454），**保住的正是 system/messages 段**，损失的只有 tools 段 ⇒ 缓存按 token 前缀切分且 **tools 段位于 messages 之后** ⇒ 改域不伤 system/messages 前缀，且「域变更只在容器重建时点」对本方案天然成立 |
| **G0-2** | 懒加载自身的前缀代价 | 同一多步任务，`lazy_tools` 开/关各跑一次，逐 step 记录 `cache_hit` | 得出「每步 `loaded` 膨胀」的前缀代价基线 | ✅ **已量化（首次）**：`loaded` 每增长即改写 tools 段 ⇒ 该步 tools 段**整段 miss**（首见 2,933；同字节复现则 4,736/236）⇒ **懒加载每步的前缀代价 ≈ tools 段全长**；域裁剪不新增该类代价（只改 tools 段**内容**，不改变「该段每步变」这一既成事实） |
| **G0-3** | 选工具准确率基线 | 构造多步任务集（每任务给定正确工具名序列）；**关懒加载（47 全可见）vs 开懒加载（3 元工具 + 47 卡）**各跑一轮 | 得出准确率 A_off / A_on。若 A_on < A_off ⇒ **先补强 §4.4 可发现性再裁剪** | ⚠️ **条件通过**：A_off = **83.3%**（6 题，首步即中，avg_rounds 1.33）；A_on = **66.7%**（1 题因任务本身就是「先看页面再点」，两种模式同样失败；1 题因 `tool_search` 中英关键词不匹配而 6 次检索未命中）。**缺口来自「懒加载 + 朴素子串检索」这一既有机制，与域裁剪无关**（本实验未开域裁剪）⇒ 建议把「补强 `tool_search`（同义词/中英映射）」列为**后续增强**，不阻塞本方案 —— 域裁剪只会**减少干扰项**、且额外提供「域清单」，不劣于现状 |

## 3. 关键设计决定（含对《治理方案》的 3 处更正）

### 3.1 域过滤必须落在**两处**，而 `tools` 恒为全量

实测代码路径（`agent/plugins/react/loop.py`）：

| 变量 | 位置 | 现状 | 裁剪后 |
|---|---|---|---|
| `tools` | `run()` :316 | `visible_tools(ctx)` 全量 47 | **保持全量**（检索通道用） |
| `prompt_catalog` | `run()` :318 | `[_card(t) for t in tools]` | **改取放行域** `[_card(t) for t in tools_vis]` |
| `tools_step` | 循环内 :420 | `self._tools_for_step(tools, task)` | `self._tools_for_step(tools, task, allowed)` |

**为什么系统提示目录也必须裁**：若只裁 native tools 而保留系统提示名册，模型**仍看得见隐藏域的工具名与描述**（`render_tools` 会打印 `- {name}（{risk}）：{desc}`），「隐藏」在语义上不成立，且 §4.4 的「干扰项减少 ⇒ 检索命中率提高」收益全部落空。**只裁一处 = 没裁。**

**为什么 `tools` 必须保持全量**：`_partition_meta`（:1009-1014）用 `catalog = {t.get("name"): t for t in tools}` 供 `tool_load`，`_tool_search(c, tools)`（:1012）也取全量。`tools` 一变瘦，检索即失明 ⇒ 死锁（《治理方案》§3.2）。

### 3.2 硬前提：域裁剪**依赖懒加载**

`LAZY_META_TOOLS` 只在 `_tools_for_step` 里注入（懒加载路径）。`lazy_tools=False` 时 native tools 就是 `tools` 本身，**没有 `tool_search` / `tool_load` 可调** ⇒ 此时裁剪 = **硬隐藏 = 不可检索**，与「隐藏但可检索」目标矛盾。

**决定**：调用点写 `allowed = allowed_domains(ctx) if cfg.lazy_tools else None`。即：

- `lazy_tools=True` 且配置了 `tool_domains` ⇒ 生效；
- `lazy_tools=False` ⇒ **自动不裁剪**（配置了也只记一条启动日志，不生效），避免死锁。

### 3.3 【更正】状态粒度：`ctx.state` 实为**容器级**，不是「会话级」

《治理方案》§4.3/§4.3.1 把 `StateKeys.TOOL_DOMAINS` 描述为「会话级」。**实测不成立**：

- `agent/run/chat.py::_boot()` 只 `build_agent()` **一次**，全进程持有同一个容器（`_apply_rebuild()` 时整体替换）；
- `Context.state`（`agent/core/context.py:104,121`）是容器实例上的 `State()`，**所有请求共享**，无 per-request child scope（`ctx.scope()` 仅 `sys/progress.py` 用于事件监听）。

⇒ 写入 `ctx.state[StateKeys.TOOL_DOMAINS]` 的作用域是 **实例级（进程级）**，会**同时影响所有会话** —— 与「插件启停写共享文件」是同一类陷阱。

**决定（一期，2026-09-30 22:52 用户裁示「需要设置开关」）**：**配置驱动 + 入设置页**，语义定为「**实例级**」：

- 生效来源：配置 `agent.react.tool_domains_enabled`（总开关）+ `agent.react.tool_domains`（白名单）；
- 变更方式：设置页保存 → `POST /api/settings` → `_apply_rebuild()`（**保存即生效，无需重启**）；
- **入设置页**：按项目「三处同步登记」制度落地（`_SETTING_SCHEMA` / `_PLUGIN_OF_KEY` / `_SETTING_DEFAULTS` + 前端两文件 + 契约测试），详见 §4 C5 / C6；
- **不新增** `StateKeys.TOOL_DOMAINS`（零新增状态键）；函数内保留一个**前向契约**读取位，供将来真正有 per-session 通道时接入（写法同 `PERMISSION_MODE`「当前无写者」）。

> **影响**：《治理方案》§4.3.1 的推理（「策略稳定 / 工作集易失」）依然成立，但**粒度名称应为「实例级」**。§4.6.1 的往返成本结论**不受影响**（`task.loaded` 确为 run 级，跨轮仍需重新 load）。

### 3.4 【更正】《治理方案》§4.1 的「native 单独口径」列**数值错误**

该列原记 `playwright 2,124 / windows 2,419 / approval 174 / agent.tasks 48`，与本轮实测（同口径、同项目纯函数）**严重不符**，且与《治理方案》§4.6 自身（1,673 / 1,555）矛盾。**实测正确值**：

| 域（owner） | 工具数 | 仅放行该域时 native | 该域卡片和 | 系统提示目录块 |
|---|---:|---:|---:|---:|
| `plugins.playwright_mcp` | 25 | **1,677** | 1,488 | 763 |
| `plugins.windows_mcp` | 20 | **1,559** | 1,370 | 659 |
| `plugins.approval` | 1 | 305 | 117 | 77 |
| `agent.tasks` | 1 | 234 | 45 | 24 |
| **全量 47** | **47** | **3,190**（元工具 195 恒在） | 3,020 | 1,488 |

> **非加性说明**：4 张「卡片和」相加 = 3,020，+ 元工具 195 = 3,215 ≠ 3,190（差 25）。原因是 `estimate_request_cost` 对 JSON 数组的 `[`/`]`/逗号只计一次，**分域求和会重复计入包装**。**验收必须用「整体调用同一函数的前后差分（Δ）」，不得用分域求和。**

### 3.5 【更正】《治理方案》§4.6 的收益是 **native-only 下界**

§4.6 只计了 native tools 一档。因 §3.1 决定**同时裁系统提示目录**，全口径还应加上该域的目录块体积。隐藏 `playwright_mcp` 时：

```
native      3,190 − 1,677 = 1,513
系统目录块  1,488 −   763 =   725
域清单行                   −≈20
─────────────────────────────────
全口径                     ≈2,218 tok/轮（占单轮 42.9%）
```

**与「目录卡去重」项的关系**：§4.6 末的「目录卡去重」（≈1,400 tok/轮）是**去掉全部名册**；本方案的域裁剪只去掉**隐藏域**的名册。两者**部分重叠、不可简单相加**，合并决策时须一次核算。

### 3.6 默认值语义（**2026-09-30 22:52 更新为「开关 + 白名单」双键**）

| `tool_domains_enabled` | `tool_domains` | 行为 |
|---|---|---|
| `False`（默认） | 任意 | **不裁剪**，逐字节等价现状（灰度默认） |
| `True` | `[]` | **不裁剪**（白名单为空视为未配置，**不做「全隐藏」**，避免误关） |
| `True` | `["plugins.windows_mcp", ...]` | 只放行白名单内的域（+ 元工具 + 已加载工具） |

> **为什么拆成两个键而不是一个列表**：① 与项目既有 react 开关（`lazy_tools` / `alignment_enabled`）同构，契约测试与前端范式现成；② 提供**显式的一键回滚**（取消勾选即可），不必依赖「把文本框清空」这种隐含语义；③ 空文本框与「未配置」在 HTTP 表单里不可区分，双键可消除歧义。
>
> **为什么不做「全隐藏」**：UI 无法安全表达（空白名单必然被误读为「关闭」）。若确需全隐藏，可在调用点以 `allowed=set()` 直接表达（不经配置）。

### 3.7 新工具 / 新 MCP 插件是否自动遵循本机制？——**是，零额外工作**

**结论：以后新增 MCP 工具插件，会自动成为一个新「域」，无需为本方案做任何改动。**

机制在**注册期**就已完成，不依赖本方案：

```python
# agent/sys/tasks.py:134-143
def register(self, ctx, name, *, schema, handler, owner=None, description="", risk="write"):
    ...
    owner = owner if owner is not None else current_plugin()   # ← 未传则自动取「当前插件 id」
    self._tasks[name] = Task(name, schema, handler, owner=owner, ...)
```

两个 MCP 桥**显式**传了 `owner=self.name`（`plugins/playwright_mcp/__init__.py:103`、`plugins/windows_mcp/__init__.py:84`），未显式传的走 `current_plugin()` 兜底。⇒ **`owner` 天然等于插件 id，域 = 插件，一一对应。**

| 场景 | 需要做什么 |
|---|---|
| 新增一个 MCP 插件（如 `plugins.filesystem_mcp`） | **什么都不用做** —— 它的工具自动成为 `owner="plugins.<新名>"` 的一个域，自动出现在 `GET /api/tools` 的 owner 分组里，自动可被域白名单引用、可被 `clip_by_domain` 裁剪、自动出现在「域清单」里 |
| 新增一个内置注册点（如 `agent.tasks`） | 同上（`current_plugin()` 兜底） |
| **想让它默认隐藏** | 只需**不**把它的 owner 写进 `tool_domains` 白名单 —— 白名单是**放行制**，未列名即隐藏 |
| **想让它默认可见** | 加进白名单（或不开总开关 = 全部可见） |
| 某插件内部想再分更细的组 | 需要**显式** `group` 字段 —— **本期不做**（见 §8） |

**唯一需要注意的两个前提**：

1. **新插件的工具数会计入 native 开销**（每工具 ≈ 68 tok 卡片 + ≈32 tok 系统提示目录 ≈ **100 tok**），直到它被隐藏。这正是本方案要解决的问题，不是本方案引入的问题。
2. **`risk` 标注**要正确传（`register(..., risk="read")`），否则 plan 模式仍会被误裁（见 §8 风险表最后一行；属独立议题）。

> **推论**：域级治理是**一次性建成、长期受益**的基础设施——**这正是选路线 2 而非路线 1 的关键理由**（路线 1 每新增一个工具就要重新设计复合工具，见《治理方案》§5）。

### 3.8 【实施期新增】安全阀：白名单与任何已注册域都不相交 ⇒ **回退为不裁剪**

复核期发现的一处**方案缺口**：原设计只保证「**空白名单** = 不裁剪」，但**非空却拼错**的白名单（如把 `plugins.windows_mcp` 写成 `windows`）会命中 §3.6 表中未覆盖的第三态 —— **全隐藏**。

其后果与「空白名单」完全相反，而且**静默**：用户勾了开关、填了域名、保存成功、界面无任何提示，但一个 token 都没省下（反而每 run 多付 2 次检索往返）。

**处置**（`loop.py::_clip_with_fallback`，已实现）：白名单非空、`tools` 非空、且裁剪结果为空 ⇒ **回退为不裁剪**并 `logger.warning` 列出「白名单 vs 现有域」，把静默的性能谜题变成一条响亮的日志。

```python
def _clip_with_fallback(tools, allowed):
    if allowed is None:
        return None, tools, {}
    tools_vis, hidden = clip_by_domain(tools, allowed)
    if tools and not tools_vis:                      # ← 安全阀
        logger.warning("tool_domains 白名单 %s 未匹配任何已注册域（现有域：%s）⇒ 本轮不裁剪；…", …)
        return None, tools, {}
    return allowed, tools_vis, hidden
```

> 这**不放宽**「确需全隐藏」的能力：调用点仍可显式传 `allowed=set()` 绕过（§3.6 脚注）。
> 判据：§6 G-安全阀（已在 P5 端到端覆盖）。

### 3.9 【实施期新增】`tool_domains` 容忍**裸字符串**

`allowed_domains()` 原写 `{str(x) for x in doms}`。若有人**手写** `data/agent_plugin_config.json` 时把白名单写成字符串（`"tool_domains": "dom.alpha"`），Python 会**逐字符迭代** ⇒ 得到 `{"d","o","m",".","a","l","p","h"}` —— 静默失效且极难排查。

**处置**：`isinstance(doms, str)` ⇒ 包成单元素列表。由单测 `test_allowed_domains_config_branches` 固化。

> 经设置页保存的路径不受影响（`_coerce_setting("list", …)` 已把字符串按 `,`/`，`/`、` 切分）；此处防的是**手改配置文件**。

```python
def _domain_of(t: dict) -> str:
    """工具所属域 = 注册来源 owner（`sys/tasks.py` 注册时写入）。缺失归一为 ""。"""
    return str(t.get("owner") or "")


def clip_by_domain(tools: list[dict],
                   allowed: set[str] | None) -> tuple[list[dict], dict[str, int]]:
    """按域裁剪。

    ``allowed is None`` ⇒ 不裁剪，**原样返回**（默认态零行为变化）。
    否则返回 ``(放行工具, 被隐藏域计数)``；计数供提示层渲染「域清单」（《治理方案》§4.4）。
    """
    if allowed is None:
        return tools, {}
    kept: list[dict] = []
    hidden: dict[str, int] = {}
    for t in tools:
        d = _domain_of(t)
        if d in allowed:
            kept.append(t)
        else:
            hidden[d] = hidden.get(d, 0) + 1
    return kept, hidden


def allowed_domains(ctx) -> set[str] | None:
    """放行域集合（来源 = 配置 `agent.react`；返回 None 表示不裁剪）。

    ``tool_domains_enabled`` 为假、或白名单为空 ⇒ ``None``（不裁剪，等价现状）。
    前向契约：将来若有 per-session 通道，可在**此处**优先读
    ``ctx.state[StateKeys.TOOL_DOMAINS]``（注意 ctx.state 实为**容器级**，见本文件 §3.3）。
    """
    node = ((ctx.config or {}).get("agent") or {}).get("react") or {}
    if not node.get("tool_domains_enabled"):
        return None
    doms = node.get("tool_domains") or []
    return {str(x) for x in doms} or None      # 空白名单 ⇒ 不裁剪（不做「全隐藏」）
```

```python
def render_domains(hidden: dict[str, int] | None) -> str:
    """被隐藏域的「存在性线索」——《治理方案》§4.4 强制项（否则「隐藏」退化为「不可得」）。"""

    return "\n".join(lines)


def build_system(catalog: list[dict], system_memory: str = "",
                 hidden_domains: dict[str, int] | None = None) -> str:
    base = (system_memory + "\n\n" + REACT_SYSTEM) if system_memory else REACT_SYSTEM
    parts = [base, render_tools(catalog)]
    domains = render_domains(hidden_domains)
    if domains:
        parts.append(domains)          # 无隐藏域时**不插入** ⇒ 默认输出逐字节不变
```

### 10.6 【v1.3】白名单 UI：手填文本 → 可勾选（2026-09-30 23:55）

**动因（用户裁示）**：「白名单改为可选择，不要用填参数这种影响用户体验的设计。」

原设计把 `tool_domains` 做成**逗号分隔文本框**，有三个实际问题：① 域名是 `owner`（插件 id，如 `plugins.windows_mcp`），用户得记住拼写；② 拼错会触发 §3.8 安全阀而**静默回退为不裁剪**，表现为「勾了开关却毫无变化」；③ 提示文案里硬编码了「当前可用域：……」清单，新增/停用插件后**立即过期**。

**设计选择**：**复选框列表**（而非下拉多选）。理由：域数量少（当前 4 个）且需要多选，「一屏看全 + 逐项勾选」比折叠下拉更直接，也让「**一个都不勾 = 不裁剪**」这一语义一眼可见。

**后端**（`agent/run/chat.py`）

| 改动 | 说明 |
|---|---|
| 新增模块级纯函数 `_domain_options(tools, selected)` | 返回 `[{"name", "count", "available"}]`，供设置页渲染候选项。**模块级**而非嵌套，是为了可单测（`_settings()` 是 `build_app` 内的闭包，无法直接测） |
| `_settings()` 返回值新增 `domains` 字段 | `_domain_options(c.root.tasks.catalog(), values.get("tool_domains"))` |

**候选集 = 当前已注册域 ∪ 配置里已选但当前未注册的域（`available=False`）**。后半段是**必需**而非锦上添花：域随插件启用/停用而增减，若只渲染已注册域，则「配置里已勾选、但该插件当前停用」的域会因控件不存在而在保存时被**静默丢弃** —— 用户会看到自己的选择无声消失。这正是本方案反复强调的「静默失效」类缺陷，故在实现期直接堵掉。
