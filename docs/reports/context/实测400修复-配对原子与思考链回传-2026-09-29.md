## 故障一：role=tool 失去前置 tool_calls（9-28 22:15，step=7）

**现象**：`Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`，整轮中断。

**根因**：治理器 `_trim_messages` 预算不足时「从新到旧连续贪心」，丢弃切点不感知配对结构——切点落在工具调用条目（assistant + tool_calls）与其结果回灌（wire 层展开为 role=tool）之间时，回灌被保留而前置调用被丢弃；pinned 回灌先占额度可单独存活，同样拆对。react 降级路径 `_trim`（按条数裁剪）切点亦有同险。

**修复**（零业务语义，纯形状判据，过治理器纯度守卫）：
- `agent/plugins/context/governor.py`：新增 `_pair_units`——按 wire 形状把消息分组成配对原子单元（带 tool_calls 的条目开启单元；content 含 tool_results 的回灌并入；其余自成单元）。`_trim_messages` 改以**单元**为预算粒度：pinned 单元先占（连带成员）、余额从新到旧连续贪心、末位单元保底 `_clip_unit_hard`（整单元保留、只裁文本载荷、骨架先扣）。
- `agent/plugins/react/loop.py`：`_trim` 降级路径切点撞上回灌条目时回退至配对边界之外。

## 故障二：thinking 模式 reasoning_content 未回传（9-29 01:27，续接 step=1）

**现象**：`The reasoning_content in the thinking mode must be passed back to the API`，续接「继续」首步即炸。

**根因**：思考链在响应侧只做前端流式展示（LLM_THINKING），**采集—存档—回传三处全缺**：流式累积受 schema 门控吞帧、非流式不读取该字段、ReasonOutput/链条目/wire 层均不携带。续接重放存档链时，上轮输出过思考的 assistant 轮缺 reasoning_content，被 DeepSeek 思考模式校验拒绝（证据链：16 条链续接成功 → 产出 1 条思考轮 → 17 条链续接即炸）。

**修复**（采集 → 存档 → 回传全链路）：
- `agent/sys/llm.py`：非流式读取 `message.reasoning_content`；流式思考帧**无条件累积**（schema 门控仅限外发事件），结果在 tool_calls / 纯文本 / schema 三条返回路径均随行。
- `agent/plugins/react/components.py`：`ReasonOutput` 新增 `reasoning_content` 字段，`DefaultReasoner` 从结果透传。
- `agent/plugins/react/loop.py`：turn 落链时非空则携带 `reasoning_content`（随链存档，续接自动重放）。
- `agent/core/request_cost.py`：`wire_messages` 对 assistant 条目（含带与不带 tool_calls 两种形状）透传该字段；user 等其余角色不夹带。
