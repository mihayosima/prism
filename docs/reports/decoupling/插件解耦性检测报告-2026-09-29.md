**无插件间硬依赖。** 所有 `inject` 仅指向内核服务（内核服务集合来自 `SYS_PLUGINS` 的 provides：['budget', 'db', 'events', 'guard', 'llm', 'migrations', 'tasks']），符合 opt-in 语义——任一业务插件禁用都不会导致其它插件装配失败。

> 方法学说明：表中 `provides` 仅采集 `@plugin` 类的**静态声明**；部分插件在运行时经 `ctx.provide(...)` 动态注册能力，未体现在静态 `provides` 中，故本矩阵对运行时服务注册为**下界估计**。inject 红线判定以「声明值是否在 `SYS_PLUGINS` provides 或静态 `provides` 中」为准，结论不受此影响。

**inject 依赖图无环。**

## 8. 解耦性评级与建议

**整体评级：PASS（解耦性良好）**

依据：
1. 三条解耦红线 + SSOT 守卫在静态扫描与 pytest 守卫测试中均无违规；
2. 插件间零横向 import、零硬依赖、零表归属越界，依赖方向严格单向（插件 → api → core）；
3. 协作主要通过 `provides/inject` 内核服务与 `Events` 事件总线完成，符合松耦合设计。

建议关注（非阻断）：
- 第 6、7 节列出的 `StateKeys` 与 `Events` 共享面，若后续插件增多，应优先通过事件总线而非共享状态键协作，避免隐式耦合累积；
- `agent/sys/plugin_manager.py` 的双命名空间语义（`agent_plugins.*` vs `agent.plugins.*`）使 `isinstance` 跨插件类型判断失效，诊断代码需以 `type(x).__name__` 或 `@plugin` 元数据比较，属设计取舍而非耦合违规，但接入新插件时需注意。
