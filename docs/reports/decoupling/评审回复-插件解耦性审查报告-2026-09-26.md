### P3｜结构性接缝：目录插件双命名空间

**结论：接受，建议取"实修"而非"仅文档"。**

`PluginManager` 以 `agent_plugins.*` 文件路径加载目录插件（`_load_module`），与 `agent.plugins.*` 常规导入路径下的类**身份不同**——`isinstance` 失效，须用 `type(x).__name__` 比较。此坑已踩过两次，目前仅靠记忆规避，风险偏高。

**整改建议（推荐顺序）：**
- **首选 ②**：loader 在 `sys.modules` 同时登记 `agent.plugins.<名>` 别名，使两种路径解析到同一模块对象（需评估与重复加载防护的相互作用）。这是根治方案。
- **兜底 ①**：若 ② 风险过大，则在 `plugin_manager` 模块 docstring 与架构文档显式声明该语义，并把"用 `type(x).__name__` 比较"固化为一条 lint/守卫，避免再次踩坑。

## 三、对报告建议的修正与补充

### 3.1 修正：P1 修法 #4 描述有误

报告 P1 修法 #4 写「`/api/memory` 改经 `ctx.memory.stats()` / 新增只读接口取数据」。核对该端点实际代码（`run/chat.py:601-611`）：

- **`stats` 早已调用**：line 606 已是 `stats = await c.root.memory.stats(c.root)`，故"改经 stats()"是冗余描述，并非缺失项。
- **真正直连仅 `rows`**：line 607-610 的 `agent_memories` 查询返回展示用明细行，这是唯一的越界点。
- **memory 插件无"列表"接口**：`MemoryDriver` 公开方法为 `remember / add / recall / context / stats / prune / wipe`（`plugins/memory/__init__.py:246-339`），**没有"按时间列出最近 N 条"的只读方法**。

**正确修法**：在 `MemoryDriver` 新增只读方法（如 `recent(n=40)`），由 `/api/memory` 调用以取代直连 SQL；未启用插件时既有的 `enabled: False` 降级保留。**不应**把"改经 stats()"作为修法表述，以免误导实施。

### 3.2 补充：第二处幻影表 `agent_plugin_state`

`KERNEL_TABLES`（`test_plugin_decoupling.py:186`）当前为 `{"agent_events", "agent_runs", "agent_plugin_state"}`。其中：
- `agent_runs`：报告已点出，系早期领域版废弃表（代码已移除，`tables.py:69-78` 仅登记迁移名、无 DDL）。
- `agent_plugin_state`：**报告未点出，同样是幻影**——它是 `data/agent_plugin_state.json` 文件，从不以 DB 表存在，任何 SQL 都不会引用它。

两者均从 `KERNEL_TABLES` 移除（移除后零行为变化，因二者本就不会命中任何 SQL 匹配）。

### 3.3 补充：P2#1 登记的守卫匹配约束

若将 `agent_budget_log` 登记进 `TABLE_OWNER`，其 `owner` 值**必须等于守卫 `_layer()` 的输出**才能避免误报。守卫判定逻辑为 `if who == owner: continue`，而 `_layer("agent/sys/budget.py")` 返回 `"sys"`。因此：
- 若写 `owner="sys/budget"` → `who("sys") != "sys/budget"` → `sys/budget` 自身写该表也会被误判为违规；
- 正确做法：以 `owner="sys"` 登记（表属 sys 层内部审计脊柱，仅 `sys/budget` 触碰，与 `agent_events` 同类豁免口径一致），或将其纳入"sys 层只读豁免"集合。
