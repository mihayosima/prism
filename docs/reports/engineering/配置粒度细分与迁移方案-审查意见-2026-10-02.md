## 3. R1 到底是什么（重新表述）

方案与 G2 的 docstring 都把 R1 描述为「`SESSION_KEY` 单值并发下可能被后写覆盖」。核实后的��确表述是：

**所有会话级服务（`GovernorRouter`、`budget`、`approval`）都从同一个容器级共享槽读取当前会话键：**

```python
# agent/plugins/context/router.py:51-55
def _session_key(self) -> str:
    st = getattr(self._ctx, "state", None)
    return str((st or {}).get(StateKeys.SESSION_KEY) or "")

# agent/sys/budget.py:50（同款）
return str((getattr(ctx, "state", None) or {}).get(StateKeys.SESSION_KEY) or "")

# agent/sys/chat.py:198（写入点，写在**根 ctx**）
ctx.state[StateKeys.SESSION_KEY] = ident.session_key
# agent/plugins/react/loop.py:431（第二个写入点）
ctx.state[StateKeys.SESSION_KEY] = session_key

# agent/plugins/approval/__init__.py:209（第三个读取点）
return str(self._ctx.state.get(StateKeys.SESSION_KEY) or "default")
```

⇒ **分桶本身是安全的；不安全的是"选哪个桶"这一步走的是共享可变槽。** 并发请求交错时 A 可能读到 B 的会话键。

**这正是我今天复核报告里的风险 R1，也是旧报告里的 F-2、路线图里的 #9 —— 同一件事被独立识别了三次。**

## 4. R1 的解法：建议用 ContextVar，而不是方案原定的「请求级 child」

方案把强一致留给「请求级 child」。审查后我建议**换一条成本低得多、且不触碰架构的路线**。

### 4.1 两条路线的成本对照

| | 请求级 child（方案原路线） | **ContextVar（本审查建议）** |
| --- | --- | --- |
| 需要动的地方 | `run/chat.py` 请求主链路 + 插件声明 `session_scope:` 工厂 + **处置 `State` 无父链**（§7.3 三选一） | 1 个新原语 + **5 个读写点** |
| 会丢容器级状态吗 | **会**（`PERMISSION_MODE` 等，需显式补偿） | 不会（`ctx.state` 结构不变） |
| 插件是否要改 | 是（每个可会话化服务一行声明） | 否 |
| 隔离粒度 | 按作用域（child） | 按 asyncio task（一个 HTTP 请求 = 一个 task）**天然对齐** |
| 与既有测试 | 需处理 `c.root.state[SESSION_KEY] = ...` 的大量写法 | 读时"ContextVar 优先、缺失回退 state"⇒ **测试零改动** |
| 风险 | 高（改请求主链路 + State 语义） | 中低（局部替换） |

### 4.2 为什么 ContextVar 天然成立

`contextvars` 的语义就是「按 task 隔离」：每个 HTTP 请求在 asyncio 里是一个 task，`ContextVar.set()` 只影响本 task 及其子任务。

- 子任务（`asyncio.create_task`）默认**复制**当前 context ⇒ 后台任务也能读到正确的会话键；
- 不同请求互不可见 ⇒ **强隔离，而非"尽力而为"**。

### 4.3 兼容策略（保证现有 500 项测试零改动）

```python
# 读取：ContextVar 优先，缺失回退 ctx.state（保住现有测试与旧调用点）
def current_session_key(ctx) -> str:
    v = _SESSION_VAR.get("")
    if v:
        return str(v)
    return str((getattr(ctx, "state", None) or {}).get(StateKeys.SESSION_KEY) or "")

# 写入：请求入口 set（run/chat.py 解析 identity 之后），
#       同时保留写 ctx.state 以兼容既有断言/回退路径
_SESSION_VAR.set(ident.session_key)
```

新原语应放在 `agent/core/`（如 `core/session.py` 旁）并**经 `agent.api` 导出**（插件只准从 `agent.api` 导入，见分层守卫）。

### 4.4 验收口径（沿用方案的纪律）

- **跨会话并发测试**：两会话并发跑，断言各自拿到自己的 Governor 值与预算桶（这是 R1 的直接验收，也是路线图 #9 的本体）；
- **回归**：全量 500 项不新增失败；
- **回滚**：删除 ContextVar 读取分支即回到现状（"回退到 state"）。
