## 1. 项目全景（代码事实）

**形态**：一个"everything-is-a-plugin"的 slim Cordis 风格运行时，加一套通用 agent harness（ReAct 循环、长期/短期/工作记忆、上下文治理、人在环审批、MCP 工具桥），配 Vue3+TS+Vite 单端口前端。零外部引擎依赖，可离线自举。

**分层**（`agent/api.py:3` 明确"包边界即依赖边界"，`agent/tests/test_agent_purity.py` 守卫）：

| 层 | 位置 | 规模（源码 LOC，不含测试） |
| --- | --- | --- |
| 内核（唯一出口 `agent.api`） | `agent/core/*` | ~2.6k（container/context/events/session/tokens/mcp_client/…） |
| 系统层（恒定装配） | `agent/sys/*` | ~2.9k（chat/llm/tasks/guard/budget/storage/loop/progress/…） |
| 目录插件（可启停卸） | `agent/plugins/*` | ~7.5k（react/memory/context/short_term/work_memory/approval/sandbox/*_mcp） |
| 适配层 | `agent/run/*` | ~2.0k（HTTP 服务 + 配置存储） |
| 装配 / 表结构 | `agent/profiles.py`, `agent/tables.py` | ~0.3k |
| **源码合计** | | **≈16.6k LOC**（另有 ~59 个测试文件） |
| 前端 | `web/src/*` | 9 `.vue` + 17 `.ts` |

**装配模型**：`agent/profiles.py:98-99` 恒定装配 `SYS_PLUGINS = (Events, Tasks, Storage, Llm, Budget, Guard)` 与 `BUSINESS_PLUGINS = (Loop, Chat)`；记忆四层与 react/approval/sandbox/MCP 桥**全部**是 `agent/plugins/` 下的目录插件，经插件页启停（默认 opt-in，`data/agent_plugin_state.json` 缺失即全停）。

**双驱动**：`agent/sys/chat.py::ChatDriver.send` 是会话驱动；装配了 `plugins.react` 则**委托**给 ReAct 循环（`sys/chat.py:244-248`），否则回退单步"规划→执行→解说"。

**运行入口**：`python -m agent.run.chat`（默认 deepseek，127.0.0.1:8720），单端口同时托管 `web/dist`（`run/chat.py:1688-1707`）。

## 2. 值得保留的工程资产（对标生产级的强项）

这些是项目的**真正实力**，也在多数对标框架里是加分项：

1. **DI 容器**（`agent/core/container.py`）：`inject` 拓扑排序（Kahn）解析依赖，缺失给清单、环给路径（`_find_cycle`），服务键唯一（D-3）；`assemble` 失败**逐插件逆序回滚**、teardown 对称回收（`container.py:277-356`）。纪律清晰。

2. **事件总线双模式 + 契约 SSOT**（`agent/core/events.py`, `events_catalog.py`）：`emit`（广播遥测，fire-and-forget，带在途上限与丢弃计数）vs `waterfall`（能力闸门，"不调 `next()` 即否决"）。事件名集中单一真相源，`EVENT_MODE` 与 `REQUIRED_SUBSCRIBER_EVENTS` 在**导入期**自洽校验（`events_catalog.py:179-184`）。`required_seams` 保证安全闸门不会"静默打开"。

3. **三层隐式契约加固**（README §"隐式契约加固"）：事件名 SSOT + 配置 schema fail-fast（`core/config_schema.py:139`，未知键/类型不符装配期报错）+ 装配期接线校验（`core/event_wiring.py`）。把"改名/拼错→运行期静默失效"变成"启动即报错"，这是大多数项目缺的。

4. **贯穿全项目的"诚实性"纪律**（罕见的工程文化）：
   - 沙箱**如实自报** `enforcement="none"`（无进程级隔离就绝不说"正常"，`plugins/sandbox/__init__.py:216-251`）；
   - provider 未接入则 `CapabilityNotImplemented`（不虚标，`sys/llm.py:59-74`）；
   - 硬规则/预算拒绝一律如实上浮、不造假成功（`sys/chat.py:263-266`）；
   - 失败/截断/降级都发 `durable` 事件留证（`sys/llm.py:123-128` 的 `LLM_TRUNCATED`）。

5. **会话/租户隔离用 ContextVar 修掉容器级共享态竞态**（R1 改造）：`core/session.py:165-217` 用 ContextVar 按 asyncio task 隔离"当前会话/run"，`budget`/`approval`/`guard`/`goal` 的读取统一经此通道——修掉了"并发请求后写覆盖先写"这类最隐蔽的串数据缺陷。会话键净化（禁 `:` 与 Redis glob 通配）防前缀扫描越权（`session.py:46-49`）。

6. **Token/成本治理的"一把尺子"**（`core/request_cost.py`）：把 messages/tools 先按 **wire 形态**序列化再估算，根治"按工具名列表估算"的 26% 系统性低估；预算**按会话分桶**（`sys/budget.py:29-33`），EWMA 口径校准（`sys/budget.py:283-293`），账单落 `agent_budget_log`；治理器装配预算同源 ÷ 校准因子。

7. **上下文治理器极强**（`plugins/context/governor.py:1008-1213`）：注册制分块装配 + 刚性块优先 + 可裁块 water-filling 回吐 + messages 块"左开右闭"互斥（绝不双份注入）+ pinned 先占额度 + `reserve_tokens` 为后续块保底 + I-1/I-2/I-3/I-4 不变量断言 + 可回放 ledger。这是硬核实现。

8. **存储层做对了难做的几件事**（`agent/sys/storage.py`）：同步 sqlite 经 `asyncio.to_thread` 卸载 + asyncio 锁与 threading 锁双重保护；显式事务且**嵌套死锁 fail-fast**（`storage.py:132-164`）；迁移前**在线备份**（官方 backup API，WAL 一致性，`storage.py:168-188`）；原子迁移组 + 防脏武校验（`MigrationRegistry.apply`）。

9. **MCP 客户端**（`agent/core/mcp_client.py`）：独立进程组 + Windows `taskkill /T` / POSIX `killpg` **杀整棵进程树**（修掉 6 天孤儿进程）；`_wait_loop` 常驻等退出码使死亡可见；stdout/stderr 双消费防管道死锁；`enum/anyOf/default` **保真**转换（模型能看到 `mode` 的 8 个合法取值）。

10. **HTTP 层的生产化细节**（`agent/run/chat.py`）：SIGTERM/SIGINT 优雅退出并排空在途 run；`active_runs` + `_RUN_LOCK` 原子"查忙→登记"修 TOCTOU（`chat.py:663-686`）；取消校验会话归属（`chat.py:954-956`）；`/api/events` 按会话行级隔离（`chat.py:1083-1099`）；`/health` `/ready` `/metrics` 探针；全局异常兜底不裸泄 `str(exc)`（`chat.py:1593-1600`）。

11. **测试套件**：639 例全离线确定性（默认 fixture provider，`sys/llm.py:35`），含解耦守卫、纯度守卫（内核零业务词）、接线守卫、会话隔离、续传等**行为级**断言，而非冒烟。

## 5. 优化建议（按优先级排序，均可落地）

### 5.1 快赢（1 天级，收益/成本比最高）

1. **翻转安全默认**：镜像 `CMD` 与 compose 默认带上 `--hardened` 且 `--token` 从环境变量注入（`PRISM_TOKEN`，缺失即启动失败）；把 `--hardened` 的 deny-by-default 作为**生产镜像**默认。改点：`Dockerfile:78`、`docker-compose.yml:44-66`、新增 `PRISM_TOKEN` 解析（`run/chat.py:_parse`）。
2. **构建吃锁文件**：`Dockerfile` 改为 `COPY requirements.lock` 并 `pip install -r requirements.lock`（或 `pip install -r requirements.lock --no-deps` 后再 `-e .`）。同时基础镜像 digest-pin。
3. **Redis 加固**：compose 中改 `127.0.0.1:6379:6379`（或干脆不发布端口，仅内网服务名访问）+ `--requirepass` + `maxmemory`/`maxmemory-policy`。
4. **CI 补三项**：`ruff check`（已配置，零成本）、`pip-audit`（或 `bandit`）、`npm test`（vitest 已在 `package.json`）。加 `dependabot.yml`。
5. **修 C1 的 3 例红灯**：定位 `storage.py::to_thread` 改写后测试 `_settle()` 轮次不足——要么给 fire-and-forget 记账加可等待钩子，要么让测试 `await` 到确定性完成（而非 `sleep(0)`×N）。这是提交当前 WIP 前的必要条件。
6. **CSP 补到 HTML**：`web/index.html` 加 `<meta http-equiv="Content-Security-Policy">`，或在 `_SPAStaticFiles.get_response` 对 `text/html` 加 CSP 头（`default-src 'self'; script-src 'self'`）。改点：`run/chat.py:1691-1705`。

### 5.2 中期（1 周级）

7. **compose 生产画像**：加 `mem_limit`/`cpus`、`read_only: true`（`data` 用卷）、`security_opt: no-new-privileges`、`cap_drop: [ALL]`、prism 级 healthcheck、`logging` 上限（`max-size`/`max-file`）。
8. **token 落地方式**：SSE 改用"一次性换 session token"或 WebSocket（携带 Authorization 头），消除 `?token=` 进日志；`buildUrl` 仅对确实无法带头的场景保留 query 通道。
9. **work_memory 一致性**：`finish` 补 `SREM`（或给索引键设 TTL）；`checkpoint`/`update` 用管道/`WATCH` 或 Lua 原子化；**统一两后端类型**（`_enc` 对 int/bool 不序列化，或两后端都规范化）。
10. **react 幂等 bug（C2）与超时兜底（C3）**：`_trim` 返回浅拷贝，预算提示改为"每步重算的构造态"而非就地 append；`_act_with_budget` 对不支持 `timeout_s` 的 actor 至少包一层 `asyncio.wait_for`。
11. **MCP 默认收拢**：`child_env` 的剥离与 cwd 重定向改为**默认开启**（当前 opt-in），并在审计中如实记录；把"剥离宿主守卫"的风险写进威胁模型。
12. **记忆运维**：给 `prune` 加 `LIMIT`/分批 + 让 `recall` 候选同样走 `last_accessed_at` 索引（已有复合索引可用）；审批会话名单加容量上限 + TTL。
13. **覆盖率门禁**：CI 加 `--cov` 并设 `fail_under` 基线（如 80%），先把 `run/chat.py` 的请求路径纳入。

### 5.3 长期（架构级）

14. **水平扩展方案**：若要 >1 副本，需把 SQLite 账本/记忆迁到共享后端（Postgres），或明确"单写多读 + 外部队列"的边界；当前 storage 层已把 SQLite 封装为可换 provider（`sys/storage.py:4`），是好的起点。
15. **巨型文件拆分**：`run/chat.py`/`loop.py`/`governor.py` 按域拆模块（已有 `_register_*` 先例），降低单文件认知负荷。
16. **收敛 `except Exception` 面**：把"刻意降级"与"意外吞错"用不同异常类型/装饰器区分，让审计能一眼筛出真隐患。
17. **`conftest.py` 提取共享 fixture**；**文档与代码对齐**（README 测试数等）。
18. **显式化装配顺序契约**：把"guard 在 sandbox 之前"这类隐性依赖变为声明式优先级（而非依赖 `prepend` 的 `insert(0)` 反直觉语义）。

## 6. 结论

Prism 的**内核与系统层是这份评估里最超出预期的部分**：DI 拓扑、事件双模式、契约 SSOT、会话级 ContextVar 隔离、wire 同源 token 口径、water-filling 上下文治理、优雅退出与取消语义、MCP 进程树治理——这些是只有真正理解分布式与 agent 运行时难点的人才会做对的工程。项目对"诚实"的坚持（不谎报 `enforcement`、不造假成功、失败必留证）也是一条贯穿始终、值得保留的文化主线。

它与"生产级"的距离**不在内核，而在外部**：默认无鉴权的部署姿态、被忽略的锁文件、缺 lint/类型/安全扫描的 CI、无资源限制的 compose、以及若干无界增长与会话隔离的理论漏面。这些几乎都是**配置与门禁层面的改动**，而非架构重写——快赢批次足以把整体安全与运维评级从"本地工具"抬到"可上生产"。

在动这些之前，**先处理当前工作区的 3 例红灯**（`storage.py` 异步化 WIP）——把工作区收敛到全绿再谈加固，否则任何"绿灯"承诺都建立在一个尚未合入的重构之上。
