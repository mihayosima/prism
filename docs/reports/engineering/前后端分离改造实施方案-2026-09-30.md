### 1.4 SSE 契约（`/api/chat/stream`）

- 帧格式：`event: <name>\ndata: <json>\n\n`（`_sse()` 构造）；
- 帧来源三类：①`start`（含 `run_id`）；②内部事件**透传**（`frame["event"] + frame["payload"]`）；③`error`；
- 前端消费事件名（实测 `handleFrame`）：`progress`、`tool_call`、`final`、`approval`、`approval_done`、`ask_user`、`ask_user_done`、`cancelled`、`token`、`thinking`、`error`、`start` 等。

### 1.5 三个缺口

1. **无 CORS**：端点全部同源假设，前端独立端口必失败；
2. **无鉴权**：任何进程可访问全部 `/api/*`；
3. **契约未文档化**：SSE 事件名与 payload 字段仅存在于前端 `handleFrame` 的隐式约定中。

## 3. 后端改动详案

### 3.1 CORS 中间件（B3）

```python
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:5173", "http://localhost:5173"],  # 白名单，不用 "*"
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

- 白名单来源：前端 dev server 默认端口（Vite 5173）；
- 生产模式（`web/dist` 托管）同源，CORS 不参与；
- 新增启动参数 `--cors-origin`（可重复），便于换端口调试（缺省即上面两条）。

### 3.2 Token 鉴权（B3）

**生成与持久化**

**校验依赖**
```python

```

**挂载范围**

| 路径 | 是否校验 |
|---|---|
| `/`、`/assets/*`（静态资源） | ❌ 公开（页面可加载，数据受保护） |
| 全部 `/api/*` | ✅ 校验 |

**实现方式**：用 `app.middleware("http")` 或为 `/api/*` 统一挂依赖；**推荐中间件**——避免逐端点改动（20 个端点零侵入）。

**前端配合**
- 启动时读 `location.search` 的 `?token=` → 写入 `sessionStorage` → 后续请求自动带；
- `client.ts` 统一注入 `Authorization`；SSE 连接自动附 `?token=`；
- 401 响应 → 弹出 token 输入框（不清空会话、不白屏）。

### 3.3 静态托管（B4）


保留**单进程部署**能力（后端 + 构建产物），同时支持分离开发。

**③ 卡片载荷取错层（阻塞级，表现＝"人机交互卡片不弹出"）**

- 现象：发消息后若 Agent 请求审批/澄清，**卡片完全不出现**；控制台无报错。
- 根因：后端进度桥（`agent/sys/progress.py:_pusher`）把**所有**内核事件载荷统一包成
  `payload = { source: <内核事件名>, data: <业务对象> }`；而 `ChatView.handleFrame` 把**外层 `p`**
  直接传给了卡片内核：
  ```ts
  cards!.showApproval(p)          // ❌ 应为 p.data
  ```
  `showApproval(d)` 首行即 `if (!d.call_id) return` —— 外层无 `call_id` ⇒ **恒真、静默返回**。
- 为何测试没拦住：卡片内核的**防御性 return 吞掉了错误**（这是好设计，但掩盖了取层错误）；
  且此前 3 项自检都**没有用真实帧结构驱动过卡片**。
- 修法：在分发入口**统一解包一次**，全部分支共用：
  ```ts
  const d = (p?.data ?? {}) as Record<string, never>
  if (ev === sseFrameName('PROGRESS')) k.useSeg().addStep(d)
  else if (ev === sseFrameName('TOKEN')) k.useSeg().appendToken((d as any).text || '')
  else if (ev === sseFrameName('APPROVAL')) { k.sealSeg(); cards!.showApproval(d) }
  ```

**B4 期间的设计判断（三处"不这样做就会坏"）**

1. **路由顺序即优先级**：`StaticFiles(html=True)` 挂 `/` 会吞掉所有未匹配路径，必须**在 `/api/*` 之后**注册。顺序颠倒 ⇒ 后端 API 被 SPA 回退覆盖成 `index.html`（前端拿到 HTML 当 JSON 解析，全站静默失效）。
2. **鉴权范围必须随托管收窄**：B3 的"全路径校验"在纯 API 形态下正确，但引入静态托管后 `index.html` 引用的 `/assets/*.js` 由浏览器原生 `<script>` 发起、**无法注入 `Authorization` 头**。收窄为仅 `/api/*` 是托管形态下的必要条件，而非放宽安全边界（数据面仍 100% 受控）。
3. **HTML 不能缓存**：Vite 产物 `index.html` 内联的是**内容哈希文件名**。若 `index.html` 被浏览器缓存，重新构建后旧 hash 已删除 ⇒ 白屏且无报错。故仅 HTML 加 `no-store`。
