## 阶段 0 · 先决：把工作区收敛到全绿（S）

当前工作区含约 48 个未提交文件，实跑 **3 failed / 636 passed**。这 3 例是与 `agent/sys/storage.py`（工作区 +184/−28，异步化改写）同批的 WIP 引入，HEAD 上通过。**不做这一步，后续任何门禁都建在未合入的重构上。**

### 0.1 根因（已定位）

`LLM_POST_CALL` 的记账监听器 `budget._post` 是**异步 fire-and-forget**（`core/events.py:147`）。测试靠 `await asyncio.sleep(0)` × N（`test_session_scope.py:61-67`、`test_followup_topics.py:97-98`）等待它落地。`storage.py` 改 `asyncio.to_thread` 后，协程 `await` 一次真实线程往返，`sleep(0)` × N 只推进 N 次事件循环轮次、等不到线程回调 ⇒ `samples` 停在 1。

叠加第二个隐患：`budget` 的预借槽按 **`caller`** 分桶（`sys/budget.py:242`），同 `caller` 的并发/连续调用会互相覆盖 pending（测试注释亦承认："同一 caller 的 pending 槽会被下次覆盖"）。

### 0.2 具体改动

**A. 让 fire-and-forget 任务可等待** —— 新增 `EventBus.idle()`（`core/events.py`，`aclose()` 旁，非破坏性、不取消）：

```python
# core/events.py —— 新增（与 aclose 并列）
async def idle(self) -> None:
    """等待全部在途 fire-and-forget 任务自然结束（不取消）。
    供测试、优雅收尾与"记账落地后断言"用；不得替代 aclose（后者取消）。"""
    while self._tasks:
        await asyncio.gather(*list(self._tasks), return_exceptions=True)
```

测试侧把 `_settle` 由 `sleep(0)`×N 改为确定性等待（`test_session_scope.py:61`、`test_followup_topics.py` 两处内联循环）：

```python
async def _settle(ctx) -> None:
    await ctx.events.idle()     # 确定性；不再依赖事件循环轮次
```

**B. 根修 pre/post 关联**（消除 caller 覆盖竞态，属 P1 真 bug 的顺手收口）：

- `sys/llm.py:104` 的 pre-call payload 增加唯一 `call_id`：
  ```python
  import uuid
  call_id = uuid.uuid4().hex
  decision = await ctx.events.waterfall(
      Events.LLM_PRE_CALL,
      {"messages": messages, "schema": schema, "caller": caller,
       "tools": tools, "finalize": bool(finalize), "call_id": call_id}, ...)
  ```
- `sys/llm.py:141` 的 post-call payload 带上同一 `call_id`。
- `sys/budget.py:242` 预借槽键由 `caller` 改为 `(caller, call_id)`（或直接用 `call_id`）；`_post`（`:257`）与 `_call_failed`（`:300`）按 `payload["call_id"]` 弹出。

**验证**：`python -m pytest agent/tests/test_session_scope.py::test_t8_cost_calibration_stays_global agent/tests/test_followup_topics.py -q` 全绿；且不再依赖任何 `sleep`。

**风险**：payload 增字段属纯数据，兼容；`call_id` 缺省时（旧调用方直接构造 payload）回退按 `caller` 取，不劣化。

## 阶段 1 · 安全默认值（P0，S–M）

> 核心动作：**把"默认不安全"翻转为"默认安全"**。安全能力**都已具备**（`--hardened`、`hmac.compare_digest`、会话归属校验），只是默认关闭。

### 1.1 鉴权默认开启 + 密钥经环境注入

- `run/chat.py::_parse`（`:71-99`）末尾加环境回退：
  ```python
  if not args.token:
      args.token = os.environ.get("PRISM_TOKEN", "")
  if os.environ.get("PRISM_HARDENED", "").strip().lower() in ("1", "true", "on", "yes"):
      args.hardened = True
  ```
- `run/chat.py:1738-1741` 由"仅告警"改为 **fail-fast**：
  ```python
  if getattr(args, "hardened", False) and not _token:
      raise SystemExit("--hardened 必须同时提供 token（--token 或 PRISM_TOKEN）")
  ```
- `Dockerfile:78` 的默认 `CMD` 追加 `--hardened`，token 经 `-e PRISM_TOKEN` 注入：
  ```dockerfile
  CMD ["python", "-m", "agent.run.chat", "--host", "0.0.0.0", "--port", "8720", "--hardened"]
  ```
- `docker-compose.yml` 的 `environment` 加 `PRISM_TOKEN: ${PRISM_TOKEN:?PRISM_TOKEN required}`，并删掉 `:64-66` 的注释块（加固已进默认）。

**连带**：`ci.yml` 的 docker 冒烟（`:160`）需带 `-e PRISM_TOKEN=ci-smoke`；否则默认 CMD 会 fail-fast 退出。

**风险**：本地 `--fixture`/`--once` 无 token 仍照常（未走该分支）；`--token` 显式传参优先级最高。

### 1.2 去掉 `?token=` 查询串（S）

**关键事实**：前端**全程用 `fetch` + `Authorization: Bearer` 头**——包括 SSE（`web/src/api/sse.ts:99-104` 是 `fetch`，**全仓无 `EventSource`**）。故 query 里的 token 是历史遗留、且是唯一进代理/访问日志的泄露面。

- `web/src/api/client.ts:88-89`：删除 `u.searchParams.set('token', token)`（`buildUrl` 不再注入）；`getToken()`（`:41-56`）保留"一次性从 `?token=` 读入再抹除地址栏"的兼容通道即可。
- 后端 `run/chat.py:1644` 的 `?token=` 提取**保留**（CLI/curl/一次性引导仍可用），但前端不再产生它。

**验证**：抓包确认请求 URL 无 `token`，`Authorization` 头存在；SSE 流正常。

### 1.3 Redis 加固（S）

`docker-compose.yml:20-42`：

```yaml
  redis:
    image: redis:7-alpine@sha256:<pin>          # digest-pin，见 2.1
    command: ["redis-server", "--appendonly", "yes",
              "--requirepass", "${REDIS_PASSWORD:-}", "--maxmemory", "256mb",
              "--maxmemory-policy", "allkeys-lru"]
    ports:
      - "127.0.0.1:6379:6379"                    # 不再发布到 0.0.0.0
```
`prism.environment` 的 `PRISM_REDIS_URL` 改为带密码：`redis://:${REDIS_PASSWORD:-}@redis:6379/0`。

> 注：原注释（`:34-40`）解释为何用 `6379:6379`（Windows IPv6 优先解析）。绑 loopback 时**必须**同步把 URL 写 `127.0.0.1` 而非 `localhost`（该注释已给出解法，照抄即可）。

### 1.4 应用 HTML 的 CSP（S）

`run/chat.py` 的 `_SPAStaticFiles.get_response`（`:1700-1705`）：

```python
async def get_response(self, path, scope):
    resp = await super().get_response(path, scope)
    if resp.headers.get("content-type", "").startswith("text/html"):
        resp.headers["Cache-Control"] = "no-store"
        resp.headers.setdefault(
            "Content-Security-Policy",
            "default-src 'self'; script-src 'self'; img-src 'self' data:; "
            "style-src 'self' 'unsafe-inline'; connect-src 'self'; "
            "frame-ancestors 'none'; base-uri 'none'")
    return resp
```
`'unsafe-inline'` 仅留给 `style`（卡片 HTML 可能带内联样式），**script 不放开**——这是挡住 innerHTML-XSS 的关键一层。上线前用真实页面回归一轮（`web/tools/check-*.mjs` 里已有 DOM 断言可复用）。

### 1.5 MCP 落点默认收拢（M）

现状：`child_env` 剥宿主安全删除守卫（`core/mcp_client.py:61-77`）是**刻意**（防 `SystemExit` 打死 server），但净效果是第三方进程在项目根（含 `local_secrets.json`、`data/*.db`）**不受宿主约束**地读写删；沙箱的 cwd/env 重定向是 opt-in（`mode=none` 默认不重定向，`plugins/sandbox/__init__.py:187-192`）。

- 把 `plugins.sandbox` 的 `workspace_for` **默认启用**（默认 `mode=workspace-write` 于镜像/compose 画像，而非插件兜底 `none`），使 MCP 子进程默认落在会话私有目录。
- 威胁模型补一句到 `core/mcp_client.py` 的 S5 段：**"剥离守卫 = 放弃宿主对子进程的文件删除防护"**，须在 README 部署章节显式提示。

> 这一步不改架构，只改默认；`enforcement` 仍如实报 `none`（重定向**不是**强制，绝对路径仍可写别处）——不要因默认启用就抬成 `partial`，那才是谎报。

## 阶段 3 · 运行时正确性（P1，M）

### 3.1 ReAct 无治理器路径的"假幂等"（S）

`plugins/react/loop.py:251-252` 的 `_trim` 在未超阈时返回**同一个 list**，调用方在 `:635` 就地 `window.append(BUDGET_TIGHT_SYSTEM)` ⇒ 每步累积：

```python
# plugins/react/loop.py:251-252
if keep <= 0 or len(messages) <= keep + 2:
    return list(messages)     # 浅拷贝：调用方会 append，不得改到共享 messages
```
（`_window` 的治理器分支已返回新 list（`:1030`），故只有降级路径受影响；这也是测试覆盖的盲点——补一例：无 context 插件跑多步预算预警，断言 system 段只出现一次。）

### 3.2 ReAct deadline 的最后一层兜底（S）

`plugins/react/loop.py:801-806` 对"不接受 `timeout_s` 的注入 Actor"退回**无超时**调用。加一层硬上限：

```python
remaining = float(cfg.deadline_s) - (time.monotonic() - started)
for kwargs in ({"timeout_s": remaining}, {}):
    try:
        return await self._actor.act(ctx, calls, **kwargs)
    except TypeError:
        continue
# 兜底：即便 Actor 不认 timeout_s，也用剩余 deadline 包一层
if remaining > 0:
    return await asyncio.wait_for(self._actor.act(ctx, calls), timeout=remaining)
return await self._actor.act(ctx, calls)
```

### 3.3 work_memory：索引清理 + 后端一致 + 原子写（M）

- **索引泄露**（`backend.py:301-307` 自认不 `SREM`）：`finish` 先读 `session_id` 再删再清索引：
  ```python
  async def finish(self, task_id: str) -> None:
      key = self._k(task_id)
      raw = await self._r.hget(key, "session_id")
      await self._r.delete(key)
      sid = raw.decode() if isinstance(raw, bytes) else raw
      if sid:
          await self._r.srem(self._idx(sid), task_id)
  ```
- **后端类型分歧**（`backend.py:259-261` vs `:119`）：`_enc` 对 `int/float/bool` **不**序列化（原样返回，由 redis-py 存字符串但语义可预测），或在 `get()` 统一 `json.loads` 尝试还原。选定其一并写进 `WorkMemoryLike` 契约注释。
- **checkpoint 读-改-写竞态**（`backend.py:280-295`）：改用 `redis.pipeline(transaction=True)` 包 `hget→hset`，或每步检查点写独立 key（`wm:{task_id}:cp:{step}`）避免 RMW。

### 3.4 记忆运维护栏（M）

- `plugins/memory/__init__.py:572` 的 `prune` 全表扫描：改为分页（`LIMIT`）+ 只对 `last_accessed_at < cutoff` 的行打分。
- `plugins/approval/__init__.py:88-89` 的会话 allow/deny 名单：加容量上限（如 512/会话，LRU 淘汰）+ TTL。
