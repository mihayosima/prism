# 内核（`agent/core`）优化方案

> 用户授权："内核不一定完全合理，也需要优化……后续还要优化内核，**内核保留解耦性即可**"。
> 本文是内核优化的实施依据。与代码不一致时以代码为准并回改本文。

## 1. 目标与原则

**原则（唯一硬约束）：解耦。**
此前"内核零改动"只是 B5/B6 那批的**战术约束**（独立验收、可回滚），不是原则。

配套原则：
- **由使用驱动，不为假想需求预留**（YAGNI）；
- 每项**独立验收、独立回滚**（沿用路线图原则）；
- 行为不变优先：凡"只改引用方式、不改值"的改造，风险最低（P1 已验证此路径）。

> **决策尺子（本方案统一用它做取舍）**：
> **只为「已存在的痛」或「马上要做的特性」动内核；不为想象中的需求动内核。**
> 同一把尺子既用来提议删除 `parallel`/`serial`/`bail`，也用来推迟 K2、K3。

## 3. 问题清单（均已用证据核实）

| # | 问题 | 证据 |
|---|---|---|
| **P-1** | **服务键仍是裸字符串**——P1/P2/P3 已分别常量化事件名、校验配置键、守卫接线，唯独服务键（`ctx.get("events")`、`provides=["llm"]`、`inject=["events","db"]`）没管。拼错即**静默失效** | 全代码库 |
| **P-2** | **属性访问走两遍父链**：`__getattr__` 先 `has()` 再 `get()` | `context.py:171` + `:174` |
| **P-3** | **State 不继承、服务继承**的"半隔离"无自洽解释；导致子 ctx **只能订阅、不能执行**（实测：`budget_spent`/`permission_mode` 读空），per-run 隔离无法实现 | `context.py:90`；`State` 无 parent 链接 |
| **P-4** | **emit 语义越界**：文档写明"只承载遥测/审计"，却是唯一 fire-and-forget 通道；高频数据（token）被迫走它 → 同步内联（阻塞生成）、成本随监听器数**乘法**增长、无背压 | `events.py:111`、`:114`、`:122` |
| **P-5** | **三模式无生产消费方**：`parallel`/`serial`/`bail` 仅见于测试，语义从未被真实使用验证 | `test_kernel.py:337/347` |
| **P-6** | emit 每次分发：每监听器 `inspect.iscoroutinefunction()`（可缓存）+ `_prune()` 线性重建 | `events.py:117`、`:125` |
| **P-7** | fire-and-forget 异步监听器用 `add_done_callback(lambda t: t.exception() and None)` 吞异常，且任务**不可取消/不可等待** → teardown 可能残留 | `events.py:118-119` |
| **P-8** | 容器直接写 `ctx._current_plugin` **私有属性**；且单属性在并发下不安全 | `container.py:264`、`:275` |
| **P-9** | 缺少"内核不得反向依赖 `sys`/`plugins`"的守卫（现仅查外部引擎 SDK） | `test_agent_purity.py` |

**已测基线**（K4 用）：1 个同步监听器 emit 5000 次 = **3.00 µs/次**；无人订阅 1.13 µs/次。

## 4. 优化项

### K0 · 补一条分层守卫（最便宜，先做）
**问题**：P-9。
**方案**：`test_agent_purity.py` 增加用例——`agent/core/**` 与 `agent/api.py` 中不得出现
`from agent.sys` / `from agent.plugins` / `import agent.sys`。
**验收**：新增用例通过；现有 103 项不回归。
**解耦影响**：只加强不变量，零行为改动。

### K1 · 服务键常量化 + 静态一致性守卫（收益/风险比最高）
**问题**：P-1——与 P1 同类的隐式契约，且是剩下的最大一块。
**方案**：
- 新增 `core/services_catalog.py`：`class Services: EVENTS="events"; LLM="llm"; TASKS="tasks";
  DB="db"; CHAT="chat"; LOOP="loop"; GUARD="guard"; BUDGET="budget"; REACT="react";
  MEMORY="memory"; WINDOWS_MCP="windows_mcp"`，经 `agent.api` 导出。
- 替换各处的裸字符串（**值不变** ⇒ 零行为改动，与 P1 同路径）。
- 新增 `test_services_contract.py`（AST）：
  ① `provides=` / `inject=` 中的字面量必须属于 `Services`；
  ② `ctx.get("…")` / `ctx.provide("…")` 的字面量同上（插件自管键走显式 allowlist）；
  ③ 每个 `Services` 常量都有提供方（防死常量）。
**落点**：约 10–15 个文件（sys/*、plugins/*、run/chat.py 的部分调用）。
**验收**：替换后全量测试通过 + 新增 3 类断言。
**风险**：改动面大但机械；建议**分批**（先 sys，再 plugins，再 run）。
**解耦影响**：**不变**——仍靠 `provides/inject` + `ctx.get`，只是把契约显式化。

### K2 · 数据流原语 `Channel`（解决 P-4 的根）
**问题**：P-4——高频数据走 `emit` 属语义越界，并带来阻塞/乘法/无背压三害。
**方案**：新增 `core/channel.py`：
```python
class Channel:
    """有界数据流通道（与事件总线分工：总线=广播遥测，通道=单/多消费者数据流）。"""
    def __init__(self, maxsize: int = 1024, on_overflow: str = "drop"): ...
    def put(self, item) -> bool: ...        # O(1)，满则按策略丢弃并记录
    async def get(self): ...
    def close(self) -> None: ...
    def __aiter__(self): ...
```
- 内核只提供**原语**，不规定用途；传输层（`run/`）持有实例并按需要注入/提供为服务。
- B5.2 的 token 流改走 Channel，不再 `emit` ⇒ 不存在"监听器乘法"，成本锁死在 O(1)+背压可控。
**验收**：单元测试（有界、溢出策略、关闭语义、多消费者）；B5.2 接入后打字机端到端可用。
**风险**：新增一条内核机制（~40 行）；需明确它**不**取代事件总线。
**解耦影响**：**改善**——数据流与遥测广播彻底分离，各有明确语义。
**状态：推迟**。理由（与删除 `parallel`/`serial`/`bail` 同一把尺子）：Channel **当前没有任何消费方**，
现在建它就是为想象中的需求造基建 —— 与我批评 P-5 自相矛盾。
**待 B5.2 获批后与 B5.2 同一批做**，届时才有真实使用者检验其语义。

### K3 · State 继承语义显式化（最需谨慎）
**问题**：P-3。
**方案（推荐渐进）**：给 `State` 增加**显式**父引用——`State(parent=None)`；读未命中时回退父级，
写始终写自身。由 `Context.child()` 决定是否传递（新增参数 `inherit_state: bool = False`，
**默认 False 保持现状**），需要者显式开启。
**验收**：默认行为零变化；开启后子 ctx 能读到父级 `budget_spent`，且写入不外泄。
**风险**：语义类改动，最容易出意外 ⇒ 排 K1/K2 之后，且**先通读 context.py + 相关插件**再动手。
**解耦影响**：不变（仍是 `ctx.state`），但解锁 per-run 隔离能力。
**状态：推迟**（语义改动）。当前**没有特性被它阻塞**——B5/B6 已绕过它落地。
现在只做一件事：**把"子 ctx 只能订阅、不能执行（budget_spent / permission_mode 会读空）"
这个坑写进文档**（我已实际踩到）。等真需要 per-run 隔离时再动语义。

### K4 · emit 治理（拆成两部分，取舍不同）
**问题**：P-6（分发开销）、P-7（异步监听器不可控）。

**K4a · 异步监听器可追踪 / 可取消 —— **现在做**（这是真 bug）**
- bus 维护 `set[Task]`；`dispose/aclose` 时取消未完成项；
- 去掉 `add_done_callback(lambda t: t.exception() and None)` 的 hacky 写法，
  改为在 `_guarded` 内统一处理异常。
- **验收**：teardown 后无残留任务；异步监听器异常有日志且不产生 "exception never retrieved" 警告。

**K4b · 微性能优化 —— 收益可忽略，顺手做即可，但**不构成动内核的理由****
- `_Listener` 在**注册时**缓存 `is_async = inspect.iscoroutinefunction(handler)`，分发时不再判定；
- `_prune` 改为**按需**（仅在检出 closed ctx 时才重建），或每 N 次分发一次。
- **自我修正**：实测基线 3.00 µs/次（无人订阅 1.13 µs），相对 LLM 调用（秒级）**可忽略**。
  真正值得做的是 K4a（P-7 是真实泄漏），不是这点微优化。

**验收**：重跑压测对比基线并给出改善幅度。
**解耦影响**：零。

### K5 · `_current_plugin` 正规化
**问题**：P-8。
**方案**：改用 `contextvars.ContextVar[str | None]`（而非 ctx 上的普通属性）——
**并发安全**，且不再需要容器写私有属性。内核导出 `current_plugin()` 访问器。
**验收**：容器装配/启动/卸载窗口内取值正确；并发两轮互不串扰。
**解耦影响**：改善（去掉内核内部破坏封装的补丁）。

## 5. 采纳的执行顺序（按 §1 的"决策尺子"排定）

### 现在做（依次）

| 顺序 | 事项 | 提交粒度 | 理由 |
|---|---|---|---|
| 1 | **K0** 补分层守卫 | 1 个提交 | 1 个测试的成本，挡住最坏的架构漂移（内核反向依赖 `sys`/`plugins`） |
| 2 | **K1** 服务键常量化 | **分三批**：sys → plugins → run | 关掉最后一类隐式契约；值不变 ⇒ 零行为改动 |
| 3 | **K4a** 异步监听器可追踪 / 可取消 | 1 个提交 | 修真泄漏（K4b 顺手带上，不单独成批） |
| 4 | **K5** `_current_plugin` 改 ContextVar | 1 个提交 | 小改动，修并发不安全 + 内核内部破坏封装 |
| 5 | **删除 `parallel` / `serial` / `bail`** | **单独一个提交** | 便于一键 revert；A2 真做时按届时的理解加回 |

## 6. 不变量与验证网

- 服务只经 `provides` / `inject` + `ctx.get` / `ctx.has`，**不 import 实现**；
- 事件只经 `Events` 常量；服务键（K1 后）只经 `Services` 常量；
- **内核零业务词**（`test_agent_purity` 守）；
- **内核不反向依赖 `sys` / `plugins`**（K0 新增守卫）；
- `agent.api` 仍是唯一出口；
- 回归网：现有 **103 项**测试 + 纯度测试 + 新增契约测试；压测基线（K4）。

## 7. 已采纳的决定（2026-09-25）

| # | 议题 | 结论 |
|---|---|---|
| 1 | 是否移除 `parallel` / `serial` / `bail` | **移除**（YAGNI）。**单独一个提交**便于一键 revert；A2 真做时按届时的理解加回 |
| 2 | K1 是否连 `run/chat.py` 的 `ctx.get("…")` 一并常量化 | **是**。插件键（`react` / `memory` / `windows_mcp`）也纳入 `Services`，不留白名单 |
| 3 | K2 是否现在就为 B5.2 服务 | **否**。推迟到 B5.2 获批后，**与 B5.2 同一批做** |

附带采纳的两条自我修正：
- **K4 拆分**：只把 **K4a**（异步监听器可追踪 / 可取消）作为"现在做"的理由；
  **K4b** 微性能优化顺手带上，**不作为动内核的依据**（3.00 µs 基线相对秒级 LLM 调用可忽略）。
- **K3 推迟**：语义改动延后；现在只把"子 ctx 不能用于执行"的坑写入文档，不碰语义。

## 8. 不做（避免过度设计）

- 给事件 payload 定 schema（现有 pure-data 校验已够）。
- 配置热更新 / 增量重载（当前重建容器已可满足）。
- trace / span / 指标（属 D13 可观测，不在内核优化范围）。
- 把 `emit` 改造成通用消息中间件——保持它"遥测/审计广播"的单一职责。
