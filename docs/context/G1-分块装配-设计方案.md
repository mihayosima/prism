# G1 — 分块装配统一编排 · 设计方案

> 定位：G1 是上下文治理的**编排层**落地——把 plan/narrate 的 system（系统记忆/记忆/工具/环境）
> 与 prior（摘要/历史）从"各自独立拼接"收敛为**统一块编排**，并给整轮上下文一个总 token 上限。
> 本文并入用户两点补充：
> **① 块预算注册制**——块自己声明"我是否存在"，治理器动态组装（静态比例不适用）；
> **② 统一互斥规则**——"summary 与 history 覆盖范围不重叠"是 **S1 的互斥规则**的一部分，
> 由 **S2 实现**，不再作为两个独立问题。
>
> 并已并入 **评审校正 6 条**（见 §2.6，逐条钉死语义）：
> ③ coverage 边界一律**左开右闭**；④ 刚性块超限**诚实标注**（report + 文本双通道）；
> ⑤ 剩余**回吐**给未满足的可裁块；⑥ `_fallback_assemble` **对拍**不劣化；
> ⑦ `covers` 作 `BlockSpec` **入参**避免循环依赖；⑧ `Assembly.report` 用 **dataclass** 不裸 dict。
>
> 纪律（不变）：`context` 只做编排（预算 / 裁剪 / 互斥），块内容仍归各 owner；
> 消费面一律 `ctx.has(Services.CONTEXT)` 软依赖——插件停用即退回现状，不劣化不裸崩。

## 1. 问题回顾（现状）

现状（`sys/chat.py`）：

- **plan 段** `system` = `MARK_CHAT_PLAN` + 系统记忆 + `PLAN_SYSTEM` + 记忆块 + 工具块 + 环境事实，
  逐段**字符串直接拼接**（chat.py:278–292）。
- **narrate 段** `system` = `MARK_CHAT_ANSWER` + 系统记忆 + `ANSWER_SYSTEM` + 证据 JSON + 记忆块（chat.py:354–366）。
- **prior** = 摘要头 + 未摘要历史（`seq > covers`，chat.py:229–245）。

短板：

| # | 缺口 | 事实 |
|---|---|---|
| S1 | **无统一块预算** | 各块独立塞入，无总 token 上限；工具/记忆/系统记忆增长时 system 无界膨胀 |
| S2 | **互斥靠隐含表达** | "摘要不重复原文"仅由 `_build_prior` 的 `seq > covers` 隐含保证，未成规则、无守卫、无校验 |

## 2. 设计要点

### 2.1 块模型（Block）——注册制的载体

一个**块** = 可装配单元，由消费方（chat）构造，声明"我是谁 / 我是否存在 / 我要多少预算 / 我覆盖哪段"：

| 字段 | 语义 |
|---|---|
| `key` | 块标识（`system_memory` / `memory` / `tools` / `env` / `summary` / `history`） |
| `kind` | `text`（并入 system 串） / `messages`（并入 prior 列表） |
| `present` | **存在性**——注册制核心：`false` 即**不参与装配、不参与预算分配** |
| `payload` | 内容（`text` 串 或 `messages` 列表） |
| `weight` | 可裁块间的预算权重（刚性块忽略） |
| `priority` | 装配顺序 / 裁剪顺序（越小越先保留） |
| `rigid` | `true`=刚性（超预算也不裁，先占预算） |
| `coverage` | `messages` 块的 seq 覆盖区间，**一律左开右闭 `(lo, hi]`**（含 `hi`、不含 `lo`）；边界值由 chat 读 `covers_up_to_seq` 后作**入参**传入（避免 governor 反向查询，见 §2.6.5） |

**注册制（点1）**：块的**存在性由块自己声明**（`present`），治理器不再猜测哪些块存在：

| 场景 | 块 | `present` 由谁决定 |
|---|---|---|
| 长期记忆停用 | `memory` | `ctx.has(Services.MEMORY)` 为假 / 召回为空 |
| 短会话（无摘要） | `summary` | `latest_summary` 为空 |
| 无工具调用 | `tools` | `tasks.catalog()` 为空 |
| 无系统记忆 | `system_memory` | `ctx.get(SYSTEM_MEMORY)` 为空 |

治理器只对 `present=true` 的块分配预算、参与互斥、进入装配——**静态比例因此不再适用**：
权重只在"存在的块"间重归一（见 2.3）。

### 2.2 统一互斥规则（S1 定义 + S2 实现）

> 用户补充②：这不仅不是 S2 的独立问题，恰恰是 S1 的互斥规则的一部分。

**规则（S1 层，形式化）**：对任意两个 `messages` 块，其 `coverage` 区间**两两不相交**。
- **边界语义钉死：一律「左开右闭」`(lo, hi]`**——含 `hi`、不含 `lo`，全链统一，不得混用双闭/左闭右开。
- 现行实例（统一为左开右闭）：`summary` 覆盖 `(0, covers]`，`history` 覆盖 `(covers, N]`
  → 边界**相接**（`lo_history == hi_summary == covers`）、**交集为空**。
- 两侧边界由 `covers_up_to_seq` **单一来源（SSOT）**派生，从规则上杜绝"摘要 + 原文重复注入"。
- 该语义必须写入 `BlockSpec.coverage` 的 **docstring**（见 §2.4），防止实现者按"左闭右开/双闭"误读
  而产生重叠（重复注入）或漏项（丢历史）。

**实现（S2 层）**：治理器装配 `messages` 块时：

1. 收集所有 `present` 的 `messages` 块，按 `coverage.lo` 排序；
2. **校验**相邻块边界相接（左开右闭下判据为 `lo_{i+1} == hi_i`）；若 `lo_{i+1} < hi_i`
   即检测到**覆盖重叠**（调用方 bug），按 `priority` **后者截断**（priority 小者胜出）并告警——**绝不双份注入**；
3. 输出前经**守卫单测**：同一 seq 不得同时出现在两个 `messages` 块。

如此，S2 不再是"另一个问题"，而是 S1 互斥规则在 `messages` 维度上的一次应用。

### 2.3 动态预算分配

```
input_budget = max_context_tokens - reserve_output_tokens
1) 刚性块（rigid=true）先各按其实际 token 扣减（system 骨架 / 系统记忆 / 环境 / 本轮 user）
2) 剩余 = input_budget - Σ刚性块
     若 剩余 < 0 → 刚性超限：按 priority 由大到小（priority 大 = 更次要，先降级/截断）处理，并**诚实标注**：
       a) report 通道：`AssemblyReport.rigid_overflow` 逐项记录 requested/allocated 与缺口 token；
       b) 文本通道：在 system_text 内插入显式降级标注段（供模型 / 用户可见）；
       **禁止静默截断**（见 §2.6.2）。
3) 可裁块（present 且非 rigid）按 weight 分配剩余上限——**多轮重分配（water-filling）**：
       loop:
         ratio  = weight / Σweight(仍被截断的可裁块)
         上限_i = 剩余 × ratio_i          # 仅对仍被截断者
         未被截断块就地落定，其**未用满的余量回吐**公共池（抬高剩余）；
       直至 全部落定 / 公共池耗尽 / 无可回吐。
     （单轮 ratio 会让"需求小的块"浪费其未用额度；回吐消除该浪费，`redistributed` 记录回吐总量。）
4) 块内按其 kind 裁剪：
     - messages(history) → 治理器 pick_history 口径（token 从新到旧；coverage=(covers, N]）
     - messages(summary) → 超预算则交压缩器再压（S2 / 滚动摘要；coverage=(0, covers]）
     - text(tools)       → 折叠低频工具（G5）/ 截断描述
     - text(memory)      → 反推 recall 实参（G4）
```

要点：
- **权重只在"存在的块"间重归一**——memory 停用时其 10% 自动让给 history/tools，不浪费。
- **回吐闭环**：可裁块的"需求 < 上限"余量必须回流再分配，否则等于把预算扔进水里。

### 2.4 接口（接缝扩展）

`plugins/context/protocols.py` 加纯数据契约（chat 构造、governor 消费；**无插件内部依赖**）：

```python
@dataclass(frozen=True)
class BlockSpec:
    key: str
    kind: str                                   # "text" | "messages"
    present: bool
    payload: str | list[dict]
    weight: float = 0.0
    priority: int = 100
    rigid: bool = False
    coverage: tuple[int, int] | None = None
    """
    messages 块的 seq 覆盖区间，**左开右闭 `(lo, hi]`**（含 hi、不含 lo）。

    边界语义钉死：``summary = (0, covers]``、``history = (covers, N]``，``covers``
    取自 ``covers_up_to_seq``（SSOT）；任意两块区间两两不相交。
    该边界由 **chat 读取后作入参传入**（非 governor 反向查询），避免
    governor→chat/short_term 循环依赖（见 §2.6.5）。
    """

@dataclass(frozen=True)
class BlockReport:
    key: str
    present: bool
    kind: str
    requested: int                    # 块自报需求 token
    allocated: int                    # 分配上限 token
    used: int                         # 实占 token
    trimmed: bool                     # 是否被裁剪
    reason: str = ""                  # 裁剪 / 跳过原因（absent / downgraded / …）

@dataclass(frozen=True)
class AssemblyReport:
    blocks: list[BlockReport]
    total_used: int
    input_budget: int
    rigid_overflow: list[BlockReport]  # 刚性超限被降级者（空 = 未超限；见 §2.6.2）
    redistributed: int                 # 回吐再分配的总 token（见 §2.6.3）

@dataclass(frozen=True)
class Assembly:
    system_text: str
    prior: list[dict]
    report: AssemblyReport             # 结构化 dataclass，**不裸 dict**（见 §2.6.6）

class GovernorLike(Protocol):
    ...                                         # 既有预算查询保留
    def assemble(self, blocks: list[BlockSpec]) -> Assembly: ...
```

> `BlockSpec` / `Assembly` 为**纯数据结构**，放 `protocols.py`——消费方不触插件内部实现，
> 与 memory 三组件同构的接缝风格。

### 2.5 装配流程（chat 侧改造）

`_plan` / `_narrate` 不再手拼 system，改为构造块列表交给治理器：

```python
blocks = [
    BlockSpec("system_memory", "text", present=bool(sm), payload=sm, rigid=True, priority=0),
    BlockSpec("memory", "text", present=bool(mem), payload=mem, weight=mem_ratio, priority=10),
    BlockSpec("tools",  "text", present=bool(tools), payload=tools, weight=?, priority=20),
    BlockSpec("env",    "text", present=True, payload=_env_facts(), rigid=True, priority=90),
]
asm = gov.assemble(blocks) if gov else _fallback_assemble(blocks)   # 无治理器 → 旧路径
system = MARK + asm.system_text
```

prior 同理：`summary` / `history` 作为 `messages` 块交给 `assemble`，由互斥规则输出。
**`covers` 由 chat 读 `summary_meta` 后作 `BlockSpec.coverage` 边界传入**（`summary=(0, covers]`、
`history=(covers, N]`）——governor 只**消费**该边界，**不反向查询** short_term/chat，从而避免
governor ↔ chat 的循环依赖（评审校正 ⑤）。`pick_history` 仅作 governor **内部**方法被 `assemble`
对 `history` 块调用（同插件内自洽，不跨插件）。

**降级**：无 `CONTEXT` → `_fallback_assemble`（即现状拼接），行为不劣化；并配**对拍测试**（见 §2.6.4）。

### 2.6 关键语义钉死（评审校正 6 条）

> 以下 6 条是设计评审的硬约束，实现时逐条对号入座；每条均配守卫单测（见 §4）。

#### 2.6.1 coverage 边界 —— 一律「左开右闭」`(lo, hi]`
- 全链统一：`summary=(0, covers]`、`history=(covers, N]`；相接判据 `lo_{i+1} == hi_i`。
- **语义写入 `BlockSpec.coverage` 的 docstring**（§2.4），杜绝口头约定。
- 守卫单测以"边界值归属"验证不重不漏：`covers` 归 `summary`（含 `hi`），`covers+1` 归 `history`
  （不含 `lo`）；`seq == lo` 不属本块。

#### 2.6.2 刚性块超限 —— 「诚实标注」具体化（**report + 文本双通道**）
- **report 通道**：`AssemblyReport.rigid_overflow` 逐项记录被降级刚性块的 `requested/allocated` 与缺口 token。
- **文本通道**：`system_text` 内插入显式标注段，例如
  `⚠️ 上下文预算超限：以下刚性内容已降级 [system_memory 缺 512 tok, env 缺 128 tok]`，
  使**模型可见、用户可查**。
- **禁止静默截断**：任何刚性块被裁**必留痕于两通道**，否则视为实现缺陷（守卫单测断言）。

#### 2.6.3 剩余回吐 —— 未用满额度回吐给被截断块（否则浪费）
- 单轮 `ratio` 分配会让"需求小于上限"的块浪费其额度；采用**多轮重分配（water-filling）**：
  未被截断块的余量**回吐**公共池 → 再分配给仍被截断的块 → 迭代至收敛 / 池空 / 无块被截断。
- `AssemblyReport.redistributed` 记录回吐总量（可观测，证明预算未空转）。

#### 2.6.4 `_fallback_assemble` —— 对拍测试保证不劣化
- 对**同一组块**（`present` 全真、预算充足），`governor.assemble` 与 `_fallback_assemble` 的
  `system_text` / `prior` 必须**逐字节等价**（参数化对拍用例）。
- 治理器停用 / 缺失时走 `_fallback_assemble`，行为与现状一致——**不劣化**。

#### 2.6.5 `pick_history` 调用位置 —— `covers` 作入参，避免循环依赖
- `covers` 由 **chat** 读 `summary_meta` 后经 `BlockSpec.coverage` **传入**；governor **不**反向查询
  short_term/chat（否则形成 governor → chat → governor 环路）。
- `pick_history` 仅作 governor **内部**方法被 `assemble` 调用（同插件内），不跨插件调用。

#### 2.6.6 `Assembly.report` —— dataclass，不裸 dict
- 定义 `AssemblyReport` / `BlockReport`（§2.4），字段固定、可类型检查、可断言；**禁止裸 dict**。

## 4. 验收与守卫

- **存在性**：memory / tools / summary 各自缺失时预算正确重归一，无空块占额。
- **互斥（左开右闭）**：长会话（>50 轮）prior 无重复 seq；边界值 `covers` 只属 `summary`；
  守卫单测（同一 seq 不跨 `messages` 块）。
- **回吐**：小需求块余量回吐后，被截断块实占提升；`redistributed > 0`，且不存在"占用 < 上限却仍空转"。
- **刚性超限双通道**：构造刚性总和 > `input_budget` 的用例，断言 `report.rigid_overflow` 非空
  **且** `system_text` 含显式降级标注段。
- **总上限**：`prior + system` 总 token <= `input_budget`；刚性超限时诚实降级并标注。
- **降级对拍**：治理器停用 → `_fallback_assemble`，与 `assemble`（预算充足时）**逐字节等价**。
- **契约**：`Assembly.report` 为 `AssemblyReport`（类型断言），非裸 dict。
- **解耦**：governor 不 import 任何插件 / 业务模块；chat 只经 `ctx.has/get(CONTEXT)`；
  `BlockSpec` / `Assembly` 纯数据；**`covers` 由 chat 传参**；纳入 `test_plugin_decoupling.py` 守卫。
