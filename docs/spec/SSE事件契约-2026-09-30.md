## 0. 一句话契约

> **每帧一行 `data: <JSON>`，JSON 形如 `{"event": "<帧名>", "payload": <载荷>}`，帧与帧之间以空行分隔。**
> `progress` / `token` / `thinking` 三类帧的载荷**再包一层** `{"source": <内核事件名>, "data": <业务对象>}`。

---

## 1. 线格式（wire format）

### 1.1 实际格式（**非**标准双行 SSE）

```
data: {"event":"start","payload":{"run_id":"a1b2c3d4"}}

data: {"event":"token","payload":{"source":"agent/llm/token","data":{"text":"你"}}}

data: {"event":"final","payload":{"text":"你好","ok":true,"evidence":{...}}}
```

要点：

| 项 | 值 | 说明 |
|---|---|---|
| 帧分隔 | `\n\n` | 两个换行 |
| 前缀 | `data: ` | 冒号后有**一个空格** |
| 单帧内容 | 一个完整 JSON 对象 | 内含 `event` 与 `payload` |
| `event:` 行 | **不存在** | 与标准 SSE 的双行（`event:` + `data:`）**不同** |
| `id:` / `retry:` 行 | 不存在 | 本协议不使用 |

> ⚠️ **易踩坑**：用标准 SSE 客户端（如 `new EventSource`）或多行解析库时，要按"单行 `data:` + JSON 自带事件名"来解析。`web/src/api/sse.ts` 的实现即：按 `\n\n` 分帧 → 只看 `data:` 行 → `slice(5).trim()` → `JSON.parse` → 取 `frame.event`。
>
> 解析失败的帧**静默跳过**（不中断流），以容忍半截/损坏帧。

### 1.2 响应头

```
Content-Type: text/event-stream
Cache-Control: no-cache
X-Accel-Buffering: no
```

`X-Accel-Buffering: no` 用于关闭 Nginx 等反代的分块缓冲（否则流式会被整段攒住）。

### 1.3 鉴权（B3 起，opt-in）

后端启用 `--token` 后，本端点需要凭据。**两种携带方式都可**：

- `Authorization: Bearer <token>`（普通 fetch）
- `?token=<token>`（**必须支持**：`EventSource` 无法自定义请求头）

> `web/src/api/sse.ts` 走的是 `fetch` + `ReadableStream.getReader()`，两者都能用；
> 但 `buildUrl()` 会**无条件**附加 `?token=`（有 token 时），以保证任何调用形态都不缺凭据。

## 2. 帧总表

| 帧名 | 载荷层次 | 来源（后端） | 前端消费点 |
|---|---|---|---|
| `start` | 平铺 | `chat.py` `_gen()` 首帧 | 记录 `run_id`（取消用） |
| `progress` | **`{source, data}`** | `progress.py` 默认映射 | `useSeg().addStep(d)` |
| `thinking` | **`{source, data:{text}}`** | `Events.LLM_THINKING` | `useSeg().appendThinking(d.text)` |
| `token` | **`{source, data:{text}}`** | `Events.LLM_TOKEN` | `useSeg().appendToken(d.text)` |
| `approval` | **`{source, data}`** | `Events.APPROVAL_PENDING` | `sealSeg()` + `cards.showApproval(d)` |
| `approval_done` | **`{source, data}`** | `Events.APPROVAL_ANSWERED` | `cards.dismissApproval(d)` |
| `ask_user` | **`{source, data}`** | `Events.ASK_USER_PENDING` | `sealSeg()` + `cards.showAskUser(d)` |
| `ask_user_done` | **`{source, data}`** | `Events.ASK_USER_ANSWERED` | `cards.dismissAskUser(d)` |
| `todo` | **`{source, data}`** | `Events.TODO_PROGRESS` | **无专门分支** ⇒ 落 `progress` 兜底（`useSeg().addStep(d)`） |
| `final` | 平铺 | `chat.py` `_worker()` 末帧 | `useSeg().finish(p.text, p.evidence)` |
| `cancelled` | 平铺 | `chat.py` 取消分支 | 由 `useSeg` 收尾（保留已出文本） |
| `error` | 平铺 | `chat.py` 异常分支 | `useSeg().finish('请求失败：' + p.error)` |

**13 帧**（上表 12 帧 + `sse.ts` 常量表中预留未用的 `tool_call`）。

> ★ **载荷层次是最大陷阱**（B2.6 第三处阻塞缺陷的根因）：
> - `progress` / `token` / `thinking` / `approval` / `ask_user` 及两个 `*_done` → 业务字段在 **`payload.data`**；
> - `start` / `final` / `cancelled` / `error` → 业务字段在 **`payload` 本身**。
>
> 两者**不可混用**。后端把前者统一包层，是因为它们经由 `agent/sys/progress.py:_pusher()` 转发，为了保留"这帧来自哪个内核事件"才加了 `source`。

## 3. 逐帧字段定义

### 3.1 `start`

```jsonc
{ "event": "start", "payload": { "run_id": "a1b2c3d4" } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `run_id` | string | ✅ | 8 位 hex。用于 `POST /api/chat/cancel` |

### 3.2 `progress`（通用步骤）

```jsonc
{ "event": "progress",
  "payload": { "source": "agent/react/step/start", "data": { "step": 3, "session_id": "..." } } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `payload.source` | string | ✅ | **内核事件名**（`agent/...`），前端取末段显示 |
| `payload.data` | object | ✅ | 该事件的原始载荷（随 `source` 而异） |

常见 `source` 与 `data`：

| `source` | `data` 字段 | 触发时机 |
|---|---|---|
| `agent/react/step/start` | `step`(int), `session_id`(str) | ReAct 每步开始 |
| `agent/react/step/end` | `step`, `tools`(str[]), `is_error`(bool) | ReAct 每步结束 |
| `agent/tasks/post-execute` | `task`, `caller`, `ok`, `span_ms`, `error`, `clipped`, `omitted_tokens`, `limit_tokens` | 每次工具调用后 |

> 停用 `plugins.react` 时收不到 `agent/react/*` 帧，属**优雅降级**（无中间过程，但不报错）。

### 3.3 `token`（打字机）

```jsonc
{ "event": "token", "payload": { "source": "agent/llm/token", "data": { "text": "你" } } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `payload.data.text` | string | ✅ | 文本**片段**（非全量） |

拼接纪律：**所有 `token` 帧的 `text` 顺序拼接 === `final.text`**。
（B5.2 起默认 `stream=true`；`schema != null` 的结构化调用**不发** token 帧。）

### 3.4 `thinking`（思考流）

```jsonc
{ "event": "thinking", "payload": { "source": "agent/llm/thinking", "data": { "text": "让我想想…" } } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `payload.data.text` | string | ✅ | `reasoning_content` 的片段 |

**不并入最终正文**（`text` 仅来自 `content`）。若无任何 `thinking` 帧，前端会移除「思考过程」折叠块（避免空壳）。

### 3.5 `approval`（审批请求）

```jsonc
{ "event": "approval",
  "payload": { "source": "agent/approval/pending",
               "data": { "call_id": "9f3c…", "tool": "fs.write", "risk": "write",
                         "mode": "auto", "kwargs": { "path": "/tmp/x" } } } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.call_id` | string | ✅ | **主键**。同 `call_id` 只弹一次（前端幂等） |
| `data.tool` | string | ✅ | 待执行工具名 |
| `data.risk` | string | ○ | `read` / `write` / `danger` |
| `data.mode` | string | ○ | 当前档位 `default`/`plan`/`auto`/`bypass` |
| `data.kwargs` | object | ○ | 调用参数（卡片里以 JSON 展示） |

> **仅在交互式 provider 下发射**（`getattr(provider, "interactive", False)`）。
> 非交互通道问了也不等人，故不发此帧（否则前端会弹出永不消解的假卡片）。

### 3.6 `approval_done`（审批了结）

```jsonc
{ "event": "approval_done",
  "payload": { "source": "agent/approval/answered",
               "data": { "call_id": "9f3c…", "tool": "fs.write", "approved": true, "by": "user" } } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.call_id` | string | ✅ | 与 `approval` 配对 |
| `data.approved` | bool | ✅ | 批准/拒绝 |
| `data.by` | string | ○ | `user` / `timeout` / `policy:deny` / … |

用途：**他处了结**（超时、另一标签页应答）时前端把卡片转成终态（禁用交互）。同页应答由前端本地收尾，此帧是幂等兜底。

### 3.7 `ask_user`（澄清问询）

```jsonc
{ "event": "ask_user",
  "payload": { "source": "agent/ask_user/pending",
               "data": { "call_id": "7ae1…", "kind": "ask_user",
                         "question": "要选哪个方案？",
                         "options": [ { "label": "方案A", "value": "A", "desc": "稳妥", "group": "" } ],
                         "multi": false, "allow_free_text": true } } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data.call_id` | string | ✅ | 主键（幂等键） |
| `data.kind` | string | ✅ | 恒为 `"ask_user"`（`/api/approval/pending` 恢复时据此分流） |
| `data.question` | string | ✅ | 问题正文 |
| `data.options` | object[] | ○ | 归一化后的选项规格，见下 |
| `data.multi` | bool | ○ | 是否多选（无候选时后端已强制 `false`） |
| `data.allow_free_text` | bool | ○ | 是否显示自由输入框（默认 `true`） |

`options[i]` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `label` | string | 显示名 |
| `value` | string | 回传值（缺省时前端回退用 `label`） |
| `desc` | string | 副说明（有则渲染成卡片行形态） |
| `group` | string | 分组名（有则按组分节） |

应答载荷（发往 `POST /api/approval/answer`）：

| 用户行为 | 请求体 |
|---|---|
| 点选单项 | `{"call_id":"…","answered":true,"choice":"A"}` |
| 多选提交 | `{"call_id":"…","answered":true,"choices":["A","B"]}` |
| 自由文本 | `{"call_id":"…","answered":true,"text":"用第三种方案"}` |

### 3.8 `ask_user_done`

```jsonc
{ "event": "ask_user_done",
  "payload": { "source": "agent/ask_user/answered",
               "data": { "call_id": "7ae1…", "answered": true, "by": "user" } } }
```

### 3.9 `final`

```jsonc
{ "event": "final",
  "payload": { "text": "已完成。",
               "ok": true, "error": null,
               "evidence": { "plan": {...}, "evidence": {...},
                             "tokens_in": 1200, "tokens_out": 340 } } }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | ✅ | **权威正文**。前端与其"token 拼接结果"对账 |
| `ok` | bool | ✅ | 本轮是否成功 |
| `error` | string \| null | ✅ | 失败原因 |
| `evidence` | object | ○ | `plan` / `evidence` / `tokens_in` / `tokens_out` |

> 前端对账纪律：`text === 累积 token` → 走**零重排**路径（只收尾活动块）；
> 不等（如被截断/重写）→ 用 `text` **整篇重建**（安全网）。

### 3.10 `cancelled`

```jsonc
{ "event": "cancelled", "payload": { "run_id": "a1b2c3d4" } }
```

由 `POST /api/chat/cancel` 触发的 `asyncio.CancelledError` 上浮时发出。前端保留已打出文本并追加「（已取消）」标注。

### 3.11 `error`

```jsonc
{ "event": "error", "payload": { "error": "builder 未装配" } }
```

流内异常（非 HTTP 层错误）。前端渲染为 `请求失败：<error>`。

### 3.12 `tool_call`（**预留，当前不发**）

`sse.ts` 的 `SSE_EVENTS` 常量表中有 `TOOL_CALL: 'tool_call'`，但后端当前**不发**此帧（工具调用信息经 `progress` 帧的 `agent/tasks/post-execute` 传递）。**保留为扩展位**，前端已有对应分支（无副作用）。

### 3.13 `todo`（规划完成度）

```jsonc
{ "event": "todo",
  "payload": { "source": "agent/todo/progress", "data": { /* 规划完成度载荷 */ } } }
```

- **来源**：`agent/sys/progress.py::FRAME_TYPES` 的 `Events.TODO_PROGRESS → "todo"`，
  由 `_pusher()` 转发 ⇒ **载荷带 `{source, data}` 包层**（同 §2 的陷阱，别按平铺读）。
- **前端现状**（2026-10-15 核实）：`sse.ts::SSE_EVENTS` **未登记** `todo`，
  前端也没有专门的 `todo` 分支 ⇒ 该帧会落入 `progress` 的默认分支
  （`useSeg().addStep(d)`），表现为"多一条步骤"。**当前不影响正确性**，但若要
  专门渲染进度（如 todo 面板），需先在 `SSE_EVENTS` 登记 `TODO: 'todo'` 再加分支。
- ★ 本帧是 **v1.0 文档欠账**：后端早已在发，契约文档此前漏登记 ⇒ 契约自检
  （`check-api-contract.mjs` 的「FRAME_TYPES 映射值必须在文档中登记」）因此红灯。

## 4. 生命周期与顺序保证

```
start
  ├─ (progress | token | thinking)*          ← 交错出现，顺序即发生顺序
  ├─ (approval → …等待… → approval_done)     ← 卡片帧会"封段"（sealSeg）
  ├─ (ask_user → …等待… → ask_user_done)
  └─ final | cancelled | error               ← 三者互斥，且必居其一（终止帧）
```

**不变量**：

1. `start` 恒为首帧，`final`/`cancelled`/`error` 恒为末帧；
2. 出现终止帧后，服务端 `return`，**不再发任何帧**；
3. 客户端断连 → 服务端 `asyncio.CancelledError` → 取消在跑任务（`finally` 清理 `active_runs`，防孤儿）；
4. `approval` 与 `approval_done` 按 `call_id` 配对；`ask_user` 同理；
5. 卡片帧到达时前端先 `sealSeg()`，保证 **DOM 顺序 == 发生顺序**（卡片插在已出文本之后，后续文本另起新段）。

## 5. 前后端对齐检查清单

| # | 位置 | 作用 |
|---|---|---|
| 1 | `agent/sys/progress.py` `PROGRESS_EVENTS` | 订阅哪些内核事件 |
| 2 | `agent/sys/progress.py` `FRAME_TYPES` | 内核事件名 → 帧名映射 |
| 3 | `agent/core/events_catalog.py` | 内核事件常量 SSOT |

| 5 | `web/src/api/sse.ts` `SSE_EVENTS` | 前端帧名常量表 |
| 6 | `web/src/api/sse.ts` `SsePayloadMap` | 帧 → 载荷类型收窄 |
| 7 | `web/src/api/types.ts` 各 `*Payload` | 字段 DTO |
| 8 | `web/src/views/ChatView.vue` `handleFrame()` | 唯一分发点 |

**自动化守卫**：

- `web/tools/check-sse-contract.mjs`（33 项）——静态契约 + 真实产物逐帧分发；
- `web/tools/check-card-payload.mjs`（11 项）——**载荷层次**专项（含反向验证）；
- `web/tools/check-views-functional.mjs`（39 项）——fetch 桩直连真实后端，字段漂移即红灯。

## 6. 附录：最小可复现调用

```bash
# 无鉴权
curl -N -X POST http://127.0.0.1:8720/api/chat/stream \
     -H 'Content-Type: application/json' \
     -d '{"message":"你好"}'

# 启用 token 后（SSE 场景用 query 参数最省事）
curl -N -X POST 'http://127.0.0.1:8720/api/chat/stream?token=my-secret' \
     -H 'Content-Type: application/json' \
     -d '{"message":"你好"}'
```

`-N` 关闭 curl 自身缓冲，否则看不到逐帧效果。
