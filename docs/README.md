# 文档索引（docs/）

本项目文档**按主题域组织**，并**把「长期有效的设计文档」与「带日期的评估快照」分开**：

- **顶层主题目录**（`architecture/` `plugins/` `memory/` `context/` `sandbox/` `spec/` `roadmap/`）= **活文档**，描述"设计当前是什么样"，会随实现更新。
- **`reports/`** = **历史快照**，是一时点的评估 / 复核 / 审计 / 计划，**只读、不再回改**（除非补更新记录）。按主题再分子目录。

> 判据（选目录时照此）：**带日期（`YYYY-MM-DD`）且属"评估/复核/审查/审计/检测/调研/勘察/对账/记录/清单/现状/分析/进度/收尾/建议/实施/计划"** ⇒ 进 `reports/<主题>/`；其余（架构、`X-设计方案`、`X-说明`、`规约`、`契约`）⇒ 进对应主题目录。
>
> 本次重组的完整 old→new 映射见 [`文档迁移清单-2026-10-20.md`](文档迁移清单-2026-10-20.md)。

## 维护约定

1. 新增**设计方案** ⇒ 对应主题目录；`plugins/` 下**再按插件包名入子目录**（与代码 `agent/plugins/<name>/` 对应，如 `plugins/react/`、`plugins/asr/`）；新增**评估/复核/审计/调研/计划报告** ⇒ `reports/<主题>/` 并**文件名带日期**。
2. 顶层主题目录名一律**小写英文单词**（不用空格）；`reports/` 子目录同名。
3. 报告类文档**不回改**；如需修订，在文内加"更新记录"并保留原快照语义。
