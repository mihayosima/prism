# 内核系统层（`agent/sys`）优化方案

> 依据：2026-09-25 对 `sys/` 全部模块 + `core/contract.py` 的逐文件复核。
> 与根目录《内核优化方案.md》（针对 `agent/core` 的 K0–K5，已落地）互补：本文只覆盖**系统层插件**。
> 与代码不一致时以代码为准并回改本文。

## 1. 目标与原则

沿用《内核优化方案.md》的决策尺子：**只为「已存在的痛」或「马上要做的特性」动手**。

- 每项独立提交、独立验收、可回滚；
- 行为不变优先；失败路径的修复不改变成功路径的任何行为；
- 不引入新内核概念（Channel 等留给 core 方案既定计划）。

## 2. 问题清单（均已在代码中定位）

| # | 问题 | 位置 | 严重度 |
|---|---|---|---|
| S-1 | **budget 预借只借不还**：provider 抛异常时 pre-call 已借的 est 无退款路径，且 `LLM_POST_CALL` 不发（失败无审计）；估算口径 `len(json)//4` 对中文低估 2–3 倍；est 不含 tools/schema 开销；`est_cost` 恒 None | `llm.py:83`、`budget.py` | **高**（预算护栏失真） |
| S-2 | **mcp_client stderr 从不消费**：`stderr=PIPE` 但无读取者，话痨 MCP 子进程写满管道缓冲区后整个卡死 | `mcp_client.py:34-37` | **高**（可实际触发） |
| S-3 | **mcp_client pending futures 泄漏**：子进程退出 / `close()` 时 `_pending` 既不 resolve 也不清，调用方悬挂至 timeout 而非立刻拿到"连接已断" | `mcp_client.py:59-76`、`:80-96` | 高 |
| S-4 | **迁移非原子**：每条 DDL 独立事务，中途失败 = 半套表且迁移名未登记 → 下次启动重放整组 | `storage.py:86-96` | **高**（数据完整性） |
| S-5 | **guard 不消费 risk 元数据**：`RISKS` 落了 read/write/danger 字段，`_decide` 只看名单，读操作与高危操作待遇相同 | `guard.py:20-33`、`tasks.py:32` | 中（安全粒度） |
| S-6 | llm 每次调用新建 `httpx.AsyncClient`（无连接复用）；无重试/退避；流式分支忽略 `usage` 字段，入账全靠估算 | `llm.py:244`、`:263` | 中 |
| S-7 | loop deadline 超时错误信息打的是 `{params}` 而非 deadline 值；`when_idle` 0.01s 轮询 | `loop.py:63`、`:75-78` | 低 |
| S-8 | `TASKS_POST_EXECUTE` 只带任务名/caller，无结果摘要、耗时、成败；失败路径完全不发事件 | `tasks.py:136` | 中（审计价值） |

| S-11 | storage 未开 WAL / busy_timeout；`_now_iso()` 在 tasks/storage/audit 三处重复 | `storage.py:42` | 低 |

## 3. 优化项

### S1 · budget 退款 + 估算口径修正（优先级 1）

**改动点**：
1. `LlmService.complete` 用 try/except 包住 `provider.complete`：
   - 失败时向 payload 附加失败标记，发 **durable `agent/llm/call-failed`**（`Events` 目录新增常量，SSOT 纪律不变），再 re-raise；
   - 成功路径行为零变化。
2. budget 增加两条订阅：
   - `post-call`：对账——用实际入账替换预借（`spent = spent − est + actual`），账面精确等于 Σ实际；
   - `call-failed`：全额退还本次预借。
3. `_tokens` 改进口径：ASCII 按 `len/4`，CJK 字符按 `~0.75 token/字` 单独计；est 输入纳入 `tools`/`schema` 序列化长度。
4. `agent_budget_log.est_cost` 填入本次预借 est（列已存在，只是从未写入）。

**验收**：新测试——provider 抛错后 `budget_spent` 恢复原值；成功调用后 spent = Σactual 而非 Σest；中文文本估算不再系统性低估（给出对照数字）。
**风险**：低。失败路径新增，成功路径仅对账（口径一致时差值≈0）。

### S2+S3 · mcp_client 加固（优先级 2）

**改动点**：
1. **stderr 消费**：`start()` 起 `asyncio.create_task(self._stderr_loop())` 逐行读 stderr，默认丢弃/降级记 log（可配 `on_stderr` 回调）；`close()` 一并取消。
2. **pending 清理**：
   - `_read_loop` 退出（EOF）时，将所有 `_pending` futures `set_exception(ConnectionError("MCP 子进程已退出"))`；
   - `close()` 先清 pending、再杀进程，保证调用方**立即**收到错误而非悬挂到 timeout。
3. `_request` 期间调用方被 cancel 时，从 `_pending` 移除该 future（done-callback 清理）。

**验收**：模拟子进程 crash → 在途请求立即得到 ConnectionError 而非超时；往 stderr 狂写日志的假 MCP server 不再卡死。
**风险**：低。均为失败路径。

### S4 · 迁移原子化（优先级 3）

**改动点**：`SqliteDb` 增加 `transaction()` 异步上下文管理器（显式 `BEGIN`/`COMMIT`/`ROLLBACK`）；`MigrationRegistry.apply` 把**每组迁移的全部语句 + 迁移名登记**包进单个事务。
**验收**：构造一条中途失败的迁移 → 库内无残留半套表、迁移名未登记、下次启动可完整重放。
**风险**：低。不改变已应用迁移的行为。

### S5 · guard 消费 risk（优先级 4）

**改动点**：
1. 权限矩阵扩展：`config["agent"]["permissions"]["risk"] = {"read": "allow", "write": "open", "danger": "deny"}`（默认值 = 现行为：一切按 open 走，**零回归**）；
2. `_decide(ctx, "task", ...)` 先按名单、再按 risk 兜底；payload 把 `risk` 从 `TaskRegistry` 带进 `TASKS_PRE_EXECUTE`（tasks.invoke 补一个字段）；
3. 为将来 approval 插件预留 `"ask"` 取值（现版本按 deny 处理并在 reason 中注明）。
**验收**：默认配置下全量测试零回归；配置 risk 矩阵后 read 自动放行 / danger 被拒并落 durable 审计。
**风险**：中低。判定逻辑新增一跳，但默认值保证现状不变。

### S6 · llm 连接复用 + usage 入账（优先级 5）

**改动点**：
1. `DeepSeekLlm` 持有懒初始化的单例 `AsyncClient`（`close()` 释放），替代每次新建；
2. 非流式与流式终态优先读响应 `usage` 字段，无则回退估算（诚实标注）；
3. （可选）对 429/5xx 做一次退避重试——若不做，理由记录在案。
**验收**：两次连续调用复用同一连接（可观测 client 实例）；有 usage 时入账为真实值。
**风险**：低。

### S7 · 小修一批（一次提交打包）

| 项 | 改动 |
|---|---|
| S-7 loop | 错误信息改为 deadline 值；`when_idle` 用 `asyncio.Event` 替代轮询 |
| S-8 tasks | `TASKS_POST_EXECUTE` 增加 `ok/span_ms/error`；失败路径补发（payload 带 error） |
| S-9 progress | `tap_progress` 支持 `maxsize`（默认 1024，满则丢最旧并计数） |
| S-10 plugin_manager | 状态文件损坏时 `logger.error` + 备份坏文件为 `.corrupt`，而非静默清空 |
| S-11 storage | 连接初始化执行 `PRAGMA journal_mode=WAL`、`PRAGMA busy_timeout=5000`；`_now_iso` 收敛到 `agent.api` 一处 |

**验收**：全量测试通过；每项各有一条针对性断言。

## 4. 执行顺序

| 批次 | 内容 | 提交粒度 | 理由 |
|---|---|---|---|
| 1 | **S1** budget 退款+口径 | 1 提交 | 正确性问题，预算护栏失真最伤 |
| 2 | **S2+S3** mcp_client 加固 | 1 提交 | 两个可实际触发的高危点，同模块一批 |
| 3 | **S4** 迁移原子化 | 1 提交 | 数据完整性 |
| 4 | **S5** guard 消费 risk | 1 提交 | 默认零回归，独立验收 |
| 5 | **S6** llm 连接复用+usage | 1 提交 | 性能+账目精度 |
| 6 | **S7** 小修打包 | 1 提交 | 均为低风险小改 |

## 5. 不变量

- 成功路径行为不变（S1 对账除外，且口径一致时差值≈0）；
- 事件名一律经 `Events` 常量、服务键经 `Services`（沿用既有 SSOT 纪律）；
- 失败路径新增的事件均为 durable 审计（`agent/llm/call-failed`），不进总线语义；
- 回归网：现有测试全量 + 每项新增针对性测试。

## 6. 不做（避免过度设计）

- mcp_client 不做自动重连（诚实抛错、由上层决定重启，符合项目"不静默"纪律）；
- llm 不做多 provider 负载均衡/熔断；
- guard 不做行级/参数级权限（粒度留给 approval 插件）；
- storage 不换 aiosqlite（文档已论证零后台线程的理由）。
