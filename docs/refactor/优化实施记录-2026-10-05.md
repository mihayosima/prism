## 阶段 0 · 堵红灯（完成）

- **`agent/core/events.py`**：新增 `EventBus.idle()` —— 非破坏性等待全部在途 fire-and-forget 任务结束（与 `aclose` 的"取消"分工）。
- **`agent/sys/llm.py` + `agent/sys/budget.py`**：给 pre/post/failed 三个 payload 线程化**唯一 `call_id`**；budget 预借槽键由 `caller` 改为 `_pending_key()`（优先 call_id，回退 caller）。**根除**"同 caller 连续/并发调用互相覆盖预借槽"的竞态。
- **`agent/tests/test_session_scope.py`、`test_followup_topics.py`**：把 `asyncio.sleep(0)×N` 的碰运气等待换成 `ctx.events.idle()` 确定性等待。
- 结果：原 3 例红灯（EWMA 校准）转绿，**639 passed**。

## 阶段 1 · 安全默认值（完成，1.5 延后）

- **1.1 鉴权默认**：`run/chat.py::_parse` 支持 `PRISM_TOKEN`/`PRISM_HARDENED` 环境注入；`_serve` **入口**（装配前）对"`--hardened` 缺 token" `SystemExit` fail-fast；`Dockerfile` 默认 `CMD` 追加 `--hardened`；compose/prism 设 `PRISM_HARDENED=1` 且 `PRISM_TOKEN` 缺失即报错。
- **1.2 去 `?token=`**：`web/src/api/client.ts::buildUrl` 不再把 token 拼进 URL（前端含 SSE 全程用 `Authorization` 头、全仓无 `EventSource`）；同步更新 `check-api-contract.mjs`、`check-direct-connect.mjs` 的相应对拍断言（由"必须带 token query"翻转为"必须不带"）。
- **1.3 Redis 加固**：compose 中 Redis 绑 `127.0.0.1:6379` + `--requirepass` + `--maxmemory`；`PRISM_REDIS_URL` 带密码。
- **1.4 HTML CSP**：`run/chat.py::_SPAStaticFiles` 对 `text/html` 补 `Content-Security-Policy`（`script-src 'self'`，style 放开 inline）。
- **1.5 MCP 落点默认收拢 —— 延后**。理由见文末。

## 顺带修复的真 bug

**`run/chat.py` 的 `_err_log` NameError**：`_err_log` 定义在 `_serve` 局部，却被**模块级** `_register_probes` 内的 `/api/chat` 错误分支引用 ⇒ 命中 `except AgentError`/`except Exception` 时抛 `NameError`，把面向用户的错误信息顶成通用 500。提到模块级 `_err_log` 后同源。（由 `ruff F821` 发现。）

## 有意延后（附理由，非遗漏）

1. **1.5 MCP 落点默认收拢**：需协调改动 `sandbox.workspace_for` 默认档位 + 两个 MCP 桥 + 审计一致性；且沙箱是**目录插件**（默认未启用），改其默认档位在默认镜像里**不生效**；真正生效要么改桥的 spawn 默认（改变真实 MCP server 的 cwd 语义，本机无真实 MCP 可端到端验证）要么默认启用沙箱插件（改 opt-in 设计）。风险 > 收益，留作独立批次。
2. **3.4a 记忆 `prune` 分页**：`valid()` 的排序（`last_accessed DESC`）与 prune 需要"最老的行"相反，分页不能简单 `LIMIT`；需给 `valid` 增 `created_before` 过滤并单独处理 invalid 行（改 SQL + 测试面）。且 prune 是**低频运维 job**（非热路径），当前 O(n) 打分只在调用时发生。留作独立批次。
3. **两后端 `get()` 类型统一**：强行统一实测**打红**既有测试（InMemory 契约锁定原生 `int`），且把 Redis 侧 json 反解会引入"数值型 session_id 被误还原成 int"的歧义。故**不改行为**，改为在契约注释中显式登记差异（诚实优先）。
4. **阶段 4 大改（文件拆分 / conftest / 装配优先级）**：属架构级重构，宜在专门的批次里做（diff 大、需逐块回归），不宜混入本次安全加固。
