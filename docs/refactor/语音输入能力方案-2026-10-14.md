## 1. 目标与范围

给 **Prism 通用型 agent** 加「语音输入」能力——把"听"沉淀成 agent 可复用能力，支持**多种输入模式**，而非某个页面的一次性按钮。

**首版支持的模式**
- **模式 R（实时流式）**：麦克风 → WS → 流式 Zipformer 即时出字（聊天输入框语音输入）。
- **模式 F（长录音文件转写）**：上传录音文件（会议/访谈，数分钟至数小时）→ VAD 分段 → **SenseVoice 离线识别器**逐段高精度转写 → 结构化分段结果。

**降级链路（仅模式 R 适用）**：本地引擎不可用时自动降级浏览器 **Web Speech API**；模式 F 无 Web Speech 兜底（浏览器无法喂文件），降级为"引擎不可用"提示。

**首版约束（用户拍板 19:28 / 19:48）**
- 本地私有引擎：**sherpa-onnx**，运行时含两类识别器：
  - 模式 R：`OnlineRecognizer`（流式 **X-ASR Zipformer transducer**，中英+标点，已确认）。
  - 模式 F：`OfflineRecognizer`（**SenseVoice**，首版即上，多语种 + 标点/ITN）。
- **实时通道（模式 R）首版不叠加 SenseVoice 定稿**（`refine` 钩子首版 passthrough，第二版接通）；**SenseVoice 作为「模式 F 文件通道的识别引擎」首版即用**——不同模式的可选引擎，非实时通道二次润色，与"首版不叠加"语义不冲突。
- 必须为第二版预留：`refine` 实时定稿钩子、HybridProvider、`asr_transcribe` tool、可选 TTS、飞书工作流（见 §9）。

**不做（首版）**：TTS 回放闭环、多语种切换 UI、云端 ASR 兜底（与"本地私有"冲突）、飞书写入执行（仅预留数据契约与 tool 接口）。

## 2. 技术选型（已确认 + 复核订正）

| 层 | 选型 | 依据 / 备注 |
|---|---|---|
| 本地引擎 | **sherpa-onnx**（自带 onnxruntime） | Apache-2.0、纯离线、C/C++ 推理、CPU 即可 8–20× 实时；12 种语言绑定 |
| 流式模型（模式 R） | **`X-ASR-zh-en` 官方流式导出 `deployment/models/chunk-480ms-model`**（encoder 565MB fp32 / decoder 11MB / joiner 10MB / tokens 58KB；中英双语 + 自动标点，X-ASR 系列 Zipformer **transducer**，cjkchar 分词） | 镜像 **hf-mirror.com / GilgameshWind/X-ASR-zh-en** 的 `resolve/main/deployment/models/chunk-480ms-model` 直拉散文件。⚠️ **不要用** k2-fsa releases 的 `sherpa-onnx-x-asr-...-int8-2026-06-03`：其编码器缺 `encoder_dims` 元数据，`from_transducer` 无法加载（根因在导出阶段）。加载：`OnlineRecognizer.from_transducer(encoder,decoder,joiner,tokens,model_type="zipformer2")`（按官方 `sherpa_streaming_infer.py`，无需 bpe）。 |
| 文件识别器（模式 F） | **`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17`**（int8 ~230MB，多语种中/英/日/韩/粤 + 标点/ITN） | 用户拍板；长录音精度最高；加载用 `OfflineRecognizer.from_sense_voice(model,tokens,use_itn=True)` |
| VAD 模型 | **`silero_vad.onnx`**（单独下载，实际 629KB） | 两通道共用 `VoiceActivityDetector(VadModelConfig(SileroVadModelConfig(model=silero_vad)))`；文件通道整段 `accept_waveform`→`flush`→循环 `front`(SpeechSegment)/`pop` 取 `(start,end)`；实时通道增量 `accept_waveform` 断句 |
| 降级（仅模式 R） | 浏览器 **Web Speech API**（`lang='zh-CN'`） | 零后端、零密钥；DeepSeek 主流插件做法 |
| 传输（模式 R） | 前端 `AudioWorklet` 采 16kHz mono int16 PCM → **WebSocket** 流式 | sherpa 官方 web client 同形态；避免 MediaRecorder(webm/opus) 服务端再解码 |
| 运行依赖 | `sherpa-onnx` + `soundfile`（读 wav）+ `numpy`（VAD 段处理） | 装进 **managed venv**；⚠ **Python 3.13 wheel 可能缺失，阶段 0 首验**（见 §8） |

> 否决项（记录备查）：FunASR 原生（~2GB PyTorch、最佳需 GPU）、faster-whisper（CPU 慢）、Whisper.cpp/transformers.js（非流式、中文弱）、云端 ASR（与"本地私有"冲突）。Whisper 离线未被选中，但 `OfflineRecognizer` 抽象不排斥将来接入。

## 3. 架构

### 3.1 后端（能力层 + 双通道端点）

仿现有 **sandbox 插件**模式（`plugins/sandbox` 用 `@plugin` 类 + `apply(ctx)` 提供能力，不挂路由，`chat.py` 直接 import）——ASR 也做成"后端能力插件"，不强加"插件挂 HTTP 路由"机制。

```
模式 R（实时）               模式 F（长录音文件）
浏览器 AudioWorklet          上传文件(.wav/.mp3/.m4a)
   │ WS /api/asr/ws             │ POST /api/asr/transcribe-file
   ▼                            ▼
agent/plugins/asr（ASRService）
   ├─ provider = SherpaOnnxProvider（持两识别器：streaming X-ASR transducer + SenseVoice offline）
   ├─ VadModule（silero-vad 单例，两通道共用）
   ├─ 实时：OnlineRecognizer.from_transducer(...) → partial/final 帧（endpoint detection 断句）
   └─ 文件：`VoiceActivityDetector` **分块** `accept_waveform` → 每块即时 `front`(SpeechSegment)/`pop` → `flush()` → [(start,end)]
            → OfflineRecognizer.from_sense_voice(...).decode → **解析 result JSON 取 text** → Segment[] 列表
```

- `agent/plugins/asr/__init__.py`：`@plugin ASR`（`provides=[Services.ASR]`，**provide 实例**而非工厂函数）；持 `ASRService` 门面；配置合并用**深合并**（嵌套节 `streaming`/`file`/`vad`），容器级 `agent.asr` ← 会话级 `plugins.asr`。
- `agent/run/chat.py`：新增 `_register_asr(app, deps)`（注册 `GET /api/asr/status`、`POST /api/asr/transcribe-file`、`WS /api/asr/ws`），在 `_register_routes` 编排序列末尾调用。⚠ WS **不受全局 http 中间件保护** ⇒ 端点内按 `--token` 自行校验（`HandlerDeps` 随之新增 `token` 字段）。
- `agent/plugins/asr/vad.py`：`VadModule`；`segment_file(samples, chunk_seconds=1.0)` **必须分块喂入**（环形缓冲 ≈10s @16k，整段灌会溢出丢段）+ 越界段丢弃 + `iter_segments` 最短段过滤 + 实时侧 `accept/flush/pop_segment`。
- `agent/plugins/asr/models.py`：模型清单（流式 X-ASR + SenseVoice + silero_vad）+ 路径解析 + 缺失时 **stdlib urllib Range 断点续传**懒下载（零 sherpa 依赖 ⇒ 没装引擎也能报就绪状态）+ `read_audio`/`resample`。
- `agent/plugins/asr/providers.py`：**`ASRProvider` 抽象基类 + `SherpaOnnxProvider`**（双识别器按模式路由；`refine` 首版 passthrough）+ `SherpaStreamingSession`（endpoint 断句）+ `Segment`/`FileTranscribeResult` 契约。
- `agent/plugins/asr/service.py`：`ASRService` 门面——**懒加载状态机**（`idle`/`loading`/`ready`/`unavailable`，不在 `apply` 里加载以免拖慢服务启动）、`ThreadPoolExecutor` 隔离 CPU 密集 decode、`threading.Lock` 串行非线程安全的 decode。

### 3.2 前端（实时采集 + 文件上传）

- `web/src/api/types.ts`（改）：登记 ASR DTO —— `AsrSegment` / `AsrFileResponse` / `AsrEngineStatus` / `AsrStatusResponse` / `AsrWsFrame` / `AsrCaptureKind`。
  ★ `AsrSegment` 字段是 **snake_case**（`start_sec`/`end_sec`），**后端未做 camel 转换** ⇒ 前端不能用 camel 命名。
- `web/src/api/asr.logic.ts`（新，**纯函数、可直接单测**）：`pickStrategy`（降级矩阵）、`strategyNotice`（诚实提示）、`isSpeechApiAvailable`、`concatFinals`、`formatDuration`、`isAsrFrame`（脏帧守卫）、`isEngineServable`。
- `web/src/api/asr.ts`（新）：ASR 客户端。**三条"不这么写就静默失效"的约束**：
  - `openAsrStream()`：★ **token 只能走 `?token=`** —— 浏览器 `WebSocket` **无法自定义请求头**，而全局 http 中间件不覆盖 WS scope ⇒ 后端 `_token_ok` 自校验；若"优化"成 header，开 `--token` 的服务直接 **4401**；
  - `transcribeFile()`：★ **全仓唯一绕过 `client.ts::request()`** 的调用 —— 文件上传必须 `FormData` 且**不可**手工设 `Content-Type`（boundary 须由浏览器生成），鉴权仍复用 `authHeaders()`；
  - `startRealtimeCapture()`：优先 **AudioWorklet**，失败降级 **`ScriptProcessorNode`** —— 后端静态页 CSP 为 `script-src 'self'`（**未放行 `blob:`**），单端口部署下 `addModule(blobURL)` 会被拦。
- `web/src/components/VoiceButton.vue`（新）：麦克风按钮 + 录音态脉冲 + 实时字幕胶囊（partial 灰 / final 深）。`onFinal` **只回填草稿，绝不自动发送**（方案硬要求：语音会出错，自动发等于替用户说话）。
- `web/src/components/TranscriptPanel.vue`（新，模式 F）：上传入口 + 分段结果（时间戳 + 文本 + 复制全文）。**空段与故障必须区分**：0 段提示"未检测到语音"，引擎不可用则明确报原因。

## 5. 协议（**已按实现订正**，前端 `api/types.ts::AsrWsFrame` 为机器可读真源）

### 5.1 模式 R（WS 流式）
客户端 → 服务端：
- 二进制帧：`int16` PCM（16kHz mono，每帧 20–40ms；前端 AudioWorklet 直接以 16kHz 打开 `AudioContext`，故不需前端重采样）
- 控制帧（JSON 文本帧）：`{"type":"start"}` / `{"type":"stop"}`（`start` 帧仅重置会话；首个 PCM 帧会懒建 session）
- ★ **鉴权**：`?token=<token>`（**只能走 query** —— 浏览器 `WebSocket` 无法自定义 header）

服务端 → 客户端（JSON 文本帧）：
- `{"type":"loading"}` → `{"type":"ready"}` → 之后 `{"type":"partial","text":…}` / `{"type":"final","text":…}` 若干
- `{"type":"error","error":"<可读原因>"}` —— ★ 字段名是 **`error`**（不是草案的 `msg`），前端据此降级 Web Speech
- 客户端发 `stop` 后服务端回 final 并**关闭连接**

### 5.2 模式 F（文件转写，HTTP）
请求 `POST /api/asr/transcribe-file`（`multipart/form-data`，**仅 `file` 一个字段**；⚠ 前端不可手工设 `Content-Type`，boundary 须由浏览器生成）

响应（JSON）：
```json
{
  "ok": true,
  "duration_sec": 1830.4,
  "sample_rate": 16000,
  "mode": "offline",
  "segments": [
    {"index":0,"start_sec":1.2,"end_sec":8.7,"text":"会议于上午九点开始……"},
    {"index":1,"start_sec":9.1,"end_sec":15.3,"text":"接下来由张工汇报进度……"}
  ]
}
```

## 8. 风险与已确认项

**已确认（用户拍板）**
1. 流式模型：**X-ASR-zh-en 官方流式 `chunk-480ms-model`**（`GilgameshWind/X-ASR-zh-en`，中英+标点，X-ASR Zipformer transducer，cjkchar 分词）；k2-fsa releases 的 int8 版编码器缺 `encoder_dims` 元数据、加载失败，已弃用。
2. 长录音离线识别器：**SenseVoice**（`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17`，首版即上，定位为模式 F 引擎）。
3. 模型一律走 **hf-mirror.com** 镜像（SenseVoice→`csukuangfj`、X-ASR 流式→`GilgameshWind/X-ASR-zh-en`）；GitHub 直连 ~60KB/s 不可用，`ghproxy`/`modelscope` 不可达。X-ASR 流式用 `chunk-480ms-model`（非 v1.2 误写的 "x-asr-480ms" 实时命名，亦非 k2-fsa int8）。

**已解决（实测结论，勿再当风险）**
4. ~~**Python 3.13 wheel 缺失**~~ → **未发生**：sherpa-onnx 1.13.8 提供 `cp313-cp313-win_amd64.whl`，直接装进 managed venv（py3.13）成功。
5. **模型下载**（已解决）：三模型共 ~800MB 经 **hf-mirror.com** 全部下完（SenseVoice int8 239MB 峰值 ~3.7MB/s；X-ASR `chunk-480ms-model` 4 文件 ~2MB/s）。`ghproxy`/`modelscope` 的 k2-fsa 路径均不可用，GitHub 直连仅 ~40–60KB/s。⚠️ **k2-fsa 的 `sherpa-onnx-x-asr-...-int8-2026-06-03` 不得采用**（编码器缺 `encoder_dims` 元数据，`from_transducer` 加载失败）。

**仍然存在的风险 / 边界**
6. **本机 CPU 性能**：X-ASR RTF≈0.12（实测流式 10s 音频流畅出字）；SenseVoice 逐段 CPU 较慢，长录音整体耗时可接受。已在 `ASRService` 内用 `ThreadPoolExecutor` + `threading.Lock` 隔离（decode 非线程安全）。
7. **WS 鉴权**：全局 http 中间件**不拦 WS 握手** ⇒ 端点内自行校验 `--token`；**浏览器 `WebSocket` 无法自定义 header ⇒ token 只能走 `?token=`**。dev 形态还需 vite proxy `ws: true`（已补）。
8. **AudioWorklet 安全上下文与 CSP**：需 `https://` 或 `localhost`（`getUserMedia` 硬性要求），公网需 TLS。
   ★ **新增约束（阶段 2 实证）**：后端静态页 CSP 为 `script-src 'self'`，**未放行 `blob:`** ⇒ 单端口部署下 AudioWorklet 的 `addModule(blobURL)` **会被拦** ⇒ 已实现降级 `ScriptProcessorNode`（已 deprecated 但兼容面最广，Safari 亦可用）。
9. **飞书写入不在首版**：仅预留 §9 数据契约与 `asr_transcribe` tool 接口，执行层（connector）未来再做；**ASR 插件与任何下游编排零耦合**。
10. **音频格式**：以 libsndfile 为准（wav/flac/ogg/mp3 等）；**m4a/aac 不支持**，读取失败明确报 400（不谎报"未识别到语音"）。上传上限 200MB，转写结束即删（不留存用户音频）。

### 8.9 识别质量优化（**已挂起**，用户 22:50 指示"先全部写完跑通"）
当前输出对**中英混说**场景不够好（实测：`昨天是mondaytoday is礼2the day after tomorrow是星期三。`）。已定位的成因与对应改法（**均未实施**，阶段 3 处理）：

| 现象 | 实测根因 | 改法 |
|---|---|---|
| 「礼拜二」→「礼2」 | `use_itn=True`（逆文本归一把中文数字转阿拉伯数字） | `use_itn` 改可配置、默认 `False`（实测中文数字更对） |
| 切段后丢标点/粘连 | VAD 切点可能落在**词中间**（实测 0.83s 处截断了"昨天"） | 短音频（<`max_segment_sec`，默认 30s）**整段直喂不切**；`min_silence_duration` 0.25→0.5s；最短段（<1.5s）与相邻段合并 |
| 段落缺标点 | SenseVoice int8 在 `use_itn=False` 下不打标点（模型固有） | 依赖第二版 `refine` 钩子（SenseVoice 给实时文本补标点/ITN）；文件通道靠分段结构承载语义边界 |

★ **已被实测否决的两个"想当然"改法**（勿再尝试）：
- **给每段前后加静音 padding** ⇒ 触发幻听（`Z天是MdayTodayday is…`），**更差**；
- **给每段加 1.5s 上下文重叠再取中间段** ⇒ 重叠区音频被识别两次，文本串味（`li ba a`），**最差**。
  ⇒ **切点质量决定一切，"补上下文"是错的方向**。

## 9. 飞书工作流对接（未来，预留契约）

将来要跑通 **录音 → 转文字 → AI 分析 → 飞书写入** 的工作流。ASR 层只负责前两段的"转文字"，后两段属编排层（可借 agent 工具链 / LangGraph 类编排），不在首版。

**ASR 输出契约（供下游消费）**
- 模式 F 返回 `Segment[]`（带 `start_sec`/`end_sec`/`text` 时间戳），天然适合 AI 分析做"按章节总结 / 待办抽取"。
- `asr_transcribe(audio_ref, mode="file") -> Segment[]` 作为 agent tool，工作流可直接调用。

**飞书写入占位（阶段 4）**
