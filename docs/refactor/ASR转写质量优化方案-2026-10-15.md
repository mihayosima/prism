## 1. 背景与实测证据

- 调用链路：`POST /api/chat/stream`（21:14）中 agent 调用 `asr.transcribe_file`，参数 `path=<用户主目录>\Desktop\测试\录音.mp3`（mp3，格式支持 ✓）。
- 事件日志实锤（`data/agent_chat.db`）：
  - `21:14:25` `tasks/pre-execute`：`asr.transcribe_file`；
  - `21:14:25` `permission/decision`：risk=`read`，自动 `allow`；
  - `21:14:31` `tasks/post-execute`：`ok=true`，**耗时 6581ms**，无报错。
- 同文件复跑（ground truth）：
  - 时长 **21.68s**，采样率 16k；
  - **VAD 只切出 1 段（1.82s–21.66s）**——前面 1.82s 静音被裁掉；
  - 原文（实际错误形态）：
    > 今天就带大家分析赏你的居住环境和默的居住情况吧。总站的面积大概是7万多平，有包区都是树木，一个角落就是它一层茫。后山这个水通的尽头，就是长一的边界了往后山深处走，这边是茫的绿叶森踪，深处有一座洞，就是什么我们的山洞部落了。
- 结论：**链路无 bug**（mp3 读得动、静音裁得掉、返回正常）。质量差来自模型精度天花板 + 长段整体解码 + 无后处理，与“分段太碎”的直觉**相反**（实际只切出 1 段）。

## 3. 候选方案全集（按杠杆分组）

### A 类：解码参数（零/低改动）

| 编号 | 方案 | 核实情况 | 针对效用 | 改动量 |
| --- | --- | --- | --- | --- |
| **A1** | **锁 `language="zh"`** | ★`from_sense_voice(language="")` 默认空；传 `"zh"` 合法 | 消除自动检测漂移，中文选字更稳，**常提 1–3% 准确率** | 1 行（必做） |
| A2 | `num_threads` 提至 CPU 核数 | 当前=2 | 仅提速、不提精度 | 改默认值 |
| A3 | `decoding_method` 改 beam | ★便捷方法暴露 `decoding_method` 但不暴露 `max_active_paths`；SenseVoice 非自回归，增益极小 | ROI 低 | 不建议 |

### B 类：长段切片重叠窗（零模型成本，直接命中本次 20s 单段）

- **B1**：在 `transcribe_file`（`providers.py:411`）对超过 `max_seg` 秒的段，按重叠窗（如 15s 窗 / 2s 重叠）切分、逐窗 `decode_stream`、再合并为一个 Segment。
  - 直接命中本次“21.68s 只切出 1 段整体解码”的问题；误差可在每个窗口内重置。
  - 对短段（默认 <15s）无影响；对长录音（会议/访谈）质量提升明显。
  - 改动：新增窗口切分辅助函数 + 单测（注意 `vad.py` 已证实切段边界是**采样点索引**而非秒，需小心换算）；纯逻辑、零模型体积成本。

### C 类：LLM 后处理校对（refine 接通）—— 对你这次同音错**最对症**

- **C1**：把原文送 LLM 做**最小改动**订正（基于语境改同音/错别字）。
  - 证据最强：公开基准中纯后处理把 WER 从 18.08% 打到 4.75%（↓75%）；Fleurs 上 Whisper 11.93%→8.54% WER。你那些“分析赏/水通/茫的绿叶森踪”正是 LLM 凭语境改同音字最擅长的。
  - 改动：`refine(text)` 接 LLM（经 `Services.LLM` 或现有对话端点）；加 `config['refine']['enabled']` 开关（**默认关**，保持首版向后兼容）。
  - **契约影响**：`asr.transcribe_file` 返回文本“可能已被 LLM 订正”。建议在 `FileTranscribeResult.to_dict()` / `Segment.to_dict()` 增 `refined: bool` 标记，并保留 `raw_text`（可选），让下游/工具调用方知情。
  - 代价：多一次 LLM 调用 + 延迟（数百 ms~数 s）；须在 prompt 约束“只改明显同音/错别字、不增删内容”以防幻觉。

### D 类：预处理降噪（新方向，针对环境噪声放大量化误差）

- **D1**：送识别前做 RNNoise 降噪 + AGC（自动增益）。你这段像自然/户外场景录音，环境噪声会放大量化误差。嘈杂场景 WER 可再降一截。
  - 改动：`read_audio` 后加降噪步骤 + config 开关；需评估依赖（`noisereduce` 或 RNNoise 绑定，或 ffmpeg 预处理）。

### E 类：模型层（精度天花板）

| 编号 | 模型 | 中文 CER | 现状 | 说明 |
| --- | --- | --- | --- | --- |
| E1 | SenseVoice **fp32** | ~2.5–2.9% | ⚠需改 `models.py` 增 fp32 spec + 下载 URL + 配置切换 | 干净 +0.5~0.8% WER；**嘈杂可达 +4.7%**——你这段若带环境音收益比想象大；代价 ~1GB 体积 |
| **E2** | **FireRedASR** | **~2.89%（中文天花板）** | ⚠`OfflineFireRedAsrModelConfig` 在 1.13.8 **已存在**，但需补 ModelSpec + 下载 URL + `from_fire_red_asr` 加载代码（**非开箱即用，需二次验证接入**） | 精度上限最高 |
| E3 | **n-gram LM 浅融合** | 提升 | ★`OfflineLMConfig` 存在 | 不引 LLM 即提精度，便宜；需 LM 文件 |
| E4 | Fun-ASR-Nano | — | ⚠需接 | 26 种地域口音 / 7 方言，口音重时考虑 |
| E5 | Paraformer-large + 独立标点 | ~3.3% | ⚠需接 + 外挂标点 | 当前已用 SenseVoice 自带标点，收益有限 |

> 注：**别换 Whisper**——Whisper-large 中文 CER 约 5–8%，比 SenseVoice（≈3%）差一档，且在 CPU 上慢一个数量级。

### F 类：重采样换 soxr（次要但真实）

- **F1**：替换 `models.py:240-258` 的线性插值为 `soxr`/`resampy` 带限重采样，消除 44.1k→16k 混叠。当前诚实注释已标注此为线性插值非带限。需引入依赖或 vendored 实现。

## 4. 推荐组合与分阶段

- **阶段 0（必做·零风险）**：**A1 锁 `language="zh"`**。1 行改动，消除检测漂移。
- **阶段 1（高性价比·零模型成本）**：**B1 长段切窗重叠解码**。直接命中本次 20s 单段问题。
- **阶段 2（最对症同音错）**：**C1 LLM refine 校对**（加 config 开关 + 契约 `refined` 标记）。
- **阶段 3（若阶段 0+1+2 后仍不满意）**：**D1 降噪** 或 **E1 fp32 / E2 FireRedASR**。
- （F1 soxr 可随时插入，影响面小，不阻塞主线。）

**预期**：阶段 0+1+2 能显著改善长录音同音错，且不增加模型体积（仅多一次 LLM 调用，且默认关）。

## 7. 风险与回滚

- **A1 / B1**：纯参数/逻辑改动，低风险，可快速回滚。
- **C1**：引入 LLM 依赖 + 延迟 + 幻觉风险（已在 prompt 约束“最小改动”）；**开关默认关** ⇒ 关即回退 passthrough 首版行为。
- **E1 / E2**：增大模型体积（~1GB+）与首次加载时间（懒加载已就绪，但首次更慢）；fp32 失败可回退 int8 spec。
- **D1 / F1**：引入外部依赖，需评估体积与安全；均经 config 开关，默认保持现行为，灰度可控。
- 所有改动经 config 开关，默认保持现行为，灰度可控。
