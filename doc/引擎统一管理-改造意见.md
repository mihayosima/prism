# 引擎统一管理 · 改造意见

> 归属：Meridian RPA 引擎 · 插件生命周期管理。
> 日期：2026-09-21。状态：意见已定稿，其中「本次落地」部分已实现。
> 目标：新增 / 卸载 / 停用插件**一步到位**，不手改装配代码，状态两页一致。

---

## 0. 装配统一模型（背景事实）

引擎的统一管理分两层：

- **内核（不可插拔）**：`Context / Container / EventBus / CommandRegistry / Scheduler` 直接 `new` 成内置服务（`engine.py:43-51`），以 `ctx.events / ctx.commands / ctx.scheduler / ctx.config` 呈现。
- **统一插件层（一切能力都是 `@plugin`）**，三路来源进同一 `Container.add()` 管线：
  1. `profile_plugins` —— 系统 Seam + Provider 选择（`bootstrap.ME1_PROFILE`）
  2. `flow_plugins` —— 业务 flow / 皮肤（`ConsoleSkin`）
  3. `plugins/` 目录 —— 用户业务插件（`PluginManager` 扫描 + `plugin_state.json` 启用集）

三路进容器后**无差别**：同一份拓扑序（`inject` 依赖）、同一套 `apply/start/teardown`、同一套 `ctx.provide / ctx.effect / ctx.command` 归属契约。差异只在「来源」（显式 profile vs 目录发现）与「可管理性」（系统只读 vs 业务可启停）。

## 1. 意见清单（含优先级）

### ⭐ 意见 1：`ctx.plugins` 从冻结清单 → 活注册表
现状 `engine.py:75` 只 `provide("plugins", plugin_manifest())`（一次数据快照，无方法），调度页/插件页/停用 409 各自重组 manifest × enabled × discovered × commands.owned_by × runner.owned_by（五处拼装）。改法见意见 3 落地 —— 本次先把「停用=自动清任务」「状态两页同源」做对，`ctx.targets` 活注册表留作后续收敛（用户暂缓）。

### ⭐ 意见 2：可管理性从「目录位置」解耦为声明式
曾因 `plugin_state.json` 被塞入 `engine.browser_actions` / `engine.profile.shared`（挪进 `engine/system/` 前）残留而误分类。本次未引入新维度，但加了 `orphans()` / `prune_orphans()` 清理残留，杜绝脏数据影响判断。

### ⭐ 意见 3：期望态 vs 运行态分离，UI 摆出差距（**本次落地**）
`desired=enabled`（state 期望）· `actual=assembled`（进程实际）· `delta`（重启/一致/新增/停用）。前端顶部汇总条一眼看清「下次启动将装配哪些」。

### 意见 4：统一插件「自述状态」钩子（可选 `status(ctx)` / `run` 返回 summary）
留给后续多插件联动（采集→评分→榜单）。本次不实现。

### 意见 5：装配缺依赖「诚实全挂」+ 结构化失败报告
保留诚实边界；本次把失败定位能力交给 `discovered/load` 的 loadable+error 字段（已有），不再扩展降级。

### 意见 6：Provider/profile 选择数据化（browser/llm/db 同一套选择机制）
与选品 `engine/seams/llm` 一起落地，本次不做（用户明确暂缓 agent 场景）。

## 2. 本次落地（原「停用/卸载要到处清任务、新增要手动启用」的根治）

1. **停用 = 自动清任务**：停用插件时自动移除其名下全部调度任务（`_drop_jobs`），不再 409 阻塞、不用去调度页手工删任务。调度选项立即消失（`_job_options` 已按启用态过滤），重启后不再装配。
2. **卸载 = 自动清任务 + 删目录**：同样先清任务再 `remove()`，恢复目录删除 + 停用 + 残留标记，一步完成。
3. **新增 = 建目录 + 自动启用**：`scaffold` 后自动写启用集，插件立即以「已启用·重启后装配」出现在插件页与调度页，重启即装配。
4. **状态视图**：插件页每行 `desired/actual/delta` + 顶部汇总，前端直接展示差距，不再靠 note 文字猜。
5. **残留清理**：`POST /api/plugin_mgr/prune` 清掉 enabled/removed 里 discovered 不存在的孤儿 id。
6. **入口默认化**：webui 默认发现 `plugins/`（有候选即装配启用集），`--no-plugins` 显式关闭 —— 不再要求记忆 `--plugins`。

## 3. 明确不做（保持边界）

- **不热插拔**：装配仍「启动时一次性完成」，启停「重启生效」为诚实边界；本次只把「差距」摆到明面 + 自动清任务。
- **`ctx.targets` 活注册表**：统一注册表收敛留作下一次（用户暂缓）。
- **内核插件化 / Provider 选择数据化**：与 agent/llm 场景一起再议。
